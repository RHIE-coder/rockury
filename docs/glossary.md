# 용어사전 (Glossary)

> steward intake 가 합의된 용어를 `용어(= 이 맥락에서의 뜻)` 형식으로 쌓는다.

- **레거시(= `__active-box__/rockury/rky-mvp`, 옛 "Liva Console" MVP)** — 현재 Rockury 이전 버전. Data/Query 서비스 기능을 여기서 선별 이관 중.
- **Tier A / Tier B (= 레거시 기능의 이관 우선순위 묶음)** — Tier A = 지금 명확히 비어 있고 공들인 핵심, Tier B = 있으면 좋은 중간 규모. (이 프로젝트 내부 분류 용어.)
- **도우미(= 셀 편집 시 값 생성을 돕는 인라인 위젯)** — UUID 도우미(랜덤 식별값 생성), 시간값 도우미(NOW·포맷 입력), NULL 토글 등.
- **Constraint 탭(= 콘솔 Data 안의 제약조건 브라우징 탭, 읽기 전용)** — 전역 제약 목록(PK/FK/UK/IDX/CHECK 필터) + 현재 테이블 제약 패널. DDL 변경 없음.
- **파라미터화 쿼리(= `{{키워드}}` 자리표시자를 실행 시 값으로 치환하는 저장 쿼리)** — bare `{{x}}`만 치환, `'{{x}}'`(따옴표)는 리터럴로 둠.
- **Run-All(= 컬렉션의 여러 쿼리를 한 트랜잭션에 순차 실행)** — 실패 시 이후 skip, 재시도/중단 지원.
- **트랜잭션 게이트(= 커밋 직전에 사람이 통과시켜야 하는 관문)** — DML 을 `BEGIN → 실행(영향행수 미리보기) → [커밋]/[롤백]` 로 태워, 확정 전 검토·되돌리기를 강제하는 안전장치. Query 뷰는 단일 DML 에, Collection 은 여러 쿼리 묶음(원자적)에 같은 게이트를 적용한다.
- **개별 실행(스텝, = 컬렉션 아이템을 하나씩 실행)** — 개별 커밋하지 않고 열린 트랜잭션에 이어 붙여 원자성을 유지한다(전체 Run-All 과 대비되는 수동 스텝 모드).
- **저장쿼리 참조(= 컬렉션 아이템이 SQL 사본이 아니라 라이브러리 쿼리를 가리킴)** — 원본 하나를 여러 컬렉션이 참조.
- **키 배지(= 컬럼 헤더의 제약 종류 표시)** — `PK`·`FK`·`UK`·`IDX`·`CHECK` **텍스트로만** 표기. 열쇠 이모지 등 애매한 기호 금지(사용자 규칙).
- **리하이드레이션(= 저장소가 바뀌면 화면이 해당 부분을 다시 읽어와 상태를 맞추는 것)** — MCP 쓰기 시 메인 프로세스가 열린 창에 "바뀌었다" 신호를 보내고, 렌더러 스토어가 그 스코프만 재로딩.
- **설계 스코프 저장(= 테이블 저장을 전량 교체가 아니라 설계 하나 단위로 하는 방식)** — 설계 X 저장이 설계 Y 행을 건드리지 않아 에이전트·화면 동시 작업이 안전해짐.
- **FK 정책(= 부모 행이 지워지거나 키가 바뀔 때 자식 행을 어떻게 할지 정한 규칙)** — `ON DELETE`(삭제 시)와 `ON UPDATE`(키 변경 시) 두 가지. 값은 `NO ACTION`(막음, 기본)·`RESTRICT`(막음)·`CASCADE`(따라감)·`SET NULL`·`SET DEFAULT`. 화면에는 **항상 둘 다** 보이고, 지정 안 한 쪽은 DB 기본값 `NO ACTION` 으로 흐리게 표기한다(정본: `workspaces/definition/fkPolicy.ts`).
- **뷰(view, = 질의 결과를 테이블처럼 보이게 저장해 둔 것)** — 실제 데이터를 담지 않아 편집 대상이 아니다. 목록에서 테이블과 갈라 보인다. 역설계로 들여온 표식(`isView`)은 설계 저장소까지 보존된다.
- **포커싱(= 목록에서 고른 테이블이 다이어그램 화면 가운데 오도록 옮기는 것)** — 확대는 상한을 둬 과하게 당기지 않는다.
- **구조 요약 칩(= JSON 셀 앞에 붙는 작은 표식)** — `{} 5`(키 5개인 객체)·`[] 12`(항목 12개인 배열)·`!`(형식이 깨진 값). 좁은 셀에서 값의 생김새를 한눈에 알려 준다.
- **시드(seed, = 테이블을 만들 때 처음부터 있어야 하는 기준 데이터)** — roles·permissions·코드표처럼 서비스 정책·제약의 바탕이 되는 행들. Remote › Data(실 DB 에 지금 담긴 데이터)와 구별된다. 스키마 요소는 아니지만 **버전 Diff 대상**이다.
- **시드 세트(seed set, = 시드 관리의 단위)** — 네 가지를 선언한다: 대상 테이블 · **자연키** · 무시 컬럼 · `설계에 없는 행` 처리. "테이블 전체"가 아니라 이 선언 단위로 반영·되먹임한다.
- **자연키(natural key, = 행의 정체성을 잡는 업무상 열쇠)** — 자동증가 `id` 같은 대체키(surrogate key) 대신 `roles.code` 처럼 뜻이 있는 컬럼. 환경마다 자동증가 값이 달라도 같은 행끼리 짝이 맞아 diff 가 성립한다(스키마쪽 `align.ts` 가 이름으로 짝짓는 것과 같은 역할).
- **무시 컬럼(= 환경마다 달라도 차이로 보지 않는 컬럼)** — `id`·`created_at` 처럼 값이 다를 수밖에 없는 것들. Diff 소음을 없앤다.
- **설계에 없는 행 처리(= 반영할 때 실 DB 에만 있는 행을 어떻게 할지)** — `그대로 둠`(설계에 적힌 행만 넣고 맞추고 나머지는 건드리지 않음, 기본) / `삭제 후보`(목록 전체를 설계가 결정하는 표 — 역할·권한 등). 삭제는 기본 꺼짐 + 명시 동의 + 트랜잭션 게이트. (코드 내부 값 이름은 `ensure` / `authoritative`. 화면에는 추상적 이름 대신 **효과 그대로** 보인다 — "관리 강도" 같은 지어낸 말은 쓰지 않는다.)
- **자연키 뒷받침(= 자연키와 정확히 같은 구성의 UNIQUE/PK 가 실제로 있는가)** — 없어도 시드 저작·버전 비교는 된다(논리적 기준으로 충분). 하지만 실 DB 반영 때 UPSERT(`ON CONFLICT (…)`·`ON DUPLICATE KEY`)는 충돌 대상 컬럼 구성을 그대로 지목하므로, 뒷받침이 없으면 "찾아서 넣기"로 내려가 동시 실행에 취약해진다.
- **별칭(alias, = 시드 행에 붙이는 설계 전용 이름)** — 다른 시드 행이 이 행을 가리킬 때 쓴다(`@users#admin`). **실 DB 에는 들어가지 않는다.** 짝짓기 기준 값(email·code)을 그대로 쓰지 않는 이유: 기준 값은 바뀌고, 그때 그걸 가리키던 참조가 전부 깨진다.
- **시드 참조(= 시드 행이 다른 시드 행을 가리키는 표기)** — `@테이블#별칭`. 반영할 때 그 환경의 실제 id 로 치환되고, 되먹임에서는 실제 id 를 다시 이 표기로 되돌린다(양방향 같은 규칙). 값이 진짜 `@` 로 시작해야 하면 `@@` 로 탈출.
- **반영 계획(= 시드를 실 DB 에 넣기 전에 만드는 문장 목록)** — 무엇을 넣고 고치고 지울 후보로 볼지 미리 계산한다. 막는 것(blocker)이 하나라도 있으면 반영하지 않는다(반쯤 심고 마는 상태 금지).
- **PK 획득 방식(= PK 를 누가 만드는가)** — `DB 가 만든다`(시드는 PK 를 담지 않음, 기본) / `시드가 정한다`(셀 값 또는 생성 규칙). 생성 규칙 자리표시자: `{uuid}`(결정적) · `{key}` · `{alias}` · `{table}`. 랜덤 생성은 없다 — 재실행마다 값이 달라지면 같은 행이 두 벌 생긴다.
- **생성 규칙 미리보기(= 규칙이 만들 값을 저작 중에 그 자리에서 보여주는 줄)** — 규칙은 자유 문자열이라 결과가 안 보이면 무엇을 만드는지 알 수 없다. `1행에 들어갈 값` 을 반영 계획과 **같은 계산**으로 보이고, 함께 알린다: 값 없음(반영 막힘) · 모르는 자리표시자(오타는 글자 그대로 들어간다) · 타입 불일치(숫자 컬럼에 숫자 아닌 값, 길이 초과).
- **변수 자리표시자(시드, = 환경마다 다른 값을 값 대신 넣어 두는 이름)** — `{{ADMIN_PASSWORD_HASH}}`. 저장쿼리의 파라미터화와 같은 문법. 시드 정의는 단일로 두고 환경차만 변수로 뺀다 → Diff 가 조용하고, 비밀값이 설계 정본에 평문으로 남지 않는다(실제 값은 환경 쪽 + OS 키체인 암호화).
- **워크트리(worktree, = 한 저장소를 여러 폴더에 동시에 펼쳐 놓는 git 기능)** — 커밋 기록은 하나를 공유하고 작업 중인 파일만 폴더별로 따로 논다. 에이전트 5개가 서로의 파일을 덮어쓰지 않게 하는 판. `node_modules`·`out`·`.harness-main` 은 gitignore 대상이라 새 폴더에 안 따라간다(준비 스크립트가 대신 깔아 준다).
- **통합 브랜치(= 직접 작업하지 않고 병합만 받는 브랜치)** — 병렬 개발에서 `main` 의 새 역할. 각 서비스는 `feat/<서비스>` 에서 일하고 완성분만 `main` 으로 올린다.
- **서비스 소유 파일(= 그 서비스 에이전트만 고치는 파일)** — 파일 경로에 서비스 이름이 박혀 있어 다른 에이전트가 같은 줄을 건드릴 일이 없는 파일. 반대는 **공용 파일**(모두가 손대야 해서 병합 충돌이 나는 파일) — 0차 작업이 공용 파일을 서비스 소유 파일로 쪼개는 일이다.
- **그룹(다이어그램, = 테이블 여러 개를 이름·색 있는 영역으로 묶은 것)** — 영역을 끌면 안의 테이블이 같이 움직이고, 테이블은 그 안에서 개별로도 움직인다. 접어서 한 덩어리로 만들 수 있고, 그 그룹만 보이게 거를 수도 있다. (MySQL Workbench 의 Layer 에 해당하는 개념 — 화면에는 "그룹"으로 적는다.) 소속은 **명시 멤버십으로 저장**한다: 위치만으로 따지면 자동 배치를 누르는 순간 묶음이 흩어진다.
- **상세보기 서랍(= 다이어그램 아래에서 올라오는 접이식 패널)** — 캔버스에서 고른 테이블의 컬럼·인덱스·제약·관계·DDL 을 보이고 고친다. 내용은 Definition 화면을 그대로 쓴다(따로 만들지 않는다). 좁으면 "크게 보기"로 같은 내용을 모달로 연다.
- **카탈로그(infra, = 노드 종류를 코드가 아니라 데이터로 적어 둔 파일)** — 공급자마다 하나(`aws.json`·`docker.json`…). 종류의 모양(이름·아이콘·중첩 규칙)과 읽는 법(탐침)과 조작(액션)을 담는다. 버전이 **둘**이다 — `schemaVersion`(파일 **형식**의 버전, 앱이 읽을 수 있는지 판정) · `catalogVersion`(그 공급자 **목록 내용**의 버전, 언제 기준인지). GCP·Azure 추가가 코드가 아니라 파일 추가로 끝나게 하는 장치.
- **탐침(probe, = 밖을 찔러 보고 결과를 읽어 오는 정의)** — "이 클라우드는 이렇게 파악해라"를 Rockury 에게 알려 주는 수단. 언제나 3단이다: **호출한다**(CLI 명령 / HTTP / 내장 어댑터) → **뽑는다**(응답에서 필요한 값의 위치를 가리킴) → **옮긴다**(우리 노드 필드로). 사용자는 JSON 을 손으로 쓰지 않는다 — 명령을 한 번 돌려 보고 출력에서 클릭으로 집으면 정의가 채워진다.
- **JMESPath(= 응답 JSON 에서 값의 위치를 가리키는 짧은 주소 문법)** — 데이터를 담는 그릇이 아니라 **가리키는 손가락**이다(`displayname`, `tags[?key=='name'].value | [0]`). Rockury 내부에서만 해석되고 사용자에게 노출되지 않는다. 점 표기(`a.b.c`)로는 배열 속 조건부 값을 못 집어서 골랐고, **표현식이 코드가 아니라서**(임의 코드 실행 경로 없음) 남이 준 카탈로그를 가져와도 안전하다.
- **프리셋(노드 프리셋, = 탐침 없이 모양만 있는 노드 종류)** — 그라파나·프로메테우스처럼 "그림에 놓고 싶지만 상태까지 읽을 필요는 없는" 것들. 라벨·아이콘·색·기본 문서 틀만 담아 만드는 비용이 거의 0이다. 나중에 탐침을 붙여 사용자 카탈로그 종류로 **승격**할 수 있고, 승격해도 이미 그려 둔 노드는 그대로 남는다.
- **미상 노드(= 카탈로그에 없는 종류로 실물에서 읽힌 노드)** — 떨어뜨리지 않고 그대로 그린다. 조용히 빼면 지도가 거짓말을 한다. 상태값도 마찬가지 — 사전에 없는 값은 '정상'이 아니라 **'모름'** 이고 원본 문자열을 함께 보인다.
- **대조(reconcile, = 설계본과 실물을 짝지어 어긋난 곳을 짚는 것)** — 결과는 셋으로 갈린다: **미구축**(설계에만 있음) · **미등록**(실물에만 있음) · **어긋남**(둘 다 있는데 다름). 짝짓기는 1순위 태그(`rockury:node=<설계노드id>`), 2순위 이름.
- **흡수(= 대조에서 벌어진 차이를 설계본 쪽으로 접는 것)** — DB 서비스의 Migration 과 **방향이 반대다.** DB 는 설계대로 실물을 고치지만, Infra 의 "적용"은 실물 값으로 **설계본**을 고친다. Rockury 가 인프라를 구축하지 않기 때문에 나온 규칙이라, 흡수는 실물을 절대 건드리지 않는다.
- **노드 문서(= 설계 노드에 붙는 설계 의도 기록)** — 역할(왜 있나)·영향(죽으면 무슨 일이 나나)·담당·의존·손대기 전 알 것 다섯 칸 + 자유 서술. **실물이 아니라 설계 노드에 붙인다** — 실물은 재생성되면 식별자가 바뀌어서, 실물에 매달면 재배포 한 번에 증발한다. MCP 로 에이전트에게 나가는 알맹이이기도 하다(이름·종류만 주면 에이전트도 "그래서 어쩌라고"가 된다).
- **미들웨어(= 앱과 앱 사이에서 메시지·캐시를 나르는 서버)** — Redis·Kafka·RabbitMQ·MQTT. 인프라 그림의 노드이면서 동시에 **접속해서 안을 들여다보는 작은 콘솔**이라, DB 서비스의 접속·콘솔 패턴을 빌려 쓴다.
- **범위(scope, = 한 연결에서 지금 보고 있는 스키마들)** — 운영 손잡이(뷰 탭 줄 오른쪽 끝)의 연결 바로 뒤 칸에서 고른다. 벤더마다 그 대상이 다른 층에 있다: MySQL/MariaDB 는 **database 여러 개**, PostgreSQL 은 **한 database 안의 schema 여러 개**, SQLite 는 파일 하나뿐이라 없다. 고른 것은 Definition·Diagram·Data·Query 가 함께 따른다 — 뷰마다 따로 고르면 같은 연결인데 화면끼리 다른 것을 본다.
- **카탈로그(catalog, DB = SQL 표준에서 database 를 가리키는 이름)** — `카탈로그.스키마.테이블` 3부 이름의 맨 앞. PostgreSQL 은 카탈로그와 스키마가 **다른 층**이고 카탈로그를 넘는 조인·FK 가 **불가능**하다. MySQL/MariaDB 는 카탈로그와 스키마가 **같은 말**이라 교차 database 조인도 FK 도 된다. (인프라 서비스의 "카탈로그"는 노드 종류 정의 파일로 전혀 다른 것이다 — 같은 낱말, 다른 대상.)
- **범위 밖 참조(= 지금 화면 범위에 없는 테이블을 가리키는 FK)** — 셋 중 하나다: **범위 밖**(체크 하나 더 켜면 들어온다) · **다른 카탈로그**(MySQL 교차 database) · **다른 연결**(PostgreSQL FDW 외부 테이블). ERD 에선 컬럼 없는 이름 카드로만 그리고, 누르면 그 테이블이 있는 화면으로 옮겨 가며 화면 아래에 "…로 돌아가기"가 남는다. 셋을 같은 회색 카드로 뭉뚱그리지 않는다 — 대처가 다르기 때문이다.
- **샘플 DB(= 앱이 스스로 만들어 주는 SQLite 파일 하나와 그 접속)** — 처음 켠 사용자가 준비물 없이 화면을 써 보게 하는 것이 목적. `<userData>/samples/sample.sqlite` 에 만들고 접속 `샘플 DB` 를 등록한다. 개발용 `npm run db:up` 이 만드는 `scripts/test-db/data/testdb.sqlite` 와는 **다른 파일**이다 — 앱이 개발 환경을 건드리지 않는다. 도커가 필요한 여러 벤더 스택은 이 말에 안 들어간다.
- **저장 필터(= 이름을 붙여 남겨 둔 조건 묶음)** — Data 화면에서 건 조건 여러 개를 한 덩어리로 저장한 것. **표마다 따로** 산다(연결 · 스키마 · 표 이름이 주인). 앱을 껐다 켜도 남고, 표가 지워지면 함께 사라진다. 지금 화면에 걸려 있는 조건("현재 필터")과 다른 것이다 — 현재 필터는 세션 동안만 기억한다.
- **필터 끔(= 조건은 그대로 두고 적용만 잠시 해제)** — 조건을 지우지 않고 전체 목록으로 돌아가는 스위치. 다시 켜면 아까 그 조건이 그대로 걸린다. "조건 지우기"(조건 자체를 없앰)와 뜻이 다르다.
- **검색 카드(= 검색창이 위에 달린 선택 목록)** — 브라우저 기본 드롭다운 대신 쓰는 공용 선택 부품. 후보가 수십 개여도 타이핑으로 좁혀 고른다. 키보드(↑↓·Enter·Esc)만으로도 다룬다.
- **못 쓰게 된 저장 필터(= 쓰던 컬럼이 사라져 적용할 수 없는 저장 필터)** — 조용히 지우지 않는다. 빨간 표시로 남겨 어느 컬럼이 없어졌는지 밝히고 적용만 막는다 — 사용자가 조건을 고쳐 되살릴 수 있어야 하기 때문.
- **권한 세트(= 재사용 가능한 권한 요구 묶음)** — 이름 + (테이블 이름/패턴 × SELECT·INSERT 등 권한 종류). 연결과 독립으로 앱에 저장되어, 연결을 지워도 남고 다른 환경의 계정에 재적용할 수 있다. 적용은 덮어쓰기가 아니라 **대조**다: 세트와 계정의 실제 권한을 비교해 모자람(GRANT 후보)/넘침(REVOKE 후보, 기본 꺼짐)을 보인다.
- **권한 층(= 권한이 주어진 범위의 수준)** — 서버 전역 > DB > 테이블 > 컬럼. 위층에서 준 권한은 아래로 내려오므로, 한 테이블의 유효 권한은 직접 준 것과 위층에서 내려온 것의 합이다. 화면은 권한이 **어느 층에서 왔는지**를 함께 표시한다 — 회수했는데 위층 권한으로 여전히 되는 미궁을 막는다.
- **표시(화면 피드백, = 화면 위에 남긴 자국 하나)** — 콕 누른 **핀**(자리 한 점)이거나 끌어서 그린 **표시**(그 영역)다. 몸짓이 갈래를 가르므로 모드 전환 버튼이 없다. 자리마다 그 아래 있던 DOM 요소와 React 컴포넌트 사슬을 따로 캔다 — 좌표가 아니라 그것이 코드로 가는 주소다.
- **묶음(화면 피드백, = 메모 하나가 덮는 표시 여럿)** — "이 카드를 저 목록으로"처럼 화살표·상자·핀 셋이 결국 한 요청일 때 쓴다. 묶는 손잡이는 **메모창 자신**이다: 열려 있는 동안 그린 자국이 그 묶음에 붙는다. 묶음 안 표시는 전부 같은 번호 배지를 달고, `note.md` 가 "표시 N개가 한 요청이다"로 밝힌다.
- **흐름(화면 피드백, = 제보 하나가 걸치는 화면 여럿)** — "A에서 이렇게 했더니 B가 이렇다"를 한 벌로 남긴다. 화면을 **떠나기 전에** "다음 화면"으로 굳혀 그림을 뜨고(`shot-N.png`), 표시는 차례가 아니라 **화면의 신원**을 붙잡는다 — 그래서 나중에 순서를 바꿔도 표시를 하나하나 고칠 일이 없다. 화면 하나짜리 제보에는 흐름 절도 단계 꼬리표도 안 붙는다.
- **훑어보기(화면 피드백, = 쌓은 것을 보고 그 자리서 고치는 패널)** — 화면(단계)마다 그때 찍힌 그림을 썸네일로 깔고 그 화면의 항목·메모를 한 줄씩 늘어놓는다. 메모를 고치고, 항목을 지우고, 화면을 걸친 항목에서 **한 화면 몫만** 빼고, 차례를 바꾸고, 제안 그림을 그린다. 보는 곳과 고치는 곳을 하나로 둔 이유: 갈라 뒀을 때는 **지난 화면의 항목을 아예 못 만져서**, 하나를 빼려면 화면을 통째로 빼고 처음부터 다시 그려야 했다.
- **초안 폴더(화면 피드백, = 아직 안 끝난 제보가 쌓이는 자리)** — `_draft-` 로 시작한다. 화면을 굳힐 때마다 메인이 바로 파일로 쓰므로, 개발 중 화면이 다시 그려져도 여러 화면 분량이 통째로 날아가지 않는다. 밑줄로 가른 이유는 "최신 폴더를 읽는" 습관이 미완성에 낚이지 않게 하려는 것. 보내면 접두어를 떼어 최종 폴더가 되고, 하루 넘게 방치되면 저장 통로가 치운다.
- **버전 확정(= 지금 작업본(draft)을 되돌릴 수 없는 스냅샷으로 굳히는 것)** — DB 설계부와 API 명세가 같은 이름으로 부른다. 예전 화면 문구는 "버전 컷"이었는데 영어 "cut a release"를 그대로 옮긴 말이라 한국어로는 영상 편집의 "컷"으로 먼저 읽혔다(2026-08-19 사용자: "'컷'이라는 단어가 맞아?"). **화면·오류 문구·에이전트에게 보이는 도구 설명은 전부 "확정"**이고, 코드 쪽 이름(`CutVersionDialog`·`cut()`·`data-api-cut-submit`)과 주석·테스트 이름의 "컷"은 그대로 뒀다 — 릴리스 용어로서는 통하는 말이라 일괄 개명의 이득보다 흔들 파일 수가 컸다. 둘이 다른 말이라는 것을 여기 적어 둔다.
