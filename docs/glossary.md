# 용어사전 (Glossary)

> steward intake 가 합의된 용어를 `용어(= 이 맥락에서의 뜻)` 형식으로 쌓는다.

- **레거시(= `__active-box__/rockury/rky-mvp`, 옛 "Liva Console" MVP)** — 현재 Rockury 이전 버전. Data/Query 서비스 기능을 여기서 선별 이관 중.
- **Tier A / Tier B (= 레거시 기능의 이관 우선순위 묶음)** — Tier A = 지금 명확히 비어 있고 공들인 핵심, Tier B = 있으면 좋은 중간 규모. (이 프로젝트 내부 분류 용어.)
- **도우미(= 셀 편집 시 값 생성을 돕는 인라인 위젯)** — UUID 도우미(랜덤 식별값 생성), 시간값 도우미(NOW·포맷 입력), NULL 토글 등.
- **Constraint 탭(= 콘솔 Data 안의 제약조건 브라우징 탭, 읽기 전용)** — 전역 제약 목록(PK/FK/UK/IDX/CHECK 필터) + 현재 테이블 제약 패널. DDL 변경 없음.
- **파라미터화 쿼리(= `{{키워드}}` 자리표시자를 실행 시 값으로 치환하는 저장 쿼리)** — bare `{{x}}`만 치환, `'{{x}}'`(따옴표)는 리터럴로 둠.
- **Run-All(= 컬렉션의 여러 쿼리를 한 트랜잭션에 순차 실행)** — 실패 시 이후 skip, 재시도/중단 지원.
- **트랜잭션 게이트(= 커밋 직전에 사람이 통과시켜야 하는 관문)** — DML 을 `BEGIN → 실행(영향행수 미리보기) → [커밋]/[롤백]` 로 태워, 확정 전 검토·되돌리기를 강제하는 안전장치. Query 뷰는 단일 DML 에, Collection 은 여러 쿼리 묶음(원자적)에 같은 게이트를 적용한다.
- **개별 실행(스텝, = 컬렉션 아이템을 하나씩 실행)** — 개별 커밋하지 않고 열린 트랜잭션에 이어 붙여 원자성을 유지한다(전체 Run-All 과 대비되는 수동 스텝 모드).
- **저장쿼리 참조(= 컬렉션 아이템이 SQL 사본이 아니라 라이브러리 쿼리를 가리킴)** — 원본 하나를 여러 컬렉션이 참조.
- **키 배지(= 컬럼 헤더의 제약 종류 표시)** — `PK`·`FK`·`UK`·`IDX`·`CHECK` **텍스트로만** 표기. 열쇠 이모지 등 애매한 기호 금지(사용자 규칙).
- **리하이드레이션(= 저장소가 바뀌면 화면이 해당 부분을 다시 읽어와 상태를 맞추는 것)** — MCP 쓰기 시 메인 프로세스가 열린 창에 "바뀌었다" 신호를 보내고, 렌더러 스토어가 그 스코프만 재로딩.
- **설계 스코프 저장(= 테이블 저장을 전량 교체가 아니라 설계 하나 단위로 하는 방식)** — 설계 X 저장이 설계 Y 행을 건드리지 않아 에이전트·화면 동시 작업이 안전해짐.
- **FK 정책(= 부모 행이 지워지거나 키가 바뀔 때 자식 행을 어떻게 할지 정한 규칙)** — `ON DELETE`(삭제 시)와 `ON UPDATE`(키 변경 시) 두 가지. 값은 `NO ACTION`(막음, 기본)·`RESTRICT`(막음)·`CASCADE`(따라감)·`SET NULL`·`SET DEFAULT`. 화면에는 **항상 둘 다** 보이고, 지정 안 한 쪽은 DB 기본값 `NO ACTION` 으로 흐리게 표기한다(정본: `workspaces/definition/fkPolicy.ts`).
- **뷰(view, = 질의 결과를 테이블처럼 보이게 저장해 둔 것)** — 실제 데이터를 담지 않아 편집 대상이 아니다. 목록에서 테이블과 갈라 보인다. 역설계로 들여온 표식(`isView`)은 설계 저장소까지 보존된다.
- **포커싱(= 목록에서 고른 테이블이 다이어그램 화면 가운데 오도록 옮기는 것)** — 확대는 상한을 둬 과하게 당기지 않는다.
- **구조 요약 칩(= JSON 셀 앞에 붙는 작은 표식)** — `{} 5`(키 5개인 객체)·`[] 12`(항목 12개인 배열)·`!`(형식이 깨진 값). 좁은 셀에서 값의 생김새를 한눈에 알려 준다.
- **시드(seed, = 테이블을 만들 때 처음부터 있어야 하는 기준 데이터)** — roles·permissions·코드표처럼 서비스 정책·제약의 바탕이 되는 행들. Console › Data(실 DB 에 지금 담긴 데이터)와 구별된다. 스키마 요소는 아니지만 **버전 Diff 대상**이다.
- **시드 세트(seed set, = 시드 관리의 단위)** — 네 가지를 선언한다: 대상 테이블 · **자연키** · 무시 컬럼 · 관리 강도. "테이블 전체"가 아니라 이 선언 단위로 반영·되먹임한다.
- **자연키(natural key, = 행의 정체성을 잡는 업무상 열쇠)** — 자동증가 `id` 같은 대체키(surrogate key) 대신 `roles.code` 처럼 뜻이 있는 컬럼. 환경마다 자동증가 값이 달라도 같은 행끼리 짝이 맞아 diff 가 성립한다(스키마쪽 `align.ts` 가 이름으로 짝짓는 것과 같은 역할).
- **무시 컬럼(= 환경마다 달라도 차이로 보지 않는 컬럼)** — `id`·`created_at` 처럼 값이 다를 수밖에 없는 것들. Diff 소음을 없앤다.
- **관리 강도(= 시드가 실 DB 를 어디까지 통제하는가)** — `전권`(설계에 없는 행은 삭제 후보) / `보장만`(설계에 적힌 행만 맞추고 나머지는 방치). roles=전권, 국가코드=보장만 식. 삭제는 기본 꺼짐 + 명시 동의 + 트랜잭션 게이트.
- **변수 자리표시자(시드, = 환경마다 다른 값을 값 대신 넣어 두는 이름)** — `{{ADMIN_PASSWORD_HASH}}`. 저장쿼리의 파라미터화와 같은 문법. 시드 정의는 단일로 두고 환경차만 변수로 뺀다 → Diff 가 조용하고, 비밀값이 설계 정본에 평문으로 남지 않는다(실제 값은 환경 쪽 + OS 키체인 암호화).
