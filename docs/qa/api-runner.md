# TestPlan: api-runner (운영부 — Environments · Runner)

> 정의(무엇을 검증하나)만 여기. 코드는 대상 모듈 옆 `*.test.ts`(vitest) + 앱 흐름 스위트 `e2e/suites/NN-*.mjs`.
> 대상 명세: `docs/spec/api-runner.md` · 불변식: `docs/spec/api-service.md` §2·§4.
> 회차 기록은 `docs/qa/runs/`.

## Scenario S1 — 값 해석 (순수 로직) — 이 서비스의 핵심 모델
- **CASE-apirunner-001** 해석 순서: `Request 기본값 < Environment 값 < 호출 파라미터`. 세 자리에 같은 이름이 있으면 호출 파라미터가 이긴다. 두 자리만 있어도 순서가 지켜진다. (resolution AC-1) → `api/runner/resolve.test.ts`
- **CASE-apirunner-002** 출처 표기: 해석 결과의 값마다 출처(`기본값`/`환경`/`호출`)가 실린다. 출처 없는 값은 결과에 없다. (resolution AC-2)
- **CASE-apirunner-003** 미해결 참조 차단: 어디에도 값이 없는 참조는 **실행 전에 차단**되고 이름이 지목된다. 빈 문자열 치환으로 넘어가면 실패. (resolution AC-3)
- **CASE-apirunner-004 (불변식 §2)** **두 바구니 분리**: 환경 값과 호출 파라미터가 한 목록으로 합쳐지지 않는다 — 해석기가 각 값의 갈래를 끝까지 들고 있다. 이름이 같아도 갈래가 섞이지 않는다. (values AC-3 · resolution AC-2)

## Scenario S2 — 환경 안전장치 (순수 로직)
- **CASE-apirunner-010** 복제 시 값 제거: 환경을 복제하면 변수 **이름만** 오고 값은 전부 빈다. 비밀 표식 여부는 유지된다. (list AC-3)
- **CASE-apirunner-011** 삭제 게이트: 실행 기록이 붙은 환경은 삭제되지 않고 **보관**으로 처리된다. 기록 없는 환경만 삭제된다. (list AC-4)
- **CASE-apirunner-012** 고아·구멍 판정: 어느 요청도 안 쓰는 값은 `고아`, 참조되는데 값이 빈 것은 `구멍`. **둘 다 아닌 것은 목록에 안 나온다.** 고아이면서 값이 빈 것은 고아로만 센다(안 쓰는 값이 빈 건 문제가 아니다). 참조는 경로·쿼리 값·헤더 값·본문·파라미터 기본값·함수 인자에서 모은다. 판정은 **편집 중인 값** 기준이다. (values AC-4) → `shared/api/envHealth.test.ts` · `e2e/suites/37-api-gaps.mjs`
- **CASE-apirunner-013** 마스킹: 비밀 표식 값은 표시용 변환에서 `••••` 로 나오고 원문 길이가 유추되지 않는다. (values AC-2)
- **CASE-apirunner-015** 카드 데이터 파생: 환경 카드에 이름·서버 주소·마지막 실행 시각이 담긴다. 실행 이력이 없으면 시각 자리가 `없음`이지 빈 문자열이 아니다. (list AC-1)
- **CASE-apirunner-016** active 일치: 카드 선택과 컨텍스트 바 셀렉터가 **항상 같은 값**을 가리킨다. 한쪽만 바뀌는 경로가 없다. (list AC-2)
- **CASE-apirunner-017** 값 편집 모델: 같은 이름을 두 번 넣으면 거부, 비밀 표식 토글이 값 수정 후에도 보존된다. (values AC-1)
- **CASE-apirunner-014 (불변식 ⑥)** **나가는 문 전수 검사**: 내보내기·복제·MCP 응답 세 경로 모두에서 환경 값 실값이 결과에 **한 글자도 없다.** 경로 하나라도 새면 실패. (values AC-5) → `api/environments/redact.test.ts`

## Scenario S3 — 요청 조립·실행 (순수 로직)
- **CASE-apirunner-020** 최종 요청 조립: 시그니처 + 환경 + 템플릿 → 경로·쿼리·헤더·본문이 완성된다. 경로 안 치환과 쿼리 인코딩이 정확. (compose AC-2)
- **CASE-apirunner-021** 미리보기 마스킹: 최종 요청 미리보기에서도 비밀 표식 값은 가려진다. (compose AC-3)
- **CASE-apirunner-022** 보내기 차단 조건: 필수 파라미터 누락 또는 미해결 참조가 있으면 조립 결과가 `차단`이고 이유가 실린다. (compose AC-4)
- **CASE-apirunner-023** 오류 분류: 연결 실패 · 타임아웃 · TLS 오류 · HTTP 오류 응답이 서로 다른 종류로 분류된다. 하나로 뭉뚱그리면 실패. (execute AC-4)
- **CASE-apirunner-024** curl/fetch 생성: 조립된 요청 → 실행 가능한 curl·fetch 문자열. **비밀 표식 값은 변수 이름으로 남고 실값이 안 박힌다.** (execute AC-5)
- **CASE-apirunner-025** 본문 표현 판정: 응답 본문을 JSON·텍스트·바이너리로 분류하고, 바이너리는 내용 대신 크기·형식만 낸다(거대 본문으로 화면이 죽지 않게). (execute AC-2)
- **CASE-apirunner-026** 취소 기록: 취소된 실행도 Run 으로 남고 결과가 `취소` 다 — 실패와 구분된다. 취소 손잡이는 **화면이 만든다**(응답을 기다리기 전에 알아야 버튼을 누른다). 화면을 먼저 "취소됨"으로 바꾸지 않는다 — 실제 기록이 돌아와야 사실이다. (execute AC-3 · observe AC-1) → `e2e/suites/37-api-gaps.mjs`

## Scenario S4 — 관측 기록 (순수 로직)
- **CASE-apirunner-030** Run 구성: 요청·파라미터·환경·**기준 버전**·요청 전문·응답 전문·시각·소요가 모두 담긴다. 기준 버전이 빠지면 실패(판정이 버전을 못 가른다). (observe AC-1)
- **CASE-apirunner-031** Run 불변성: 명세를 바꾼 뒤에도 지나간 Run 의 내용이 그대로다. (observe AC-2)
- **CASE-apirunner-032** Run 마스킹: 저장된 Run 에 비밀 표식 값이 가려진 채로 들어간다 — 기록 열람·MCP 어느 경로로도 실값이 안 나온다. (observe AC-3) → `shared/api/redact.test.ts`
- **CASE-apirunner-032b (응답 경로)** **서버가 되돌려준 비밀도 지운다** — 응답 본문·응답 헤더·오류 문구까지 훑는다(키를 에코하는 서버). 긴 값부터 지워 짧은 값이 긴 값을 잘라 먹지 않는다. 4글자 미만은 안 지운다. **우리가 모르는 값(서버 발급 토큰)은 못 지운다** — 그래서 MCP 에는 본문을 안 준다. (observe AC-3b)
- **CASE-apirunner-033** 기록 실패 격리: Run 저장이 실패해도 실행 결과는 정상 반환된다. (observe AC-4)
- **CASE-apirunner-034** 상한 처리: 보관 상한을 넘겨 지워진 건수가 집계되어 표시된다. **조용히 사라지면 실패.** (history.list AC-5)
- **CASE-apirunner-035** 기록 필터: 요청별·환경별·상태별·기간 필터가 조합으로 동작한다. (history.list AC-2)
- **CASE-apirunner-036** 두 Run 비교: 응답의 추가/삭제/변경된 필드를 가려낸다. **순서가 뜻을 갖는다**(뒤바꾸면 새로 생김과 없어짐이 뒤집힌다). 중첩·배열 자리번호까지 경로로 편다. 상태·기준 버전·환경 같은 본문 밖 차이는 따로 센다. **JSON 이 아니면 "같다"로 넘기지 않고** 못 쪼갰다는 사실을 남긴다. (history.list AC-4) → `shared/api/runDiff.test.ts` · `e2e/suites/37-api-gaps.mjs`
- **CASE-apirunner-036b (다시 실행)** 같은 파라미터로 다시 보낸다 — 기록이 파라미터를 따로 들고 있어 가능하다(조립된 주소에서는 못 되돌린다). **비밀 표식 값이 섞였으면 그 자리를 비우고 이름을 지목한다**(`••••` 를 그대로 보내지 않는다). 지나간 기록은 안 바뀌고 새 기록이 하나 더 생긴다. (history.list AC-3 · observe AC-1) → `e2e/suites/37-api-gaps.mjs`
- **CASE-apirunner-037** 목록 행 파생: 시간 **역순** 정렬, 각 행에 요청 이름·환경·상태·소요가 담긴다. (history.list AC-1)

## Scenario S5 — 스트림·수신 (순수 로직)
- **CASE-apirunner-040** 보내기 패널 가시성 판정: 양방향(WebSocket·gRPC 양방향/클라이언트)은 패널 있음, 서버 스트리밍(SSE·gRPC server-streaming)은 **패널 없음**(비활성이 아니라 없음). (stream.session AC-3) → `shared/api/stream.test.ts`
- **CASE-apirunner-041** 타임라인 조립: 보낸 것/받은 것이 방향 표식과 함께 시간순으로 정렬된다. 재접속 시도도 항목으로 들어간다. (stream.session AC-2/AC-4)
- **CASE-apirunner-042** 세션 → Run: 세션 하나가 Run 하나가 되고 메시지 목록이 그 관측 내용이다. 상호작용 모양이 Run 에 실리고 **응답 본문 자리는 비어 있다**. 결과 갈래(성공/취소/오류)가 "실패"로 뭉뚱그려지지 않는다. (stream.session AC-6)
- **CASE-apirunner-042b (전송 선택)** 스트리밍 상호작용이 있는 종류는 저마다 다른 전송이 정해진다(WebSocket·SSE·gRPC·GraphQL 구독). 스트리밍이 없는 종류는 **흉내 내지 않고** 사유가 달린 빈 결과를 준다. 단발·수신 모양은 각각 Send·Inbox 로 안내한다. (stream.session AC-7) → `shared/api/stream.test.ts`
- **CASE-apirunner-042d (세션 안전선)** 자동 재접속은 **총 시도 상한**에서 멈춘다 — 붙었다 끊기를 반복하는 서버에서 연속 카운터가 0으로 돌아가 영원히 재접속하면 세션이 끝나지 않아 기록도 안 남는다. 상한을 넘긴 사실이 이유에 적힌다. (stream.session AC-10) → `shared/api/stream.test.ts`
- **CASE-apirunner-042e (원격 입력 상한 · 조용한 소실 금지)** 줄바꿈 없이 계속 흘리는 서버, 거대한 한 프레임, 상식을 넘는 `id` 를 각각 상한에서 끊고 **자른 사실을 데이터에 적는다.** 상한 하나 때문에 세션이 죽지 않는다. 긴 한 줄이 여러 청크로 와도 **이차식으로 느려지지 않는다**(예전 구현은 16MB 한 줄에 2.4초 — 메인 프로세스 정지). (stream.session AC-11) → `shared/api/sse.test.ts`
- **CASE-apirunner-042f (가공된 비밀)** 같은 비밀의 **다른 표기**(URL 인코딩·base64·대소문자)도 지울 목록에 든다 — 서버가 그 형태로 되돌려주기 때문. 해시·서명은 되돌릴 수 없어 **못 지운다**(한계를 테스트가 못박는다). (send.observe AC-3b) → `shared/api/redact.test.ts`
- **CASE-apirunner-042g (늦게 더한 비밀)** 세션·대기 **도중** 환경에 비밀을 새로 추가해도 그 뒤 오는 메시지·수신에서 지워진다 — 가리는 목록을 시작 시점에 가두면 그 뒤 것이 샌다. (stream.session AC-8 · inbox.listener AC-8) → `e2e/suites/36-api-inbox.mjs`
- **CASE-apirunner-042c (SSE 프레임)** 청크 경계가 프레임을 잘라도 이어 붙인다. 줄바꿈 세 종류(LF·CRLF·CR)를 모두 줄 끝으로 보고, CRLF 가 청크 사이에서 갈려도 한 줄로 센다. 주석(하트비트)은 메시지로 세지 않고, `data` 없는 프레임은 이벤트가 아니며, 서버가 끊어도 마지막 프레임을 `flush` 로 꺼낸다. → `shared/api/sse.test.ts`
- **CASE-apirunner-043** 수신 본문 대조: 들어온 본문을 선언한 기대 스키마와 대조해 **네 갈래**로 가린다 — 맞음 · 어긋남 · **`선언 없음`** · **`대조 불가`**(JSON 아님). 뒤 둘은 맞음이 아니다. 선언이 깨져 있어도 추측하지 않고 `선언 없음`. 필수 누락·타입 불일치·null 을 각각 경로와 함께 지목하고 중첩까지 들어간다. **선언에 없는 필드가 더 와도 어긋남이 아니다**(발신자는 남이다). 필수여부 `모름`은 빠지고 몇 개 뺐는지 실린다. (inbox.received AC-3 · AC-6) → `shared/api/inbox.test.ts`
- **CASE-apirunner-043b (받는 모양만)** 수신 대기는 `inbound` 요청에만 걸린다 — 보내는 요청에 걸려 하면 이유를 달아 거부한다. (inbox.listener AC-7)
- **CASE-apirunner-044** 포트 충돌 처리: 쓰는 포트면 이유를 알리고 다른 포트를 제안한다. **몰래 다른 포트로 옮겨 붙지 않는다**(주소를 이미 남에게 알려 줬을 수 있다) — 대기는 꺼짐으로 남는다. 가까운 데 빈 포트가 없으면 지어내지 않는다. 수신 주소는 **로컬 고정**이라 외부 호스트를 만들 손잡이가 없다. (inbox.listener AC-2/AC-3) → `shared/api/inbox.test.ts`
- **CASE-apirunner-045** 타임라인 도구: 검색·필터가 메시지 목록에 동작하고, 메시지 하나 복사·전체 내보내기가 원문을 보존한다. (stream.session AC-5)
- **CASE-apirunner-046** 수신 목록 행: 들어온 요청이 시간순으로 쌓이고 메서드·경로·크기·시각이 담긴다. 헤더·본문 전문이 보존된다. (inbox.received AC-1/AC-2)
- **CASE-apirunner-047** 수신 → Run: 웹훅 수신 하나가 Run 하나가 된다 — 웹훅도 관측 기록이다. **방향이 반대라 칸의 뜻도 반대다** — `request` 가 들어온 것이고 `response` 는 우리가 되돌려준 것이다. 대조 결과가 관측 내용에 남고, **대조가 어긋나도 수신 자체는 성공**이다(둘은 다른 축). (inbox.received AC-4) → `shared/api/inbox.test.ts`
- **CASE-apirunner-048** 수신 응답 코드: 기본 `200`, 지정하면 그 코드로 응답한다(재전송 유도를 위해 실패 코드도 낼 수 있어야 한다). (inbox.received AC-5)
- **CASE-apirunner-046a (gRPC — 정의를 못 받으면 안 붙는다)** reflection 을 안 켠 서버에서는 세션을 열지 않고 사유를 준다. **`연결됨` 으로 가지 않는다** — 붙여 놓고 아무것도 못 읽으면 사용자가 서버를 의심한다. (stream.session AC-7b) → `main/api/grpcReflect.test.ts` · `e2e/suites/39-api-grpc.mjs`
- **CASE-apirunner-046b (gRPC — 모양은 서버가 정한다)** 서버 정의상 단발인 메서드는 스트림으로 열지 않고 Send 로 안내한다. 없는 메서드는 **서버가 아는 목록과 함께** 사유를 준다(오타인지 패키지가 다른지 알 수 있어야 한다). (stream.session AC-7b) → `main/api/grpcReflect.test.ts`

- **CASE-apirunner-050 (오조작 방지)** 앱 진입 직후 Environment 가 **선택되지 않음**이고 실행 버튼이 비활성이다. 이유 툴팁이 보인다. (guard AC-1)

## 미구현 · 미검증 (조용한 통과 금지)
> 아래는 **정의는 있으나 아직 만들지 않은 것**이다. 케이스가 적혀 있다고 통과한 것이 아니다.
- **스트림·수신 기록의 다시 실행** — 안 만든다(의도). 세션을 "다시 트는 것"은 같은 뜻이 아니고,
  웹훅은 우리가 보내는 것이 아니다. 화면이 그 버튼을 안 그린다.
- **외부 터널** — 1차 로컬 전용이므로 외부 콜백 수신 케이스는 없다. 터널 도입 시 승격.
  화면이 그 사실을 상시 문구로 말하고, `127.0.0.1` 바인딩이 코드로 고정돼 있다(호스트 손잡이 없음).
- **수신 목록 상한(500건)** — 넘겼을 때 "버렸다"를 적는 것까지 구현했으나 **e2e 로 안 밟았다**
  (500건을 쏘는 스위트가 없다). 본문 상한(2MB)은 `36-api-inbox` 가 실제로 밟는다.
- **앱 재시작 후 대기 꺼짐** — 코드로는 아무것도 자동 복원하지 않아 구조적으로 보장되지만,
  `12-cold-restart` 가 API 스위트보다 **먼저 돌아** 재시작 검증에 안 들어간다(`main` 몫 항목).
- **구독 재접속 · `wss://`(TLS)** — 재접속 정책은 다른 전송과 같은 자리를 지나지만
  **구독으로 재접속이 도는 것은 e2e 로 안 밟았다**(손잡기를 다시 하는 왕복이 붙는다).
  `wss://` 도 검사용 서버가 평문이라 **안 밟았다** — 주소 바꾸기는 단위 테스트로 덮였다.
- **회차가 끝난 뒤 통로가 실제로 닫히는지**(AC-7d) — 참조를 버리는 대신 닫도록 고쳤고
  회차 빗장·회차 가드를 세웠고, 2026-07-29 에 **통로를 한 칸으로 모아** 닫는 자리를 하나로
  만들었다(전송별 칸 3개 → 1개, `Session` 안 전송 분기 5곳 → 1곳). 다만 **열린 소켓 수를
  세는 검사는 여전히 없다**(그걸 보려면 앱 안의 핸들을 들여다봐야 한다).
- **평문 소켓 고지·`id` 가 다른 메시지·손잡기 전 소음 상한** — 전부 단위 테스트로 덮였지만
  **실제 서버로는 안 밟았다**(그렇게 행동하는 검사용 서버를 더 세워야 한다).
- **구독을 여러 개 한 소켓에** — 규약은 `id` 로 여러 구독을 구분할 수 있지만 우리는
  세션당 하나만 연다(`id` 고정). 화면이 요청 하나를 고르는 모양이라 필요가 없다 —
  필요해지면 그때 연다.
  (gRPC 는 2026-07-29 구현 — `CASE-apirunner-046a~046g` · `39-api-grpc`.
   GraphQL 구독도 같은 날 — `CASE-apirunner-047a~047f` · `40-api-graphql-sub`.)
- **gRPC 재접속 · TLS** — 자동 재접속은 WebSocket·SSE 와 같은 자리를 지나므로 정책은 같지만,
  **gRPC 로 재접속이 도는 것은 e2e 로 안 밟았다**(정의를 다시 받아 오는 왕복이 붙는다).
  `grpcs://`(TLS) 도 검사용 서버가 평문이라 **안 밟았다** — 주소 읽기는 단위 테스트로 덮였다.
  · **재접속마다 정의를 다시 받아 온다**(캐시 없음). 붙자마자 끊는 서버에서 상한 20회까지
    그 왕복이 반복된다 — 동작은 맞지만 낭비이고, 고치지 않았다(성능 리뷰 지적).
- **gRPC 상한(정의 16MB · 서비스 500개)** — 넘겼을 때 판정을 멈추고 그 사실을 말하는 것까지
  구현했으나 **e2e 로 안 밟았다**(그만큼 흘리는 서버를 세우는 스위트가 없다). 단위 테스트도 없다.
- **`__proto__` 를 서비스 이름으로 쓰는 서버** — 훑을 때 걸러 내는 것까지 구현했고 단위
  테스트가 덮지만, **실제 그런 서술자를 만드는 서버로는 안 밟았다**(추정 위험으로 남긴 지적).
- **스트림 타임라인 상한** — 5,000건을 넘기면 오래된 것부터 버리고 건수를 알린다(화면·기록이
  같은 수를 말한다). 파서 상한은 단위 테스트로 덮였지만 **세션 5,000건 초과는 e2e 로 안 밟아
  봤다**(그만큼 흘리는 스위트가 없다).
- **자동 재접속 총 상한(AC-10)** — 재접속이 실제로 도는 것은 `35-api-stream` 이 밟는다.
  다만 **20회 상한에 닿는 것**은 안 밟았다(20번을 유발하려면 스위트가 분 단위로 길어진다).
  정책 자체는 단위 테스트로 덮였다.
- **연결 제한시간(AC-9)** — 30초. 실제로 걸리게 하려면 스위트가 30초를 기다려야 해서 **안 밟았다**.
