# TestPlan: uiux-ia (UI/UX 서비스 골격 — 모듈·뷰 트리 + 컨텍스트 셀렉터)

> 정의(무엇을 검증하나)만 여기. 코드는 대상 모듈 옆 `*.test.ts`(vitest) + 앱 흐름 스위트 `e2e/suites/NN-*.mjs`.
> 명세 정본: `docs/spec/uiux-ia.md`.

## Scenario S1 — 서비스 선언 무결성 (순수 로직) → `services/uiux/service.test.ts`

선언 데이터가 깨지면 셸이 조용히 이상하게 그려진다(탭이 사라지거나, 두 칸이 같은 id 라 하나만 잡히거나).
**깨지면 실제로 문제가 되는 것만** 붙든다 — 라벨 문자열을 그대로 옮겨 적지 않는다.

- **CASE-uiux-001** 모듈 구성: 6개이고 순서가 `features · screens · flows · rules · style · versions` 다. 첫 칸이 `features` 여야 한다(기본 진입). (shell.modules AC-1/AC-2)
- **CASE-uiux-002** 뷰 구성: `screens` 는 `canvas · spec · review`, `style` 은 `tokens · components`, `versions` 는 `timeline · diff` 를 갖는다. `features` · `flows` · `rules` 는 뷰 없이 자기 workspace 를 갖는다 — 뷰도 workspace 도 없는 모듈이 있으면 그 칸은 빈 화면이 된다. (shell.modules AC-3)
- **CASE-uiux-003** id 유일성: 모듈 id 가 서로 겹치지 않고, 한 모듈 안의 뷰 id 도 서로 겹치지 않는다. (shell.modules AC-6)
- **CASE-uiux-004** 컨텍스트 셀렉터: `project · version · viewport` 세 개이고, `version` 기본값은 `draft`, `viewport` 기본값은 `pc` 이며 옵션은 `pc · tablet · mobile` 셋이다. `project` 는 기본값 없이 안내 문구를 갖는다. (shell.context AC-1/AC-3/AC-4/AC-5)
- **CASE-uiux-005** 구획을 나누지 않는다: 어떤 셀렉터도 `activeInAreas` 를 갖지 않고(= 모든 모듈에서 활성), 어떤 모듈도 `area` 를 갖지 않는다. DB 서비스의 설계부/운영부 분리를 따라가지 않는다는 결정이 코드에 남아야 한다. (shell.context AC-2)

## Scenario S2 — 앱 구동 순회 (실 앱) → `npm run surface-verify`

- **CASE-uiux-010** 전 화면 순회: 셸의 `data-nav-service` / `data-nav-module` / `data-nav-view` 훅을 타고 UI/UX 의 leaf 10개(features · screens×3 · flows · rules · style×2 · versions×2)를 모두 방문하고, 각 화면이 자기 경로 배지를 보인다. **별도 스위트를 만들지 않는다** — 화면 품질 게이트(`e2e/surface/verify.mjs`)가 nav 등록만으로 자동 순회하므로 등록이 곧 커버리지다. (shell.modules AC-4/AC-5)

> **기준선 메모 (2026-07-28 실측).** placeholder 화면의 경로 배지는 대비가 4.35(< 4.5) 라 화면 품질
> 게이트가 위반으로 잡는다. 기존 두 화면(`canvas` · `components`)도 같은 이유로 수용돼 있었고, 화면이
> 10개로 늘면서 `e2e/surface/baseline/uiux.json` 이 2건 → **10건**이 됐다. 원인은 공용 컴포넌트
> (`ui/PlaceholderView`)의 흐린 배지 색이고, 공용 파일은 `main` 에서 다섯 서비스 영향을 보며 고쳐야
> 하므로 이번 범위가 아니다 — **실제 화면이 들어오면 placeholder 와 함께 사라진다**.
>
> **따로 기억할 것**: 첫 실행에서 컨텍스트 셀렉터 라벨(`Viewport`)도 같은 4.35 로 한 번 잡혔는데
> 갱신·재실행에서는 재현되지 않아 기준선에 들어가지 않았다. 원인 후보는 `shell/ContextBar.tsx` 의
> 라벨 색(`text-muted` — 배지와 같은 값)이다. 이건 placeholder 와 달리 **화면이 들어와도 남는
> 상시 요소**이므로, 재발하면 기준선으로 덮지 말고 `main` 에서 공용 색을 다뤄야 한다.

## Scenario S3 — 안정 주소 (순수 로직) → `services/uiux/address.test.ts`

흐름의 도착점·규칙의 대상·핀 코멘트가 전부 주소에 걸린다. 주소가 흔들리면 그 전부가 조용히 끊긴다.

- **CASE-uiux-020** 조각 규칙: 소문자·숫자로 시작하는 소문자 영숫자·하이픈·밑줄만 통과한다. 대문자·공백·한글·점·기호 시작은 막는다. (INV-2)
- **CASE-uiux-021** 거절 이유를 사람 말로: 빈 값·점·공백·대문자·시작 글자·쓸 수 있는 글자를 각각 다른 문구로 알린다. 화면이 그대로 보여줄 문구이므로 "패턴 불일치" 같은 말을 쓰지 않는다. (INV-2)
- **CASE-uiux-022** 주소 만들기: 층을 순서대로 이어 붙이고(1~4조각), 잘못된 조각이 있으면 **던진다** — 잘못된 주소가 데이터에 남으면 나중에 조용히 안 걸린다. 몇 번째 층이 문제인지 알린다.
- **CASE-uiux-023** 되돌리기: 주소를 층으로 분해하고, 깊이가 얕으면 아래 층은 비운다. 주소가 아닌 것(빈 값·빈 조각·대문자·5조각 초과)은 **예외가 아니라 null** 로 판정한다. 만든 주소는 그대로 되돌아온다(왕복).
- **CASE-uiux-024** key 충돌: 같은 부모 아래 겹친 key 를 한 번씩 돌려준다(세 번 겹쳐도 한 번). (INV-1)

> INV-1 은 두 겹으로 지킨다 — 저장 전 이 판정 + `uiux_*` 테이블의 UNIQUE 인덱스. 인덱스 쪽 검증은
> 저장 경로(IPC)가 생기는 단계에서 통합 케이스로 덮는다.

## Scenario S4 — 화면 내용 읽기·쓰기 (순수 로직) → `services/uiux/content.test.ts`

저장소에서 읽은 JSON 은 믿을 수 없다(손으로 고쳤거나, 예전 모델이거나, 에이전트가 잘못 썼거나).
여기서 던지면 **화면 목록 전체가 안 뜬다.**

- **CASE-uiux-030** 못 읽는 입력: 빈 값·깨진 JSON·객체가 아닌 것(`null`·배열·문자열·숫자)은 빈 내용으로 떨어진다. 던지지 않는다. (INV-3)
- **CASE-uiux-031** 부분 복구: `sections` 가 배열이 아니면 빈 목록으로 살리되 나머지 필드는 남긴다. id 없는 섹션·컴포넌트, type 없는 컴포넌트는 걸러내고 나머지는 살린다(id 는 트리 조작의 손잡이라 없으면 못 살린다). `components` 가 없으면 빈 목록, `name` 이 없으면 빈 문자열.
- **CASE-uiux-032** 껍데기 이벤트: 효과(화면 전이·데이터 변이)가 하나도 없는 이벤트는 버린다 — 아무 일도 안 하기 때문. 살아남은 게 없으면 `events` 칸 자체를 두지 않는다.
- **CASE-uiux-033** 쓰기: 빈 값(빈 이벤트 목록·빈 뷰포트)은 적지 않아 diff 를 조용하게 유지한다. 쓴 것은 그대로 읽힌다(왕복).

## Scenario S5 — 화면 안 트리 조작 (순수 로직) → `services/uiux/tree.test.ts`

**Spec 뷰와 Canvas 가 같이 쓰는 층**이다. 편집 규칙이 화면마다 흩어지면 한쪽에서만 되는 조작이
생기고, 그때부터 두 화면이 서로 다른 데이터를 만든다.

- **CASE-uiux-040** id 만들기: 안 쓰인 이름은 그대로, 겹치면 번호를 붙이되 **중간이 비면 그 자리를 쓴다**(번호가 무한히 커지지 않게). 섹션과 컴포넌트가 한 이름 공간을 쓰므로 섹션 이름과 겹치는 컴포넌트 id 는 만들어지지 않는다.
- **CASE-uiux-041** 더하기: 섹션은 기본 맨 뒤(자리를 주면 그 자리). 컴포넌트 id 는 **종류에서 딴다**(`input`) — 흐름·규칙이 가리키는 손잡이라 사람이 읽을 수 있어야 한다. 없는 섹션에 넣으면 아무 일도 없다(화면이 사라진 섹션을 가리킬 수 있다).
- **CASE-uiux-042** 입력을 고치지 않는다: 모든 조작이 새 객체를 돌려준다 — 변경 감지와 되돌리기의 전제다.
- **CASE-uiux-043** 지우기: 컴포넌트는 그것만, 섹션은 안의 컴포넌트까지. 없는 id 는 아무 일도 없다.
- **CASE-uiux-044** 옮기기: 다른 섹션으로 옮긴다. 없는 컴포넌트·없는 섹션이면 아무 일도 없다.
- **CASE-uiux-045** 자리 기준: `toIndex` 는 **뽑아낸 뒤의 자리**다 — 같은 섹션에서 아래로 옮기면 뒤 항목이 한 칸 당겨지는데, 이 기준이어야 "3번째에 놓는다"가 언제나 같은 뜻이 된다. 범위를 벗어난 자리는 끝으로 접는다(드래그가 범위를 넘겨도 안 깨진다).
- **CASE-uiux-046** 섹션 순서도 같은 기준으로 바꾼다.
- **CASE-uiux-047** 고치기: 속성만 바꾸고 **id 는 그대로 둔다** — 이벤트가 그 id 로 가리키고 있다.
- **CASE-uiux-048** 전이 붙이기: 요소에 붙이고 되읽는다. 같은 요소에 다시 붙이면 **갈아탄다**(한 요소에 하나 — v1). 떼면 그 요소 것만 사라지고 남는 게 없으면 칸 자체를 지운다. 입력을 고치지 않는다.

## Scenario S7 — 조각 치환 엔진 (순수 로직) → `services/uiux/preview/template.test.ts`

조각은 사용자·에이전트가 고칠 수 있다. 하나가 잘못됐다고 화면 전체가 안 그려지면 무엇이
잘못됐는지도 볼 수 없다.

- **CASE-uiux-060** 값 넣기: `label`·`props.*` 를 슬롯에 넣는다. 값이 없으면 빈 문자열(조각에 `{{...}}` 가 그대로 남지 않게). 숫자·불리언은 글자로, 객체는 비운다(`[object Object]` 방지).
- **CASE-uiux-061** **이스케이프**: 사용자가 넣은 이름표가 그대로 마크업이 되지 않는다. 미리보기는 그림자 뿌리 안이지만 스크립트는 그 안에서도 돈다.
- **CASE-uiux-062** 있으면 보이기: 값이 있으면 내용을, 없으면 통째로 없앤다. 빈 문자열·빈 배열·false 는 "없는 것"으로 본다.
- **CASE-uiux-063** 배열 반복: 항목마다 반복하고 `{{.}}` 에 지금 항목을 넣는다. 반복 항목도 이스케이프한다.
- **CASE-uiux-064** 망가진 조각(닫히지 않은 섹션·빈 문자열·이상한 경로)에도 던지지 않는다. 치환되지 않은 부분은 그대로 남겨 무엇이 잘못됐는지 보이게 한다.

## Scenario S8 — 미리보기 렌더 (순수 로직) → `services/uiux/preview/render.test.ts`

**토큰이 렌더를 지배한다**를 기계로 강제하는 자리다. 이게 없으면 조각에 색을 하드코딩해도
아무도 모르고, 그 순간 토큰의 뜻이 사라진다.

- **CASE-uiux-070** 고르기 목록의 모든 종류에 조각이 있다 — 빈칸이면 그 종류는 대체 조각으로 떨어진다.
- **CASE-uiux-071** 조각 CSS 에 **하드코딩된 색·길이가 없다**(토큰 변수·`calc` 안은 제외). 그리고 조각이 쓰는 토큰 변수가 기본 토큰에 **전부 있다** — 없는 변수를 쓰면 그 스타일이 조용히 안 먹는다.
- **CASE-uiux-072** 모르는 종류는 대체 조각으로 떨어진다(화면에 구멍을 내지 않는다). 모든 조각이 **값 없이도** 그려진다 — 막 만든 컴포넌트는 이름표조차 없다.
- **CASE-uiux-073** 조각을 마크업과 스타일로 가르고, 셀렉터에 `.t-<종류>` 스코프를 붙인다(쉼표로 나열한 것도 각각). 여러 조각이 같은 클래스 이름을 써도 서로 안 덮인다.
- **CASE-uiux-074** 배치 → CSS: 기본은 세로 쌓기, 가로는 **기본 줄바꿈**(좁은 폭에서 안 깨지게), 격자는 칸 수를 반영하고 범위 밖 값은 접는다. 간격은 토큰 경로면 변수로, 길이면 그대로.
- **CASE-uiux-075** 화면 그리기: 구조대로 그리고 **쓰인 조각의 CSS 만** 모은다. 래퍼는 `display:contents` 라 배치에 끼어들지 않는다. 섹션 이름은 켰을 때만 보인다. 토큰이 뿌리에 실린다.
- **CASE-uiux-077** 고른 요소는 외곽선, 끌고 있는 요소는 흐리게. 아무것도 안 골랐으면 그 규칙 자체가 실리지 않는다.
- **CASE-uiux-076** 빈 화면·이상한 종류 이름에도 던지지 않는다. 클래스에 들어가는 종류 이름은 CSS 에서 안전한 글자로 바뀐다. 뷰포트 폭은 PC > 태블릿 > 모바일 순으로 좁아진다.

## Scenario S9 — 끌어놓기 계산 (순수 로직) → `services/uiux/preview/dnd.test.ts`

좌표를 다루는 유일한 자리다. 여기서 잘못 세면 **엉뚱한 데 떨어지고**, 그건 사용자가 가장
빨리 신뢰를 잃는 종류의 버그다.

- **CASE-uiux-080** 자리 가르기: 세로 배치는 위아래 중심으로, 가로·격자는 **줄부터** 가른다(좌우만 보면 아랫줄이 윗줄보다 앞이 된다). 같은 줄이면 좌우 중심.
- **CASE-uiux-081** 끌고 있는 것은 세지 않는다 — 그래서 나온 자리가 곧 `moveComponent` 의 "뽑아낸 뒤의 자리"와 같다(변환이 필요 없다). 그 자리를 그대로 넣으면 의도대로 옮겨진다.
- **CASE-uiux-082** 빈 영역은 0번. 어느 영역에도 안 걸리면 **null**(놓아도 아무 일 없음). 영역이 겹치면 안쪽 것을 쓴다.
- **CASE-uiux-083** 제자리 판정: 원래 자리에 놓으면 옮기지 않는다(집었다 놓기만 해도 저장이 도는 것을 막는다). 없는 요소는 옮길 것이 없으므로 제자리로 본다.
- **CASE-uiux-084** 가이드 선은 넣을 곳 **앞뒤 사이**에 긋는다 — 요소 위에 겹치면 "얹는다"로 읽힌다. 세로 배치는 가로선, 가로 배치는 세로선.
- **CASE-uiux-085** 빈 영역이면 영역 맨 앞에, 없는 영역이면 null.

## Scenario S11 — 능력별 집계 (순수 로직) → `services/uiux/features.test.ts`

- **CASE-uiux-090** 앱 › 서비스로 접어 세고 위로 올라가며 합친다 — 화면 단위로 세면 사람 말이 안 된다.
- **CASE-uiux-091** 화면이 없는 앱·서비스도 빠뜨리지 않는다(빠진 자리를 봐야 한다). 모르는 상태 값은 `designed` 로 본다(저장소는 열린 문자열). 빈 트리도 던지지 않는다.
- **CASE-uiux-092** 완성도는 **확인된 것만** 센다 — 구현만 된 것을 완성으로 세면 "다 됐다"가 거짓이 된다. 화면이 없으면 0(나눗셈을 하지 않는다).

## Scenario S12 — 토큰 병합 (순수 로직) → `services/uiux/preview/tokens.test.ts`

## Scenario S10 — 실제 앱 흐름 → `e2e/suites/13-uiux-spec.mjs`

- **CASE-uiux-050** 위계 만들기 → 구조 편집 → 저장 잔존: 프로젝트가 없으면 안내와 CTA 를 보이고, 프로젝트를 만들면 **바로 그것을 보게 된다**. 앱 → 서비스 → 화면을 만들고, 같은 자리 주소 중복은 거절하며 이유를 보인다(INV-1). 화면을 고르면 안정 주소(`coupang.buyer.auth.login`)가 층을 이어 만들어진다. 영역·요소를 넣으면 요소 id 가 종류에서 따지고, **화면을 떠났다 돌아와도 남는다**(저장이 실제로 됐다는 뜻). 요소를 지우면 그것만 사라진다. (spec `uiux.screens.spec` 전 Section)
- **CASE-uiux-051** Canvas 미리보기: 같은 화면이 실제 화면으로 그려지고(그림자 뿌리 안이라 로케이터가 뚫고 본다), 조각이 **토큰 변수를 상속받아** 그려지며, 지금 뷰포트 폭을 헤더에 알린다. 뷰를 바꿔도 위계가 남는다(셸 공유). (spec `uiux.screens.canvas`)
- **CASE-uiux-058** Versions: 지금 설계를 **굳히면** 목록에 쌓이고, 그 뒤 화면 이름을 고치면 비교에서 **"이름 A → B"** 로 짚힌다. 볼 필요가 있는 것이 위로 온다. 에이전트는 굳힌 버전을 읽을 수 있지만 **컷·삭제는 못 한다**(경계를 끊는 건 사람의 판단). (spec `uiux.versions`)
- **CASE-uiux-057** Rules: 요소에 형식 규칙을 붙이면 **그 자리에서 문장으로** 보이고, Rules 에 프로젝트 전체가 모인다. (spec `uiux.rules`)
- **CASE-uiux-056** Flows: 요소 속성에서 **화면 목록으로** 전이를 붙이면(주소를 손으로 안 적는다) 그래프에 화면이 노드로 뜨고 줄이 갈린다. (spec `uiux.flows`)
- **CASE-uiux-055** Style(토큰): 처음엔 전부 기본값이고, 색을 바꾸면 **몇 개 바꿨는지** 알린다. Components 뷰가 조각을 종류별로 늘어놓고, **바꾼 토큰이 미리보기에 그대로 들어간다**(computed style 로 확인) — Style 이 있는 이유가 이 한 줄이다. 에이전트는 `get_ui_tokens` 로 그 값을 읽고(실제 코드의 토큰과 맞추려고), `set_ui_tokens` 는 **준 값만** 바꾼다. (spec `uiux.style`)
- **CASE-uiux-054** Review(의견): 요소를 고르면 **어디에 남기는지** 알려주고, 남긴 의견이 목록에 쌓이며, 그 요소가 미리보기에 **점선으로** 표시된다. 에이전트가 `list_ui_notes` 로 그 의견을 **요소 주소째** 읽고, `resolve_ui_note` 로 넘기면 미해결 목록에서 빠진다 — 사람 → 에이전트 → 반영의 한 바퀴. (spec `uiux.screens.review`)
- **CASE-uiux-053** MCP 한 바퀴: 에이전트가 `get_ui_tree` 로 **안정 주소째** 위계를 받고, `get_ui_surface` 로 화면 구조를 읽고, `set_ui_surface_status` 로 **확인 결과를 되돌려 적는다**. 없는 주소는 프로토콜 오류가 아니라 **어떻게 확인하는지 담은 안내**로 돌아온다. 읽기·쓰기 6종이 모두 노출되고 삭제류 ui 도구는 없다. 그리고 그 기록이 **Features 집계에 나타난다** — 사람이 만들고 → 에이전트가 판정하고 → 앱이 보여주는 한 바퀴.
