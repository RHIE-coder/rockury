# Service: db-connections (Connections — 운영부)

> 원시 DB 접속(Connection)의 목록·상태 확인·그룹 분류를 담당하는 화면 명세 정본.
> 위계: Service > Surface > Section > Component. ID 는 코드·테스트와 기계 대조용 안정 키.
> 코드: `src/renderer/src/services/db/connections/` · 저장 `src/main/store/connections.ts`.

공통 불변식
- 비밀번호 평문은 카드/목록에 절대 노출하지 않는다(편집 다이얼로그 눈 아이콘만).
- 그룹은 표시·분류 상태일 뿐 — 어떤 연결 능력(테스트·바인딩·Remote)에도 영향이 없다.

---

## Surface: db-connections.list (Connections 뷰)

### Section db-connections.list.auto-check — 진입·새로고침 자동 확인
- **AC-1** 뷰 진입(마운트)·`새로고침` 버튼은 모든 연결을 병렬로 확인한다 — 단, `자동 확인에서 제외` 연결은 건너뛴다.
- **AC-2** 건너뛴 연결의 이전 확인 결과는 **'미확인'으로 되돌린다**. 옛 "실패/연결됨"이 남아
  방금 확인된 것처럼 읽히면 안 된다(2026-07 사용자 실측 혼동 → 회귀 금지).
- **AC-3** 편집에서 제외로 바꾸는 즉시 그 카드 상태도 '미확인'으로 초기화한다.
- **AC-4** 카드별 수동 테스트(플러그 버튼)는 제외 여부와 무관하게 항상 동작한다(탈출구).
- **AC-5** 제외 연결 카드에는 `자동확인 제외` 배지를 표시한다.

### Section db-connections.list.groups — Connection 그룹
- **AC-1** `새 그룹` 버튼으로 그룹 생성 — 생성 직후 인라인 이름 입력이 열린다(Enter/blur 확정, Esc 취소).
- **AC-2** 그룹 섹션 헤더: 폴더 아이콘 + 이름 + 카드 수 + 이름변경(연필)/삭제(휴지통, 인라인 확인).
- **AC-3** 그룹 삭제 시 소속 연결은 **지워지지 않고 미분류로** 돌아간다.
- **AC-4** 그룹은 1단계(중첩 없음). 화면 순서: 그룹들(sort_order) → 미분류.
- **AC-7** 그룹 헤더 왼쪽 **그립 손잡이(⠿)를 끌어 그룹의 위아래 순서를 바꾼다** — 카드 DnD 와 동일한 방식:
  드래그 중 **원본 섹션은 목록에서 빠지고 그 자리(놓일 위치)에 점선 자리표시(가상 배치)가 들어가며**,
  그룹 축약본 고스트가 마우스를 따라온다. Esc/스크롤 영역 밖 놓기는 취소. 순서는 `connectionGroups:reorder` 로 영속. (미분류는 항상 마지막)
- **AC-5** 미분류 섹션은 그룹이 하나라도 있을 때만 `미분류` 라벨을 보인다(그룹 0개면 기존 평면 그리드 그대로).
- **AC-6** 사라진 그룹을 가리키는 연결은 미분류로 취급한다(카드 증발 금지 — `bucketByGroup` 안전망).

### Section db-connections.list.dnd — 카드 드래그 앤 드롭
- **AC-1** 카드를 6px 이상 끌면 드래그 시작(그 미만은 평범한 클릭=활성 연결 선택). 카드 안 버튼 위에서는 시작하지 않는다.
- **AC-2** 드래그 중 **고스트(카드 축약본)가 마우스를 따라온다**. 원본 카드는 목록에서 빠진다.
- **AC-3** 놓일 자리는 **점선 플레이스홀더(가상 요소)** 로 대상 섹션의 삽입 위치에 미리 보인다.
  대상 섹션에는 강조 테두리를 준다.
- **AC-4** 드롭으로 그룹 넣기/빼기(미분류)/같은 섹션 내 순서 변경이 된다. 섹션 밖에서 놓거나 Esc 를 누르면 취소.
- **AC-5** 순서 캐논: 전역 sort_order 하나로 관리 — [그룹들(그룹 순서)의 카드…, 미분류 카드…] 평탄화.
  그룹-로컬 순서 컬럼을 따로 두지 않는다(`applyMove` 가 전역 순서를 재계산, 이동+정렬은 단일 트랜잭션 `connections:move`).
- **AC-6** 기하 판정(`insertionIndex`)은 그리드 행(수직 겹침)으로 묶고 행 안에서 카드 가로 중심으로 앞/뒤를 가른다.

### Section db-connections.list.data — 저장 모델
- **AC-1** `connection_groups(id, name, sort_order, created_at, updated_at)` + `connections.group_id`(NULL=미분류).
- **AC-2** 신규 IPC 채널(`connections:move`, `connectionGroups:*`)은 MCP coverage 지도에 등재한다(현재: 전부 제외 — UI 분류 상태).

## Surface: db-connections.sample (샘플 DB)

> **샘플 DB** = 앱이 스스로 만들어 주는 SQLite 파일 하나와 그것을 가리키는 Connection.
> 처음 켠 사용자가 준비물 없이 곧장 화면을 써 보게 하는 것이 유일한 목적이다.
> 도커 스택(여러 벤더)은 이 명세 범위 밖 — 뒤 단계에서 별도로 다룬다.

공통 불변식
- **준비물이 없다.** 도커·네트워크·외부 프로세스에 의존하지 않는다. 도커가 없는 기기에서 전부 동작한다.
- **개발 환경을 건드리지 않는다.** `npm run db:up` 이 만드는 `scripts/test-db/data/testdb.sqlite` 와
  **다른 파일**이다. 앱이 개발용 컨테이너·파일을 지우거나 덮는 일이 없다.
- 실패하면 아무것도 남기지 않는다 — 파일만 생기고 접속이 없거나 그 반대인 반쪽 상태를 만들지 않는다.

### Section db-connections.sample.entry — 진입점
- **AC-1** 빈 상태(`아직 연결이 없어요`)에 `샘플 DB 만들기` 를 `첫 연결 만들기` 옆에 둔다. 부차 강조(outline).
- **AC-2** 툴바에 상시 둔다 — 위치는 `새 그룹` 왼쪽. 접속이 쌓인 뒤에도 사라지지 않는다.
- **AC-3** **버튼 라벨이 상태를 말한다** — 샘플 접속이 없으면 `샘플 DB 만들기`, 있으면 `샘플 DB 다시 만들기`.
  눌렀는데 아무 일도 안 일어나는 상태를 만들지 않기 위해서다.
- **AC-4** 버튼 곁에 설명 문장을 붙이지 않는다(화면 문구 규율 — 머리·버튼엔 이름만).

### Section db-connections.sample.create — 만들기
- **AC-1** 파일 위치는 `<userData>/samples/sample.sqlite` **고정**. 사용자가 고르지 않는다
  (되돌리기 쉽고, 앱을 지우면 함께 사라지는 자리라서).
- **AC-2** 만들 접속: 이름 `샘플 DB` · `dbType: sqlite` · `database` = 파일 절대경로 ·
  host/port/user/password 없음. 비밀번호가 없으므로 safeStorage 경로를 타지 않는다.
- **AC-3** **파일과 접속을 따로 판정한다** — 넷 중 하나로 갈린다.

  | 파일 | 접속 | 동작 | 알림 |
  |---|---|---|---|
  | 없음 | 없음 | 둘 다 만든다 | `샘플 DB 만듦` |
  | 있음 | 없음 | 접속만 만든다(파일 보존) | `샘플 DB 만듦 — 기존 파일 사용` |
  | 없음 | 있음 | 파일만 만든다(접속 보존) | `샘플 DB 파일 다시 만듦` |
  | 있음 | 있음 | `다시 만들기` 로 넘어간다(sample.reset) | — |

- **AC-4** 샘플 접속인지는 **이름이 아니라 파일 경로로 판정한다.** 사용자가 이름을 바꿔도 두 개가 생기지 않는다.
- **AC-5** 끝나면 그 접속을 활성 연결로 고른다 — 만들기만 하고 아무 데도 안 데려다주지 않는 상태를 피한다.
- **AC-6** 만들어진 접속은 이후 평범한 접속이다 — 이름 변경·그룹 이동·삭제 모두 다른 카드와 동일하게 된다.

### Section db-connections.sample.reset — 다시 만들기
- **AC-1** 샘플 접속이 있을 때만 나온다.
- **AC-2** **되돌릴 수 없으므로 확인을 거친다.** 확인 문구는 무엇이 지워지는지를 말한다 —
  파일 경로와 함께 `이 파일에 직접 넣은 데이터도 사라집니다`. "초기화합니다" 같은 뭉뚱그린 말은 쓰지 않는다.
- **AC-3** 확인 방식은 그룹 삭제와 같은 결(인라인 확인)로 맞춘다 — 파괴적 동작의 생김새를 한 벌로 둔다.
- **AC-4** **파일만 새로 만들고 접속 레코드는 보존한다**(id·그룹·순서·이름). 그래야 그룹에 넣어 둔 배치가 안 깨진다.
- **AC-5** WAL 모드라 곁 파일(`-wal`·`-shm`)이 함께 생긴다 — 지울 때 셋을 함께 처리한다.
- **AC-6** 새 파일을 먼저 만든 뒤 바꿔치기한다. 지우기에 성공하고 만들기에 실패해 **샘플이 사라지는 상태를 만들지 않는다.**
- **AC-7** 다시 만든 뒤 그 접속의 확인 상태는 `미확인` 으로 되돌리고, 열려 있는 Remote 화면은 스키마를 다시 읽는다
  (옛 파일 기준 목록이 남아 새 파일인 것처럼 읽히면 안 된다 — list.auto-check AC-2 와 같은 이유).

### Section db-connections.sample.source — 샘플 내용과 번들
- **AC-1** **정본 SQL 은 한 벌이다.** 지금 `scripts/test-db/init/sqlite/init.sql` 에 있는 것을
  `src/main/resources/sample-sqlite.sql` 로 옮기고, `scripts/test-db/setup.mjs` 가 그 경로를 읽게 고친다.
  앱용·개발용을 따로 두면 한쪽만 고쳐져 어긋난다.
- **AC-2** 앱은 이 SQL 을 **빌드 시점에 문자열로 품는다**(`?raw` import). 별도 파일로 따라다니게 하면
  배포 도구에 숨은 의존이 생기는데, 지금 이 프로젝트엔 배포 도구 자체가 아직 없다.
- **AC-3** 내용은 표 23개 + 뷰·트리거·인덱스·생성 컬럼. 커머스풍(사용자·조직·상품·주문·결제·재고·게시글)이라
  스키마 읽기·다이어그램·조회를 한 접속에서 다 보여줄 수 있다.
- **AC-4** 이 SQL 은 **빈 파일에만 한 번 실행한다.** 평범한 `INSERT` 23개라 두 번 실행하면 기본키 충돌로 깨진다.

### Section db-connections.sample.errors — 실패
- **AC-1** 폴더 생성·파일 쓰기가 막히면 접속을 만들지 않는다.
- **AC-2** 알림은 무엇이 막혔는지 말한다(권한 없음·디스크 부족 등). "실패했습니다"로 끝내지 않는다.
- **AC-3** 실패해도 기존 접속·그룹은 그대로다.

### Section db-connections.sample.data — 통로
- **AC-1** 새 IPC 채널 셋: `connections:sampleStatus`(파일·접속 유무 읽기) ·
  `connections:createSample` · `connections:resetSample`.
- **AC-2** 셋 다 MCP coverage 지도(`src/main/ai/coverage/db.ts`)에 **제외**로 등재한다 —
  사유: 사용자 디스크에 파일을 만들고 지우는 동작. 등재를 빠뜨리면 `npm test` 가 실패한다.
- **AC-3** 판정 로직(무엇을 만들고 무엇을 건너뛸지)은 화면·파일 입출력과 분리한 순수 함수로 둔다
  (`connections/samplePlan.ts`) — 결정적이라 테스트로 못박을 수 있다.
