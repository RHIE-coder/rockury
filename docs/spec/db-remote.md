# Service: db-remote (Remote — 운영부)

> 활성 연결의 실 DB 를 introspection 으로 역설계해 조회/편집/쿼리한다.
> 이 문서는 레거시(rky-mvp) 기능 이관(Tier A·B + Data 도우미 + 서비스 전역) 범위의 명세 정본이다.
> 위계: Service > Surface > Section > Component. ID 는 코드·테스트와 기계 대조용 안정 키.

공통 불변식
- 편집/DML 커밋은 트랜잭션 게이트(`txBegin → txExec → txCommit/txRollback`)를 거친다. (현행 유지 — 레거시의 비트랜잭션 apply 로 퇴보 금지.)
- 키 표기는 `PK`·`FK`·`UK`·`IDX`·`CHECK` **텍스트 배지만**. 열쇠 이모지 등 애매한 기호 금지.
- **참조 해석은 이름이 아니라 `(스키마, 테이블)` 으로 한다** — 아래 `db-remote.scope` AC-5.

## Surface: db-remote.scope (범위 — 여러 스키마를 한 화면에서) (신설)

> 연결 하나가 dbname 하나에 묶여 있던 것을 풀어, **그 연결에서 볼 스키마들**을 고른다.
> 출처: 2026-07-30 화면 피드백("한 DB 서버에 여러 dbname… PostgreSQL 은 database 안에
> 여러 스키마(public·auth)… 한 번에 보고 싶다"). 작업 기록: `.harness/steward/artifacts/main/intake.md`.

### Section db-remote.scope.model — 벤더마다 다른 층 (불변식)
> 갈리는 기준은 UI 취향이 아니라 엔진 제약이다: **한 연결이 한 번에 볼 수 있는 범위가 어느 층에 있나.**
> 정본: `db/scope.ts`(`scopeModel`).
- **AC-1** MySQL·MariaDB — 다중 선택 대상은 **database** 다. 연결 하나로 `db1.t JOIN db2.t` 가 되고 InnoDB 는 교차 database FK 도 건다. 위층(카탈로그)을 따로 두지 않는다.
- **AC-2** PostgreSQL — 다중 선택 대상은 **한 database 안의 schema** 다. 그 위 database 층은 **연결을 갈아타는 자리**다(연결이 database 하나에 묶이고, 교차 database 는 조인도 FK 도 불가능하다). 여러 database 를 한 화면에 섞지 않는다 — 넘는 관계가 없어 선이 하나도 안 이어진다.
- **AC-3** SQLite — 파일 하나가 database 하나라 고를 것이 없다. 범위 손잡이를 **아예 안 그린다**.
- **AC-4** 도메인은 `TableDef.schema` **한 칸**으로 이 셋을 다 담는다(MySQL 은 database 이름, PostgreSQL 은 schema 이름, SQLite 는 `main`). 카탈로그는 연결의 속성이라 테이블에 싣지 않는다 — 한 화면은 언제나 카탈로그 하나다.
- **AC-5** **참조 해석은 `db/schemaRef` 한 곳에서만 한다**(`resolveRef`·`sameTable`). 이름 문자열로 대상을 찾으면 두 스키마에 같은 이름 테이블이 있을 때 **조용히 엉뚱한 테이블에 붙고**, 그 오염이 ERD 선·Data FK 조회·전체 스크립트 순서·Migration diff 로 번진다(오류가 안 나고 결과만 틀린다). `refSchema` 가 비면 그 제약이 걸린 테이블과 같은 스키마로 친다 — 예전 데이터와 단일 스키마 사용자는 양쪽이 다 비어 있어 동작이 안 바뀐다.

### Section db-remote.scope.selector — 범위 손잡이
- **AC-1** 자리는 **운영 손잡이**(뷰 탭 줄 오른쪽 끝)의 Connection 칸 **바로 뒤 한 곳**이다. 뷰마다 두지 않는다 — 같은 연결인데 Definition 과 Diagram 이 다른 것을 보게 된다. 고른 값을 Definition·Diagram·Data·Query 가 함께 따른다.
- **AC-2** 스키마 층은 **다중 선택**이고, 목록은 시스템 스키마를 뺀 실 DB 조회로 채운다(`introspection:schemas`). 손잡이에는 **지금 보고 있는 스키마 이름**을 적는다 — 하나면 이름, 여럿이면 `첫이름 외 N`, 범위를 한 번도 안 골랐으면 **화면에 실제로 올라온 스키마 이름**(`shownScope`). 아직 아무것도 안 읽었을 때만 자리 이름(`범위`)으로 둔다. `기본` 처럼 무엇을 보고 있는지도 눌러서 뭘 하는지도 안 알려 주는 말은 쓰지 않는다 — 실제로 그렇게 적었다가 사용자가 손잡이를 **못 찾았다**(2026-07-30 "어디있다는거지?").
- **AC-3** **마지막 하나는 끌 수 없다** — 다 끄면 읽을 것이 없어 빈 화면이 되고, 그것은 고장으로 읽힌다.
- **AC-4** (PostgreSQL) database 층은 체크가 아니라 **이동**이다. 같은 서버·포트·계정에서 그 database 에 붙는 연결이 있으면 그 연결로 옮겨 가고, 없으면 그 항목을 흐리게 그리고 이유를 말한다(**말없이 연결을 만들지 않는다**). 왜 여기만 이동인지 목록 머리에 한 줄로 적는다 — 안 적으면 "왜 여러 개를 못 고르지"가 된다.
- **AC-5** 고른 범위는 **연결에 저장된다**(`connections.schemas`). 앱을 다시 열면 보던 범위로 돌아온다. 저장된 것 중 없어진 스키마(지워졌거나 권한이 빠진 것)는 읽을 때 떨어뜨리고, 순서는 고를 수 있는 목록의 순서로 맞춘다(`reconcileScope`) — 그대로 믿으면 없는 스키마를 계속 읽으려다 매번 실패한다.
- **AC-6** 빈 범위(`[]`)는 "기본 스키마 하나"다 — PostgreSQL `current_schema()`, MySQL `DATABASE()`. **예전 연결은 전부 빈 범위라 지금과 똑같이 동작한다**(데이터 이전 없음).

### Section db-remote.scope.introspection — 역설계
- **AC-1** 역설계 3종이 스키마 목록을 인자로 받는다. IR 의 테이블·컬럼·키·FK가 모두 `schema` 를 달고 나오고, FK 는 참조 대상의 `refSchema` 까지 채운다(**범위 밖을 가리킬 수 있어서** — 그 자리가 2단계 "범위 밖 카드"의 입력이다).
- **AC-2** 스키마 이름은 SQL 문자열로 이어 붙이지 않고 파라미터로 넘긴다(PostgreSQL `= ANY($1)`, MySQL `IN (?)`) — 주입 방어.
- **AC-3** 정규화가 만드는 id 에 스키마가 들어간다(`t:<schema>.<table>`). 이름만 쓰면 `public.users` 와 `auth.users` 가 같은 id 를 갖고 **뒤엣것이 앞엣것을 덮어써 테이블 하나가 통째로 사라진다.**
- **AC-4** 목록 정렬은 **스키마 먼저, 그 안에서 이름순** — 범위를 켜면 스키마별로 뭉쳐 보인다.

### Section db-remote.scope.display — 어느 스키마 것인지 화면이 말한다
> 합쳐 보이려면 **구분이 화면에 있어야** 한다. 표시 없이 합치면 `card`(entity)와 `cards`(public)가
> 아무 표식 없이 나란히 서서 어느 쪽인지 알 수 없다(2026-07-30 사용자 실측: "내가 어떻게 이걸 구분하냐").
> 정렬만 스키마순이고 머리가 없으면 오히려 "이름순이 깨진 한 덩어리"로 읽혀 **더 나쁘다**.
- **AC-1** 목록(사이드바)은 **스키마로 먼저 묶고** 묶음마다 이름·개수 머리를 그린다. 그 안에서 테이블/뷰를 가른다(`db-remote.definition.table-list` AC-4 는 묶음 안에서 그대로 적용). 스키마가 하나뿐이면 머리를 안 그린다 — 시끄럽다.
- **AC-2** 머리를 그릴지는 **검색 결과가 아니라 전체 목록** 기준이다. 검색으로 한 스키마만 남았다고 머리가 사라지면 지금 보는 것이 어디인지 알 수 없어진다.
- **AC-3** 검색은 테이블명·컬럼명에 더해 **스키마명**도 훑는다 — 범위를 켠 뒤 제일 먼저 하는 일이 "auth 것만 보기"인데, 못 훑으면 그러려고 범위를 껐다 켜야 한다.
- **AC-4** 상세 머리와 ERD 노드 머리는 스키마를 **이름 앞에 흐리게** 붙인다(`entity.card`). ERD 캔버스에 동명 노드가 함께 떠 있을 때 머리만 보고 갈릴 수 있어야 한다.
- **AC-5** FK 참조 표기는 **참조 대상의 스키마가 다를 때만** 접두어를 붙인다 — 같은 스키마면 시끄럽다.

### Section db-remote.scope.outside — 범위 밖 참조 (신설)
> 범위를 좁게 잡을수록 밖을 가리키는 FK 가 반드시 생긴다. 아무 표시도 안 하면 ERD 선이 허공에서
> 끊기고 상세의 참조 링크는 눌러도 아무 일이 없다 — 둘 다 "고장"으로 읽힌다.
> 정본: `remote/outsideRef.ts`.
- **AC-1** 밖 대상은 **컬럼 없는 이름 카드**로 그린다(ERD: 점선 테두리). 컬럼을 빈 칸으로라도 그리면 "컬럼이 없는 테이블"로 읽힌다 — 안 읽었으니 **모르는 것**이다.
- **AC-2** 종류를 **둘로** 가른다: `addable`(이 연결에서 고를 수 있는 스키마 — 켜면 들어온다) · `unavailable`(고를 수 있는 목록에 없다 — 권한이 없거나 사라졌다). 대처가 다르므로 같은 회색 카드로 뭉뚱그리지 않는다.
  > **왜 셋이 아니라 둘인가**(2026-07-30 실 DB 실측으로 계획 수정): ⑴ PostgreSQL 은 교차 database 참조가 문법 자체로 불가능하다(오류코드 `0A000` "cross-database references are not implemented") — FK 가 다른 카탈로그를 가리키는 일이 애초에 없다. ⑵ MySQL·MariaDB 의 교차 database FK 는 되지만 거기서 database 는 곧 스키마 자리라 `addable` 과 같은 것이다. ⑶ 다른 **서버**의 테이블은 FK 로 가리킬 수 없다 — 그건 참조가 아니라 그 서버에 붙는 **다른 연결**의 이야기다.
- **AC-3** 스키마 목록을 못 읽었으면 전부 `unavailable` 로 떨어뜨린다 — 켤 수 있다고 잘못 말하는 것보다 안전하다.
- **AC-4** `addable` 카드·칩은 **누르면 그 스키마를 범위에 더한다**(그리고 곧바로 다시 읽어 실물 노드로 바뀐다). 범위가 비어 있는 상태에서 더할 때는 지금 화면에 올라온 스키마들을 먼저 채운 뒤 더한다 — 안 그러면 보고 있던 것이 사라진다.
- **AC-5** 같은 곳을 가리키는 FK 가 여럿이면 **카드는 하나**, 그리로 오는 선만 여럿이다. 카드 순서는 대상 이름순 — 자동 배치가 실행마다 흔들리면 안 된다.
- **AC-6** 밖 카드는 배치를 저장하지 않고 그룹에도 안 들어간다(실물이 아니다). 끌어 옮기지도 못한다.
- **AC-7** FK 를 눌러 다른 테이블로 건너가면 화면 아래에 **"`<스키마.테이블>` 로 돌아가기"** 가 남는다. 사이드바에서 손으로 고른 것은 "건너온" 것이 아니므로 그 자리를 지운다. (설계부 Definition 의 `returnTo` 오버레이와 같은 규칙.)

> **진행(2026-07-30)**: 1단계(읽기)·2단계(범위 밖 표현) 완료. 남은 것 —
> 설계부 멀티 스키마와 DDL 스키마 한정(3단계), 편집·Migration(4단계).

## Surface: db-remote.data (Data 뷰)

### Section db-remote.data.table-list — 테이블/뷰 분리 목록 (이미지 #4)
- **AC-1** 사이드바가 일반 테이블과 뷰를 분리 렌더한다: 테이블 목록 위, `VIEWS` 섹션 아래.
- **AC-2** 각 테이블/뷰 행에 대략적 행수(또는 컬럼 수 대체값)를 우측에 표시한다.
- **AC-3** 뷰 행에는 `V` 텍스트 배지를 표시한다(이모지 금지). PK 없는 편집불가 테이블은 `읽기전용` 표시.
- **AC-4** 검색 필터로 이름 부분일치 필터링된다.

### Section db-remote.data.grid — 그리드 + 키 배지 + 타입 라벨 (이미지 #3)
- **AC-1** 컬럼 헤더에 제약 종류 배지를 텍스트로 표시한다: `PK`/`FK`/`UK`/`IDX`. FK 에 열쇠 아이콘을 쓰지 않는다.
- **AC-2** 컬럼명 아래에 데이터 타입 라벨(예: `char(36)`, `int`, `datetime`)을 표시한다.
- **AC-3** 헤더 클릭 정렬 3-state(ASC→DESC→해제), 정렬 방향을 화살표로 표시.
- **AC-4** 편집된 셀/행은 변경 하이라이트, 삭제행 취소선, 신규행 `NEW` 배지+초록 하이라이트.
- **AC-5** 긴 값(임계 초과)은 hover 시 전체값(상한 내) 툴팁을 보인다.
- **AC-6** 컬럼 폭은 **내용에 맞춰 자동**으로 잡는다 — 헤더(컬럼명·타입 라벨·키 배지)와 실제 값 중 가장 긴 것 기준, 최소·**최대 폭 상한** 안에서(`data/colWidth`). 상한을 넘는 값은 계속 잘리고 셀 도구(툴팁·복사·JSON 뷰어)로 전체를 본다.
- **AC-7** 사용자가 직접 끌어 조절한 컬럼은 그 폭이 자동 계산을 이긴다. 테이블을 바꾸면 조절값은 초기화된다.

### Section db-remote.data.cell-helpers — 값 생성 도우미 (이미지 #1·#2)
- **AC-1 (UUID)** uuid 종류 셀 편집 시 `UUID`(랜덤 식별값 생성)·`NULL` 칩 팝오버를 제공하고, `UUID` 클릭 시 유효한 UUID 를 채운다.
- **AC-2 (시간값)** date 종류 셀 편집 시 `YYYY-MM-DD HH:mm:ss[.SSS]` 입력 + `NOW`(현재시각, ms 포함)·`OK`(확정)·`ESC`(취소) 를 제공한다.
- **AC-3 (NULL)** 모든 편집 셀에서 NULL 토글이 가능하고 NULL 은 흐린 이탤릭으로 표시된다.
- **AC-4** boolean=select, json=뷰어/편집 모달, fk=참조 룩업 모달. FK 트리거는 텍스트 표기.

### Section db-remote.data.json-cell — JSON 값 보기 (신설)
> 정본 로직: `console/data/jsonCell.ts`. 셀 폭 안에서는 JSON 원문을 읽을 수 없다는 게 출발점.
- **AC-1** JSON 셀은 원문 대신 **구조 요약 칩**(객체 `{} 키수`, 배열 `[] 항목수`, 깨진 값 `!`)과 공백을 정리한 한 줄 미리보기를 보인다.
- **AC-2** 셀을 누르면 값 뷰어가 열린다. 열 때 **보기 좋게 정렬**해 보여주고, 제목에 사람 말 요약(`객체 · 키 5개`)을 쓴다.
- **AC-3** 뷰어는 형식이 정상인지/어디가 깨졌는지를 항상 보인다. `정렬`·`한 줄로`·`복사` 를 제공한다.
- **AC-4** 읽기 전용 테이블(뷰·PK 없는 테이블)에서도 뷰어가 열린다 — 이때는 입력이 막히고 적용 버튼이 없다.
- **AC-5** 적용할 때 유효한 JSON 은 한 줄로 정리해 넣는다(우리가 보여주려고 넣은 들여쓰기가 저장 값에 섞이지 않게). 깨진 값은 사용자가 쓴 그대로 둔다.

### Section db-remote.data.toolbar — 툴바 (필터·Export·컬럼가시성·타임존)
- **AC-1** 필터 바: 컬럼/연산자/값 다중 조건(AND), 추가·삭제·초기화·적용. (현행 유지)
- **AC-2** Export: CSV/JSON/SQL INSERT (현행 유지).
- **AC-3** 컬럼 표시/숨김 토글 팝오버(Show all/Hide all) 제공.
- **AC-4** 날짜 표시 모드 3-way 토글(UTC/LOCAL/TIMESTAMP), LOCAL 시 IANA 타임존 선택.
- **AC-5** 클립보드 복사: 셀값 복사 · 행 JSON 복사 · **현재 페이지 CSV 복사**(툴바) · 현재 페이지 JSON 복사(하단).
  CSV 는 **보이는 그대로** 뜬다 — 숨긴 컬럼은 빼고 날짜는 AC-4 의 표시 모드를 따른다. 스프레드시트에 붙여넣는
  용도라 파일 Export(원본 값·전체 컬럼)와 일부러 다르다. 행이 0이면 버튼은 꺼진다.
  같은 화면에 복사가 둘 이상이면 **라벨에 형식을 밝힌다**(`CSV 복사`·`JSON 복사`) — 그냥 "복사"면 뭘 뜨는지 모른다.
- **AC-6** 미저장 변경이 있을 때 테이블 전환 시 폐기 확인.

### Section db-remote.data.constraints-tab — Constraint 탭 (읽기 전용, 이미지 #5)
- **AC-1** 상단에 `Tables N` / `Constraints M` 탭. Constraints 탭 진입 시 활성 연결의 전 제약을 집계 목록으로 보인다.
- **AC-2** 종류 필터 칩: `ALL`/`PK`/`FK`/`UK`/`IDX`/`CHECK`, 각 개수 표시.
- **AC-3** 각 제약 항목: 종류 텍스트 배지 + 이름 + `테이블 · 컬럼` + FK 는 짧은 참조 표기(`→ users (id)`). 하단 표의 Reference 열은 정책까지 붙인 표기를 쓴다. 표기는 Definition 의 FK 표기 규칙과 같은 정본에서 나온다.
- **AC-4** 현재 선택 테이블의 제약을 하단 패널에 Type/Name/Columns/Reference 로 보인다.
- **AC-5** 읽기 전용 — 추가/삭제/수정 DDL 없음(후속 범위).

## Surface: db-remote.query (Query 뷰)

### Section db-remote.query.editor — 에디터 (파라미터화·자동저장·스키마 패널)
- **AC-1** CodeMirror + 방언 하이라이트 + 스키마 자동완성 + 포맷 + `⌘/Ctrl+↵` 실행. (현행 유지)
- **AC-2 (파라미터화)** `{{키워드}}` 를 추출해 실행 전 값 입력칸을 띄우고 치환한다. `'{{x}}'`(따옴표)는 리터럴로 두고 bare `{{x}}`만 치환. 미입력 시 실행 차단.
- **AC-3 (자동저장)** 라이브러리에 연결된 쿼리는 입력 멈춤 후 자동 저장(디바운스).
- **AC-4 (스키마 패널)** 테이블/컬럼 트리 + 검색 + `PK`/`FK` 텍스트 표기, 이름 클릭 시 에디터에 삽입, 테이블 클릭 시 미리보기.

### Section db-remote.query.execution — 실행 (라우팅 안전·EXPLAIN 트리)
- **AC-1** read/dml/ddl 분류 라우팅, DML 트랜잭션 게이트, destructive 경고, DDL 자동커밋 경고.
- **AC-2 (스크립트 안전 라우팅)** 에디터에 여러 문(`;` 구분)이 있으면 **첫 문이 아니라 전체 문**으로 성격을 판정한다.
  한 문장이라도 DML 이면 스크립트 전체를 트랜잭션 게이트로 보낸다 — 뒤에 숨은 DML 이 게이트를 우회해 자동 커밋되는 것을 막는다.
  (실행 자체의 다중 문 순차 처리는 main `queryService`(splitStatements)가 담당. 재사용/순서/항목별 제어가 필요한 다중 SQL 은 Collection 이 담당.)
- **AC-3 (EXPLAIN)** 실행계획을 재귀 트리로 렌더(접기/펼치기, 비용·행수 요약).

### Section db-remote.query.results — 결과 (export)
- **AC-1** 결과 그리드(행번호, NULL/객체/원시값 구분), 메타(행수·ms·affected). (현행 유지)
- **AC-2 (export)** 결과를 CSV/JSON 으로 내보낸다(Data 뷰 export 유틸 재사용).

### Section db-remote.query.history — 히스토리 강화
- **AC-1** 소스 필터(All/Query/Data/Collection) + 검색 + 항목 클릭 Re-run.
- **AC-2** 우측 슬라이드 드로어로 최근 실행을 빠르게 재실행.

## Surface: db-remote.collection (Collection 뷰)

### Section db-remote.collection.tree — 라이브러리 트리 (열기/실행·rename)
- **AC-1** 폴더/쿼리 계층 트리, 폴더 생성, DnD 재정렬(자기 자손 드롭 방지). (현행 유지)
- **AC-2 (열기/실행)** 트리의 저장 쿼리를 클릭/더블클릭하면 에디터로 로드하거나 실행한다(현행의 죽은 동선 해소).
- **AC-3 (rename)** 폴더/쿼리/컬렉션 이름 변경.

### Section db-remote.collection.items — 컬렉션 아이템 = 저장쿼리 참조
- **AC-1** 컬렉션 아이템은 SQL 사본이 아니라 라이브러리 쿼리를 **참조**한다.
- **AC-2** 참조 중인 쿼리를 삭제하려 하면 거부하고 참조 컬렉션을 알린다(삭제 가드).

### Section db-remote.collection.run-all — 실행 (전체/개별, 원자성)
- **AC-1 (전체 실행)** Run-All: 여러 쿼리를 한 트랜잭션에 순차 실행, 항목별 상태(pending/running/ok/error/skipped), 실패 시 이후 skip.
- **AC-2 (재시도)** 실패 지점부터 재시도(Retry).
- **AC-3 (중단)** 실행 중 Abort → 세션 롤백.
- **AC-4 (결과)** 각 SELECT 결과를 모달로 확인.
- **AC-5 (개별 실행·원자성)** 아이템을 하나씩 실행할 수 있다. 단, 개별 실행은 **개별 커밋하지 않고** 열린 트랜잭션에
  이어 붙는다(없으면 새로 연다) — 커밋/롤백 전까지 하나의 원자적 트랜잭션. 도중 한 문장이 실패하면 세션 전체가 롤백된다.

## 재설계(레거시 rky-mvp 구조 이식) — 갱신된 화면 구성

### Surface db-remote.query (재설계) — 저장쿼리를 "객체"로
- **AC-R1** 좌측 = 저장쿼리 **폴더/파일 트리**(검색·새폴더/새쿼리·우클릭 rename/move to/delete·DnD 재정렬).
- **AC-R2** 중앙 = 선택한 쿼리 편집기: 이름·설명 인라인 편집(자동저장) + SQL 편집기(Run/Format/EXPLAIN, {{키워드}}) + 결과 그리드.
- **AC-R3** 우측 = Schema 패널(토글, 기본 열림) — 테이블/뷰·컬럼(클릭 삽입·미리보기).

### Surface db-remote.collection (재설계) — 컬렉션 폴더 트리 + QUERIES 소스
- **AC-R1** 좌측 = 컬렉션 **폴더/파일 트리**(검색·새폴더/새컬렉션·rename·delete·DnD). (`collection_folders` + `collections.folder_id`)
- **AC-R2** 중앙 = 선택 컬렉션의 아이템 + Run-All/개별 실행(원자성) + 결과 모달.
- **AC-R3** 우측 = QUERIES(저장쿼리 트리) — 클릭해 컬렉션에 참조 추가.

### Surface db-remote.history (신설) — 다중 소스 실행 이력 (독립 뷰)
- **AC-1** Query/Data/Collection 실행을 `source` 로 구분해 기록(`query_history.source`). 커밋된 것만 기록(tx 게이트 경로).
- **AC-2** 독립 Remote 뷰(Query 하위 아님 — 소스가 셋이라). Time/Source/SQL/Rows/Speed/Status + 소스필터 + SQL 검색 + 페이지네이션.
- **AC-3** 행 클릭 시 SQL 을 Query 에디터로 보낸다. 이력 비우기.

### Surface db-remote.definition (신설) — 스키마 정의 브라우저·편집기
> 실 DB introspection 결과(`TableDef[]`)를 Design 의 Definition 화면 형태로 브라우징하고, 라이브 스키마를 **편집**한다.
> Diagram·Object 와 **같은 introspection 소스**를 공유하는 "역설계-조회/편집" 계열이며, nav 위치는 Remote 의 **첫 뷰**(Definition → Diagram → Data 순).
> 편집은 draft 에 쌓여 baseline↔draft diff 를 DDL 로 미리 보이고 tx 게이트로 적용한다(아래 edit 섹션).
> (Migration 은 버전 기반 반영 파이프라인으로 계속 공존한다 — Remote 직접 편집은 임의 DDL 을 이미 허용하는 Query 와 같은 성격.)

#### Section db-remote.definition.table-list — 테이블/뷰 목록 사이드바
- **AC-1** 활성 연결의 테이블·뷰를 이름순 목록으로 렌더하고, 각 행 우측에 컬럼 수를 표시한다. 뷰는 아이콘으로 구분(이모지 금지).
- **AC-2** 이름 또는 컬럼명 부분일치 검색 필터(대소문자 무시).
- **AC-3** 항목 클릭 시 활성 테이블을 전환한다. 기본 활성은 첫 테이블. 재조회로 스키마가 바뀌어 활성 id 가 사라지면 첫 테이블로 폴백. 편집 중이면 `+` 로 새 테이블을 추가한다.
- **AC-4** 목록은 **테이블 묶음과 뷰 묶음을 갈라** 각각 개수와 함께 섹션으로 보인다(Data 사이드바와 같은 구성). 해당 묶음이 비면 그 섹션 머리는 그리지 않는다.
- **AC-5** 이 목록은 화면마다 따로 그리지 않는다 — Definition(운영/설계)·Diagram 이 **같은 컴포넌트**(`db/TableListPanel`)와 같은 순수 로직(`db/tableList`)을 쓴다. 각 행에는 이름으로 집을 수 있는 `data-table-row` 훅이 있다(e2e 가 구조 대신 이 훅으로 행을 집는다 — 지우면 스모크가 깨진다).
- **AC-6** 사이드바는 이 목록을 `테이블` 탭으로 담고 `제약` 탭을 함께 둔다(`db/TableSidePanel`) — Data 사이드바와 같은 구성. 제약 탭의 규칙은 `db-design.definition.side-panel` 이 정본이다.

#### Section db-remote.definition.detail — 상세 (Table 뷰)
- **AC-1** 컬럼 그리드: `#`/`Name`/`Type`/`Keys`/`Null`/`Default`/`Comment`. 키는 서비스 공통 불변식대로 `PK`/`FK`/`UK`/`IDX` 텍스트 배지(복합키는 위치 표기), CHECK 참여 컬럼은 `CHK` 마커.
- **AC-2** 제약 목록: 종류 텍스트 배지 + 이름 + 참여 컬럼. FK 는 `→ ref테이블 (컬럼)` + **정책 칩 두 개**(아래 FK 표기 규칙), CHECK 는 식(expression) 표기.
- **AC-3** (읽기) FK 의 참조 테이블을 클릭하면 그 테이블로 점프한다(활성 전환 + Table 뷰).
- **AC-4** (편집) 인라인 편집 — 컬럼 추가/수정(이름·타입·NULL·기본값·코멘트)/삭제/이동, 키 토글(PK/UK/IDX), 제약 추가·수정·삭제(FK 참조·**ON DELETE 와 ON UPDATE 둘 다**, CHECK 식), 테이블 이름·코멘트·삭제.

##### FK 표기 규칙 (설계부·운영부 공통 불변식)
> 정본: `workspaces/definition/fkPolicy.ts` + `FkPolicyChips.tsx`. 새 화면에서 FK 를 그릴 때 직접 문자열을 만들지 않는다.
- **AC-F1** 참조 대상은 `테이블 (컬럼[, 컬럼])` 한 형태로만 쓴다(`users.id` 식 축약 금지).
- **AC-F2** `ON DELETE` 와 `ON UPDATE` 를 **항상 둘 다** 보인다. 한쪽만 그리면 "제약이 없다"는 오독을 부른다.
- **AC-F3** 값이 없으면 DB 가 실제로 적용하는 `NO ACTION` 을 채워 보이되 흐리게 그리고, 마우스를 올리면 그 정책이 무슨 뜻인지 쉬운 말로 알려 준다. (설계부가 미지정을 `RESTRICT` 로 보이던 표기는 DDL 생성 결과와 어긋나 폐기 — `ddl.ts` 는 값이 없으면 절 자체를 안 쓴다.)
- **AC-F4** 좁은 목록(Data 제약 목록 등)은 참조만 쓴 짧은 표기를, 폭이 있는 표는 정책까지 붙인 표기를 쓴다 — 둘 다 같은 정본 함수(`fkRefText`)에서 나온다.

#### Section db-remote.definition.sql — SQL(DDL) 뷰
- **AC-1** `[Table|SQL]` 표현 토글(읽기 모드). SQL 뷰는 활성 테이블을 **연결 방언**으로 생성한 `CREATE TABLE` DDL 을 구문 강조로 렌더한다(`generateDdl`, Design Definition 과 동일 하이라이터 공유).
- **AC-2** 연결 방언 배지를 표시한다(방언은 선택지가 아니라 연결의 고정 속성). `Copy` 로 DDL 을 클립보드에 복사.
- **AC-3** 카드 본체는 설계부와 **같은 컴포넌트**(`workspaces/definition/SqlCard`)다 — 범위 토글·구문 강조·`Copy`·`저장`이 두 부서에서 같게 동작한다. 규칙은 `db-design.definition.sql` 이 정본이며, 운영부는 여기에 **연결 이름**을 전체 스크립트의 파일 이름으로 넘긴다(`oh-my-pokemon.sql`).

#### Section db-remote.definition.edit — 편집 적용 파이프라인 (신설)
- **AC-1** `편집` 진입 시 현재 introspection 을 baseline 으로 스냅샷하고 draft 를 연다(연결 단위, Diagram 과 공유). 편집은 draft 에만 쌓인다.
- **AC-2** 하단 미리보기 바가 baseline↔draft diff(`generateMigration`)로 생성될 `ALTER/CREATE/DROP` DDL 과 대기 변경 수를 보인다(구문 강조, 펼침).
- **AC-3** 파괴적 문(DROP·이름변경 등)은 개수를 경고하고 적용 전 확인을 받는다. MySQL/MariaDB 는 DDL 자동 커밋이라 별도 경고.
- **AC-4** `적용` 은 tx 게이트(`query.txBegin→txExec→txCommit`)로 실행하고 실패 시 롤백한다. 성공 시 재역설계 후 편집을 종료한다. `버리기` 는 draft 를 버린다.
- **AC-5** sqlite 등에서 자동 생성 불가한 변경(컬럼/제약 정의 변경)은 `unsupported` 로 미리보기에 표시한다(수동 처리 안내).

#### 공통
- **AC-1** 미접속 시 "연결을 선택하세요" 안내 화면(placeholder)을 보인다.
- **AC-2** `새로고침` 으로 활성 연결을 재역설계한다(Diagram·Object 와 캐시 공유).

### Surface db-remote.diagram.table-panel — ERD 좌측 사이드 패널 (신설)
> Data 사이드바와 같은 구성의 패널을 ERD 왼쪽에 둔다 — 노드가 많으면 캔버스에서 테이블을 눈으로 찾기 어렵다.
> 설계부(Design › Diagram)·운영부(Remote › Diagram 읽기/편집) 셋 다 **같은 컴포넌트**(`console/diagram/DiagramTablePanel` → `db/TableSidePanel`)를 쓴다.
- **AC-1** 좌측 패널에 `테이블`/`제약` 두 탭을 보인다. `테이블` 탭은 테이블/뷰를 갈라 목록으로 보인다(Definition·Data 와 같은 공용 패널·같은 규칙 — `db-design.definition.side-panel`).
- **AC-2** 항목을 누르면 그 노드를 선택하고 **캔버스를 그 노드로 옮긴다**(부드럽게 이동, 과확대 방지 상한). 선택 상태는 캔버스 클릭과 공유한다.
- **AC-3** 필터(`관계만`)로 캔버스에서 빠진 테이블은 목록에서도 빠진다 — 눌러도 갈 곳이 없는 항목을 보이지 않기 위해 선택·필터 상태를 캔버스와 같은 곳에서 든다.
- **AC-4** `제약` 탭의 항목을 누르면 그 제약이 걸린 테이블 노드로 캔버스가 이동한다(AC-2 와 같은 이동).

### Surface db-remote.diagram — ERD 캔버스 공통(배치·그룹·상세보기) (신설)
> 세 ERD 캔버스가 **같은 시각 레이어**를 쓴다: Design › Diagram(가상 ERD) · Remote › Diagram(읽기) · Remote › Diagram(편집).
> 아래 배치·그룹·상세보기 규칙은 **셋 모두의 정본**이다(`db-design.diagram` 은 이 절을 가리킨다).
> 다른 것은 저장 스코프뿐: **Remote 는 연결(Connection)별, Design 은 설계별**.

#### Section db-remote.diagram.layout — 배치 영속
- **AC-1** 노드 위치와 화면 위치(뷰포트)를 스코프별로 영속한다. 스코프 키는 Remote = 연결 id, Design = `design:<설계 id>`. 노드 키는 이름 기반 결정적 id(`t:<테이블명>`)라 재역설계 뒤에도 짝이 맞는다.
- **AC-2** **화면을 떠나도 저장이 유실되지 않는다.** 지연 저장(디바운스)이 걸려 있는 동안 화면이 사라지면 떠나기 전에 마저 저장한다 — 취소하지 않는다. (회귀: 캔버스를 옮긴 직후 다른 화면으로 갔다 오면 배치가 초기화되던 문제.)
- **AC-3** **안 보이는 테이블의 위치를 지우지 않는다.** 저장은 지금 보이는 노드의 위치를 이미 저장된 위치 **위에 얹는다**(통째 덮어쓰기 금지) — `관계만`·`그룹만 보기` 로 숨은 테이블의 배치를 지키기 위해서다.
- **AC-4** `자동 배치` 는 저장된 배치를 지우고 자동 배치(dagre)로 되돌린다. 이때 **그룹은 지우지 않는다** — 소속은 위치와 무관한 명시 멤버십이다.
- **AC-4a** 자동 배치는 **그룹을 흩어 놓지 않는다** — 같은 그룹 테이블끼리 붙여 놓는다(dagre 묶음). 그룹이 하나도 없으면 예전과 **완전히 같은** 배치가 나온다(그룹 기능이 기존 화면을 바꾸지 않는다).
- **AC-5** 저장된 화면 위치가 없으면 전체가 보이도록 맞춘다. 새 테이블이 나타나면 그 테이블만 자동 배치 자리에 채우고 나머지는 사용자 배치를 유지한다.
- **AC-5a** 화면에서 빠졌다 **다시 나타나는** 테이블(접힌 그룹을 펼 때, `관계만`·`그룹만 보기` 를 끌 때)은 **저장된 자리로 돌아온다** — 자동 배치 자리로 튀지 않는다. 자리 우선순위는 `화면 > 저장본 > 자동 배치` 다.

#### Section db-remote.diagram.group — 그룹(레이어)
- **AC-1** 그룹은 **이름과 색을 가진 영역**으로 캔버스에 그려진다. 테이블·관계선보다 **뒤에** 그려 내용을 가리지 않는다.
- **AC-2** 그룹의 **이름표를 끌면 소속 테이블이 같은 거리만큼 함께 움직인다.** 소속 테이블은 그 안에서 개별로도 움직인다(둘 다 된다). 영역 **안쪽은 클릭·드래그를 캔버스로 통과**시킨다 — 영역 전체가 손잡이면 큰 그룹이 화면을 덮었을 때 캔버스를 옮길 수도, 빈 곳을 눌러 선택을 풀 수도 없다.
- **AC-3** 소속은 **명시 멤버십으로 저장**한다 — 위치로 추정하지 않는다. 테이블을 그룹 영역 안에 끌어다 놓으면 소속이 되고 밖으로 끌어내면 빠진다. 왼쪽 패널에서도 넣고 뺄 수 있으며 **같은 멤버십**을 건드린다. (위치로 추정하면 `자동 배치` 한 번에 묶음이 흩어진다.)
- **AC-4** 그룹은 **접을 수 있다.** 접으면 소속 테이블 노드는 숨고 그룹 상자만 남는다. 접힌 그룹을 드나드는 관계선은 그룹 상자에 모아 그린다 — 관계가 사라진 것처럼 보이면 안 된다.
- **AC-5** 그룹 색은 고를 수 있고, 안 고르면 순서대로 자동 배정한다. 화이트 테마 위에서 안의 테이블 글자를 읽을 수 있는 **옅은 채움**만 쓴다.
- **AC-6** 영역 크기는 기본적으로 소속 테이블을 여백과 함께 감싸도록 **자동 계산**한다. 빈 그룹도 테이블을 끌어다 놓을 수 있게 최소 크기를 유지한다.
- **AC-6a** 상자는 **손으로 크기를 조절할 수 있다** — 잡는 곳은 **모서리 손잡이만**이다. 변(edge) 전체를 잡히게 하면 투명한 띠가 상자 가장자리에 걸친 테이블의 클릭을 가로챈다(실측 회귀). 한 번 조절하면 그 크기와 자리를 지키고 소속을 옮겨도 자동으로 안 변한다 — 사람이 정한 크기를 앱이 되돌리면 조절이 무의미하다. 다시 자동으로 맡기려면 패널의 `자동 크기` 를 누른다. 접힌 상자는 이름표 한 장 크기가 고정이라 조절 대상이 아니고, 손으로 정한 크기도 최소 크기 아래로는 안 내려간다.
- **AC-7** 그룹 정보(이름·색·멤버십·접힘)는 배치와 **같은 스코프에 함께** 영속한다.
- **AC-8** 그룹이 하나도 없으면 화면은 지금과 똑같다 — 그룹 기능이 기본 화면을 바꾸지 않는다.

#### Section db-remote.diagram.group-panel — 왼쪽 패널 그룹 UI
- **AC-1** 좌측 사이드 패널에 `그룹` 탭을 더한다(`테이블·뷰`·`제약` 과 나란히). 그룹별 소속 테이블을 접이식 목록으로 보인다. 어디에도 안 속한 테이블은 `그룹 없음` 묶음에 남는다.
- **AC-2** 그룹 만들기·이름 바꾸기·색 고르기·지우기를 여기서 한다. **그룹을 지워도 테이블은 지워지지 않는다** — 묶음만 풀린다.
- **AC-2a** 지우기는 **확인 창(Dialog)** 을 띄운다. 창은 그룹 이름과 **소속 테이블 목록·개수**를 보이고, "묶음만 풀리고 테이블은 남는다"를 분명히 말한다. 되돌리기가 없어서 모아 둔 소속 목록이 오클릭 한 번에 날아가기 때문이다. 앱 안의 Dialog 를 쓰고 **시스템(브라우저) 확인 창은 쓰지 않는다** — 그건 이 Electron 창에서 자동 검사를 멈춰 세운다(`AGENTS.md` 앱 구동 e2e 함정).
- **AC-2b** **소속 테이블까지 지우는 선택지는 설계부(Design)에만 있다.** 운영부(Remote)의 확인 창에는 `그룹만 지우기` 뿐이다 — 거기 테이블은 실 DB 객체라, 지우는 길은 편집 모드의 대기 변경 → DDL 미리보기 → 트랜잭션 게이트 하나여야 한다(그룹 패널이 우회로가 되면 안 된다).
- **AC-2c** 설계부에서 `테이블도 함께 지우기` 를 고르면 **한 단계를 더** 거친다: 사라질 테이블 목록을 보이고, 확인 문구 **`{N}개 테이블도 함께 삭제합니다`** 를 사람이 그대로 입력해야 지우기 버튼이 열린다(앞뒤 공백만 눈감아 준다). 버튼 한 번으로 테이블 여러 개가 사라지면 안 되고, 몇 개가 사라지는지를 손으로 쓰게 해야 실제로 읽는다. 이 삭제는 **설계에서만** 일어난다 — 실 DB 반영은 Migration 몫이다.
- **AC-3** 그룹의 테이블 항목을 누르면 캔버스가 그 노드로 이동한다(`db-remote.diagram.table-panel` AC-2 와 같은 이동).
- **AC-4** **그룹만 보기** — 켠 그룹의 소속 테이블만 캔버스에 남긴다. `관계만` 필터와 함께 걸린다(둘 다 켜면 둘 다 적용).
- **AC-5** 접기 토글은 패널에도 있고, 캔버스의 접힘과 **같은 상태**다.

#### Section db-remote.diagram.detail — 상세보기 서랍
- **AC-1** 캔버스에서 테이블을 고르면 **캔버스 아래 서랍**에 그 테이블 상세가 뜬다. 접고 펼 수 있고, 접으면 캔버스가 온전히 돌아온다. 아무것도 안 고른 상태의 기본은 닫힘이다.
- **AC-2** 서랍 내용은 **Definition 화면을 그대로 쓴다 — 따로 만들지 않는다.** 읽기(Remote)는 `TableDetail`, 라이브 편집(Remote › Diagram 편집)은 `EditableTableDetail`, 설계(Design)는 `TableForm`. Definition 에서 되는 편집은 여기서도 그대로 된다(컬럼 추가·수정·삭제, 키 토글, 제약 편집 — `db-remote.definition.detail` AC-1~4 가 그대로 적용된다).
- **AC-3** `[Table|SQL]` 토글로 DDL 원문을 보이고 복사한다 — Definition SQL 뷰와 **같은 컴포넌트·같은 방언 규칙**(`db-remote.definition.sql`).
- **AC-4** 상세의 FK 참조 테이블을 누르면 **캔버스가 그 테이블로 이동**하고 서랍도 그 테이블로 바뀐다 — Definition 의 "점프"가 다이어그램에서는 화면 이동이 된다.
- **AC-5** 서랍의 `크게 보기` 는 **같은 내용**을 모달로 연다. 좁은 서랍에서 다 못 보는 경우를 위한 확대이지 다른 화면이 아니다.

### Surface db-remote.diagram (편집) — ERD 캔버스 편집 (신설)
> Remote › Diagram 을 편집 가능하게. Definition 과 **같은 연결 단위 편집 스토어·적용 파이프라인**(baseline↔draft diff → DDL 미리보기 → tx 게이트 → 재역설계)을 공유하며, 캔버스가 편집 표면이 된다. 시각 레이어(노드/엣지/배치)는 읽기 Diagram·Design ERD 와 공유.
- **AC-1** `편집` 진입 시 draft 를 편집 가능한 ERD 로 렌더한다(모든 컬럼에 관계 핸들 개방, 노드 드래그 가능).
- **AC-2** 노드 클릭 시 사이드 편집 패널 — 테이블 이름·삭제, 컬럼 추가/이름·타입 편집/NULL 토글/PK 토글/삭제, FK 목록·삭제.
- **AC-3** 컬럼의 오른쪽 핸들을 다른 테이블로 끌면 FK 를 만든다(참조 컬럼 기본값 = 대상 PK, `buildFkPatch`).
- **AC-4** 캔버스 상단 `테이블` 로 새 테이블 추가, 검색·간략 토글 제공. 노드 위치는 연결 단위로 영속(읽기 Diagram 과 공유).
- **AC-5** 하단 미리보기 바(db-remote.definition.edit 와 동일)로 대기 변경·DDL·파괴적 경고를 보이고 tx 게이트로 적용한다.
