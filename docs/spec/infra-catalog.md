# Service: infra-catalog (노드 종류 카탈로그 · 탐침 · 공급자 연결)

> Infra 서비스가 **무엇을 알고 있는가**를 담는 화면 명세 정본.
> 위계: Service > Surface > Section > Component. ID 는 코드·테스트와 기계 대조용 안정 키.
> 짝 문서: `docs/spec/infra-architecture.md`(무엇을 그리고 대조하는가) · 테스트 정의 `docs/qa/infra-catalog.md`.
> 코드: `src/renderer/src/services/infra/catalog/` · `src/main/ipc/infra/` · `src/main/store/migrations/infra.ts`.

## 이 서비스가 푸는 문제
Rockury 는 인프라를 **구축하지 않는다**(→ architecture 문서 공통 불변식). 대신 "무엇이 어떤 종류이고,
그것을 어떻게 읽어 오는가"를 **데이터로** 들고 있어야 한다. 그래야 지원 안 하는 클라우드(사내 시스템,
KT Cloud, NCP 등)를 사용자가 직접 알려 줄 수 있고, GCP·Azure 추가가 코드가 아니라 파일 추가로 끝난다.

**노드 타입 = 모양 + 탐침 + 액션.** 셋이 다 있어야 노드인 게 아니다 — **모양만 있어도 노드다.**

| 층 | 모양 | 탐침 | 액션 | 예 |
|---|---|---|---|---|
| 내장 공급자 카탈로그 | ✅ | ✅ | ✅ | AWS EC2, 도커 컨테이너 |
| 사용자 카탈로그 | ✅ | ✅(사용자가 정의) | 선택 | 사내 쿠버네티스, KT Cloud |
| 노드 프리셋 | ✅ | ❌ | ❌ | 그라파나, 프로메테우스 |
| 맨 노드 | 기본 모양 | ❌ | ❌ | 이름만 있는 박스 |

## 공통 불변식
- **자격증명 값은 카탈로그 파일에 절대 들어가지 않는다.** 참조(`{{cred.<id>}}`)만 허용하고, 값처럼 생긴 것이
  들어오면 형식 검증이 거부한다. 실제 값은 OS 키체인(`src/main/infra/crypto.ts`).
- **카탈로그에 없는 종류는 떨어뜨리지 않는다.** 실물에서 모르는 종류가 나오면 '미상' 노드로 그린다.
  조용히 빼면 지도가 거짓말을 한다.
- **상태 사전에 없는 값은 '정상'이 아니라 '모름'이다.** 원본 문자열을 함께 보인다.
- **명령은 셸을 거치지 않는다.** 인자 배열로 넘긴다(치환값이 명령의 일부로 실행되는 길을 없앤다).
- **표현식은 코드가 아니다.** 뽑기 표현식이 임의 코드를 실행할 수 있으면 가져온 카탈로그가 곧 구멍이다.

## Surface: infra-catalog.registry (카탈로그 목록)

### Section infra-catalog.registry.sources — 출처 구분
- **AC-1** 카탈로그는 출처 세 가지로 갈려 표시된다: `내장` · `내가 만듦` · `가져옴`.
- **AC-2** 각 항목은 공급자 이름 · `catalogVersion` · 노드 종류 수를 보인다.
- **AC-3** 내장 카탈로그는 편집할 수 없다. 고치려면 **복제**해서 `내가 만듦` 으로 만든다.
- **AC-4** 앱이 아는 것보다 높은 `schemaVersion` 파일은 **읽지 않고 거부**하고 이유를 보인다.
  일부만 적재해 반쯤 동작하는 상태를 만들지 않는다.

### Section infra-catalog.registry.import — 가져오기 (신뢰 경계)
- **AC-1** 저장 전에 그 파일이 **실행하게 될 모든 명령을 목록으로** 보인다(노드 종류 · 명령줄 · 호출 방식).
- **AC-2** 명시적 승인 없이는 저장하지 않는다. 승인 시각을 기록한다.
- **AC-3** 형식 검증 실패 시 **어느 필드가 왜** 틀렸는지 보인다. 부분 저장 금지(전부 들어가거나 전부 안 들어간다).
- **AC-4** 가져온 카탈로그에서 나온 노드는 상세에서 출처가 계속 `가져옴` 으로 보인다.

### Section infra-catalog.registry.export — 내보내기
- **AC-1** 내보낸 파일에 자격증명 값이 포함되지 않는다(참조만). 내보내기 직전 기계 검사로 강제한다.
- **AC-2** 내보내기 단위는 카탈로그 하나. 사용자 프리셋도 같은 형식으로 내보내진다.

### Section infra-catalog.registry.data — 저장 모델
- **AC-1** `infra_catalogs(id, source, provider_id, schema_version, catalog_version, body, imported_at, approved_at)`.
  `body` 는 검증을 통과한 원문 JSON.
- **AC-2** `provider_id` 는 카탈로그끼리 겹칠 수 있다(내장 aws 를 복제해 고친 사용자 aws). 목록에서 출처로 가른다.

## Surface: infra-catalog.types (노드 종류)

### Section infra-catalog.types.definition — 종류 정의(모양)
- **AC-1** 종류는 `id` · 표시 이름 · 아이콘 · 색 · `canNestIn`(무엇 안에 들어갈 수 있나) ·
  `canLinkTo`(무엇과 이을 수 있나) · 기본 문서 틀을 갖는다.
- **AC-2** `canNestIn`/`canLinkTo`/`canContain` 이 **실재하지 않는 종류**를 가리키면 형식 검증에서
  실패한다(그림이 조용히 깨지는 것을 배포 전에 잡는다). `canContain` 의 `"*"` 는 예외다.
- **AC-3** 탐침이 없는 종류도 유효하다 — 그게 프리셋이다.
- **AC-4** 종류 목록 화면은 카탈로그·프리셋을 한 목록에서 검색·필터할 수 있다(설계 캔버스가 여기서 고른다).
- **AC-5** **부모 쪽 허가 `canContain`.** 자식의 `canNestIn` 만으로는 *묶음 상자·서버·쿠버네티스*처럼
  "아무거나 담는" 종류를 표현할 수 없다 — 세상의 모든 자식이 자기를 등재하게 만들 수 없기 때문이다.
  부모가 `canContain: ["*"]`(또는 특정 종류 목록)로 허가하면 그것이 자식 규칙보다 **먼저** 본다.
  (2026-07 실제 프리셋을 쓰다 드러난 구멍 — 그전에는 묶음 상자가 아무것도 못 담았다.)

### Section infra-catalog.types.presets — 노드 프리셋
- **AC-1** 프리셋은 모양만 담는다: 라벨 · 아이콘 · 색 · 기본 포트 · 기본 문서 틀 · 바깥 링크 틀.
- **AC-2** 내장 프리셋 첫 묶음 — 관측(그라파나 · 프로메테우스 · 로키 · Jaeger) · 미들웨어(Redis · Kafka ·
  RabbitMQ · MQTT) · 게이트웨이(Nginx · Traefik · Kong) · 실행(도커 · 쿠버네티스 · PM2) ·
  CI(GitHub Actions · Jenkins).
- **AC-3** 사용자가 자기 프리셋을 만들어 저장·내보내기 할 수 있다(사내 시스템 이름들).
  `노드 종류` 화면의 **새 프리셋** — 탐침 없이 id·이름·아이콘만으로 만든다.
  종류 id 에는 영문·숫자와 `. _ -` 만 허용한다: 이 값이 표현식·저장 키·설계 노드의 참조로
  쓰이므로 공백이 섞이면 그 전부가 흔들린다.
- **AC-4** **승격** — 프리셋에 탐침을 붙여 사용자 카탈로그 종류로 올릴 수 있다.
  승격해도 **이미 그려 둔 설계 노드는 그대로 유지된다**(종류 id 가 이어진다).
  그래서 승격 중에는 **종류 id 칸을 잠근다** — 바꾸면 그 노드들이 전부 '알 수 없는 종류'로 떨어진다.
  모양(아이콘·색·담길 곳·문서 틀)도 그대로 따라온다: 승격이 '새로 그리기'가 되면 안 된다.
  화면 이동은 사용자가 한다(공용 nav 를 건드리지 않는다) — 그 사이는 승격 안내 띠가 잇는다.

### Section infra-catalog.types.icons — 아이콘
- **AC-1** 아이콘 참조는 **문자열 하나**다: `phosphor:<이름>` · `pack:<팩>/<이름>` · `data:image/svg+xml;…`.
  카탈로그·프리셋·사용자 정의가 전부 같은 문법을 쓴다.
- **AC-2** 모르는 접두어나 없는 이름이면 **기본 아이콘으로 떨어지고 경고를 남긴다** — 그림이 깨지지 않는다.
- **AC-3** 공식 클라우드 아이콘(AWS·Azure·GCP)은 **앱에 내장하지 않는다.** 사용자가 직접 넣는
  아이콘 팩으로만 쓴다 — 상표·재배포 조건을 우회가 아니라 정면으로 피한다.
- **AC-4** 빌드 시 카탈로그·프리셋을 훑어 **실제 쓰이는 아이콘만** 묶는다. 아이콘 세트 전체가 번들에
  들어가면 안 된다(이름이 문자열이라 자동 정리가 안 되는 것을 생성 단계로 푼다).
- **AC-5** 앱 껍데기(좌측 레일 · 버튼)의 아이콘은 기존 `lucide` 를 그대로 쓴다. phosphor 는 **다이어그램
  노드 아이콘 전용**이다 — 공용 `nav/types.ts`(`LucideIcon`)를 건드리지 않는다.

## Surface: infra-catalog.probe (탐침 — 어떻게 읽어 오나)

> **탐침(= 밖을 찔러 보고 결과를 읽어 오는 정의).** 사용자가 Rockury 에게 "이 클라우드는 이렇게 파악해라"
> 를 알려 주는 수단이다.

### Section infra-catalog.probe.shape — 탐침의 모양
- **AC-1** 탐침은 언제나 3단이다: **호출한다 → 뽑는다 → 옮긴다.**
- **AC-2** 호출 방식 3종 — `cli`(명령 이름 + **인자 배열**) · `http`(URL·메서드·헤더) ·
  `builtin`(도커 소켓 · Redis 접속처럼 JSON 으로 못 적는 내장 어댑터).
- **AC-3** 뽑기 표현식은 접두어를 갖는다(`jmespath:…`). 접두어가 없으면 JMESPath 로 읽는다(기본값).
  접두어 구조 덕에 나중에 다른 문법을 더해도 카탈로그 형식이 안 깨진다.
- **AC-4** 옮기기 필드 — `externalId`(필수) · `name` · `status` · `parentExternalId` · `designNodeRef`.
  `parentExternalId` 가 중첩 박스를, `designNodeRef` 가 설계본 매칭(→ architecture 문서)을 만든다.
- **AC-5** `statusMap` 은 원본 상태 문자열을 `정상 | 주의 | 멈춤 | 없어짐` 중 하나로 옮긴다.
  **사전에 없는 값은 `모름`** 이고 원본 문자열을 함께 보인다.
- **AC-6** 표현식 평가는 임의 코드를 실행하지 않는다 — 코드 평가 경로가 존재하지 않아야 한다.
- **AC-7** **응답 형식**을 선언한다 — `json`(기본, 통짜 JSON 하나) 또는 `ndjson`(**줄마다 JSON 하나**).
  도커가 `ndjson` 으로 뱉는다(`docker ps --format {{json .}}`). 통짜로 읽으면 첫 줄 뒤에서 문법 오류가 나
  "출력이 JSON 이 아니다"로 잘못 보고된다. `ndjson` 은 줄들을 배열로 묶으므로 목록 표현식이 `[]` 가 된다.
- **AC-8** **`{{…}}` 는 우리만 쓰는 문법이 아니다.** `cred` · `node` · `arg` 세 이름공간만 우리 것이고,
  그 밖의 것(도커·kubectl 의 출력 서식 `{{json .Names}}`)은 **손대지 않고 그대로 흘려보낸다.**
  우리 이름공간인데 값이 없으면 반드시 던진다 — "조용한 통과"는 여기서 생기지 않는다.
  (2026-07 도커 카탈로그를 쓰다 드러남 — 그전에는 정상 도커 명령을 카탈로그에 적을 수 없었다.)

### Section infra-catalog.probe.editor — 탐침 편집 (돌려보고 집기)
> 이 섹션이 빠지면 "지원 안 하는 클라우드" 요구가 통째로 죽는다. **M1 필수** — 구현 완료.

- **AC-1** 명령을 입력하고 실행하면 **원본 출력을 그대로 펼쳐** 보인다(JSON 은 접었다 펴는 트리로).
- **AC-2** 출력에서 `목록` · `id` · `이름` · `상태` · `부모` · `설계 매칭` 을 **클릭으로 집으면
  표현식이 자동으로 채워진다.** 사용자는 문법을 몰라도 된다.
- **AC-3** 미리보기 — 지금 정의로 노드가 **몇 개** 뽑히는지, 상태 색이 어떻게 칠해지는지 즉시 보인다.
  `모름` 으로 떨어진 상태값이 있으면 그 목록을 따로 보인다(사전에 추가하라는 신호).
- **AC-4** 표현식을 손으로 고칠 수 있다 — 클릭으로 못 집는 경우(배열 속 조건부 값 등)의 탈출구.
- **AC-5** 명령이 실패하면(없는 명령 · 권한 없음 · 시간 초과) **종료 코드와 표준 오류를 그대로** 보인다.
  삼키고 "실패했습니다"로 뭉개지 않는다.
- **AC-6** 저장하면 `내가 만듦` 카탈로그의 노드 종류로 들어간다. 대상 카탈로그를 고르거나 **새로 만든다**.
  같은 종류 id 면 **자리를 지키며** 덮어쓴다 — 뒤로 밀면 저장할 때마다 목록 순서가 흔들려
  사용자가 자기 카탈로그를 못 알아본다.
- **AC-7** 응답 형식(`json`/`ndjson`)을 화면에서 고른다 — 도커를 붙이려면 필수다(probe.shape AC-7).

### Section infra-catalog.probe.execution — 실행 규칙
- **AC-1** 셸을 거치지 않는다. `{{cred.*}}` · `{{node.*}}` 치환은 **인자 배열의 한 칸 안에서만** 일어난다
  (치환값에 공백·따옴표·세미콜론이 있어도 인자가 쪼개지지 않는다).
- **AC-2** 실행에 시간 제한이 있고, 넘으면 중단하고 **시간 초과로 표시**한다(성공으로 넘어가지 않는다).
- **AC-3** 실행 이력을 남긴다 — 언제 · 어느 공급자 · 어떤 명령 · 성공 여부 · 소요 시간.
  **자격증명 값은 이력에 남기지 않는다**(치환 전 형태로 기록).

## Surface: infra-catalog.providers (공급자 연결)

### Section infra-catalog.providers.credentials — 자격증명
- **AC-1** 입력칸은 **카탈로그가 선언한 슬롯대로 자동 생성**된다(예: AWS = 프로필 이름, Vercel = 토큰).
- **AC-2** 값은 OS 키체인으로 암호화해 저장한다(`src/main/infra/crypto.ts`). **평문은 로컬 DB 에 안 들어간다.**
- **AC-3** 화면 · 실행 이력 · 내보내기 어디에도 평문이 나오지 않는다.
- **AC-6** **상대가 되뱉은 자격증명도 막는다.** 우리가 만드는 문자열에서 비밀을 빼는 것만으로는
  부족하다 — **공급자가 자기 오류 메시지에 값을 실어 돌려보내는 길**이 있다
  (실측: AWS CLI 는 `The config profile (<값>) could not be found` 라고 답한다).
  그래서 표준 출력·표준 오류·실행 오류를 **프로세스 경계를 넘기 전에**(메인에서) 훑어
  자격증명 값을 참조 표기(`{{cred.<id>}}`)로 바꾼다. **가리되 자리는 남긴다** —
  통째로 지우면 무엇이 틀렸는지 못 읽고, 그대로 두면 비밀이 샌다.
  (2026-07-29 연결 시험을 붙이다 e2e 가 실제로 잡아냈다.)
- **AC-4** `연결 시험` — 탐침 하나를 실제로 돌려 성공/실패를 보인다. 실패하면 원문 오류를 그대로
  (AC-6 의 가리기를 거친 뒤). **명령이 돌았다고 끝이 아니다** — 그 응답을 우리가 **읽어낼 수 있어야**
  연결된 것이므로, 뽑기까지 태워 "○○ N건을 읽었습니다"로 답한다.
  시험에 쓸 탐침은 **지금 실제로 돌릴 수 있는 것**(cli)만 고른다 — 아직 못 돌리는 방식을 고르면
  눌러도 안 되는 버튼이 된다.
- **AC-5** 이 연결을 **읽기 전용으로 표시**할 수 있다. 표시하면 `danger` 액션 버튼이 잠긴다.
  화면에 한 줄로 알린다 — **권한의 진짜 통제는 클라우드 쪽 권한 설정(IAM)이고 이 표시는 보조선이다.**

### Section infra-catalog.providers.data — 저장 모델
- **AC-1** `infra_providers(id, catalog_id, name, cred_encrypted, read_only, created_at, updated_at)`.
- **AC-2** 공급자 연결을 지우면 그 연결로 읽어 온 실물 스냅샷도 같이 지운다.
  **설계본은 건드리지 않는다**(설계는 실물과 독립).

### Section infra-catalog.actions.definition — 액션 정의
- **AC-1** 액션은 카탈로그가 정의한다 — `id` · 라벨 · 호출(탐침과 같은 3종) · `danger` · 인자 스키마.

## Section infra-catalog.mcp — MCP 등재 (절대 불변식 4)
- **AC-1** `infra:*` 채널은 전부 `src/main/ai/coverage/infra.ts` 에 노출 또는 제외로 등재한다.
- **AC-5** 도구 정의는 **서비스마다 자기 파일**(`src/main/ai/tools/<서비스>.ts`)에 두고, 공용 `tools.ts` 는
  그 배열을 이어 붙이기만 한다 — `coverage`·`migrations`·`preload` 와 같은 분할이다.
  다섯 서비스가 도구를 더할 때 같은 줄을 놓고 부딪히지 않는다.
- **AC-2** **액션 실행 채널(`infra:runAction`)과 탐침 임의 실행 채널(`infra:runProbe`)은 제외로 등재**한다.
  사유: 에이전트가 실물을 조작하거나 임의 명령을 돌리는 문을 열지 않는다. 읽기 채널만 노출한다.
- **AC-3** 자격증명을 다루는 채널(`infra:setCredential` 등)도 제외. 사유: 비밀값 취급 경로.
