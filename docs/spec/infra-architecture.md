# Service: infra-architecture (설계본 · 노드 문서 · 실물 지도 · 대조)

> Infra 서비스가 **무엇을 그리고 무엇과 대조하는가**를 담는 화면 명세 정본.
> 위계: Service > Surface > Section > Component. ID 는 코드·테스트와 기계 대조용 안정 키.
> 짝 문서: `docs/spec/infra-catalog.md`(무엇을 알고 있는가) · 테스트 정의 `docs/qa/infra-architecture.md`.
> 코드: `src/renderer/src/services/infra/{design,reconcile}/` · `src/main/ipc/infra/` · 스키마 `src/main/store/migrations/infra.ts`.

## 이 서비스가 푸는 문제
인프라 대시보드는 대개 "EC2 하나 떠 있고 3000번 리스닝 중"까지만 알려 주고 **그래서 어쩌라는지**를
말해 주지 않는다. Rockury 는 반대로 간다 — **설계자의 의도가 적힌 설계본이 정본**이고, 실물은 그 설계와
맞는지 대조하는 대상이다.

## 공통 불변식
- **Rockury 는 인프라를 구축하지 않는다.** 실물을 바꾸는 유일한 통로는 카탈로그가 정의한 액션 버튼이고,
  그것도 사용자가 명시적으로 누를 때만이다. **대조 결과가 자동으로 실물에 반영되는 경로는 존재하지 않는다.**
- **"적용"의 방향이 DB 서비스와 반대다.** DB 는 Migration 이 실물을 고치지만, Infra 의 적용은
  **실물을 설계본에 흡수**하는 것이다. 유일한 쓰기 대상은 우리 설계 데이터다.
- **노드 문서는 설계 노드에 붙는다. 실물에는 안 붙는다.** 실물은 재생성되면 식별자가 바뀐다 —
  문서를 실물에 매달면 재배포 한 번에 전부 증발한다.
- 실물 값은 언제나 **"○분 전 기준"** 과 함께 보인다. 방금 읽은 것처럼 보이게 하지 않는다.

## 마일스톤
| | 범위 | 이 문서에서의 깊이 |
|---|---|---|
| **M1** ✅ | 설계본 그리기 + 노드 문서 (실물 연결 0) | 인수조건까지 · 구현 완료 |
| **M2** ✅ | 로컬 도커 읽기 + 대조 | 인수조건까지 · 구현 완료 |
| **M3** | AWS 읽기 + 대조 | M2 규칙을 그대로 씀 (공급자만 추가). **탐침은 고정 표본으로 검증됨**(→ 아래) |
| **M4** ✅ | 액션 버튼 | → `infra-catalog.md` §actions · 도커로 실측 |
| **M5** 🟡 | 미들웨어 콘솔 | **Redis 완료**(도커로 실측) · RabbitMQ·Kafka·MQTT 미착수 |

> **✅ 의 뜻**: 이 문서에 적힌 인수조건이 전부 코드에 있고 테스트가 덮는다는 뜻이다.
> 명세가 코드보다 앞서 있으면 그 자리에 `(미구현)` 을 적고 마일스톤을 🟡 로 낮춘다 —
> 안 그러면 다음 사람이 "이미 있는 줄 알고" 찾다가 시간을 버린다.
> (2026-07-29 게이트에서 실제로 ✅ 가 거짓이던 것을 잡아 고쳤다.)

### 의식적으로 미룬 것
`node-doc.mcp` AC-4(대조 결과 MCP 노출) · `design.versions` AC-1(설계본 버전)은 각 항목이
자기 자리에서 **사유와 함께** 미구현임을 적고 있다. 마일스톤 판정에는 넣지 않는다.

### AWS(M3) 는 어디까지 검증됐나
실 계정 없이 **고정 표본**으로 탐침을 검증했다 — `catalog/builtin/awsSamples.json` 에 실제
AWS CLI(`--output json`) 응답의 **구조와 키 이름을 그대로** 박아 두고, `aws.json` 의 표현식이
거기서 무엇을 뽑는지 `aws.test.ts` 가 고정한다(`CASE-icat-120`~`124`).
**덮지 못하는 것**: 명령줄 자체가 맞는지(옵션·리전), 권한, 응답 페이지 나눔 — 실 계정의 몫이다.

## Surface: infra-architecture.design (설계본 — 다이어그램)

### Section infra-architecture.design.canvas — 그리기
- **AC-1** 노드를 놓고 · 이름 짓고 · 끌어 옮기고 · 서로 잇는다. 좌표는 영속된다
  (DB 서비스의 `diagram_layouts` 와 같은 패턴).
- **AC-2** 노드 종류는 카탈로그·프리셋 목록에서 고른다. 종류 없이 **맨 노드**로도 놓을 수 있다.
- **AC-3** **중첩** — 종류의 `canNestIn` 이 허용하는 부모 안에만 들어간다. 허용되지 않는 조합은
  놓이지 않고 **왜 안 되는지**를 보인다(조용히 튕기지 않는다).
- **AC-4** 부모 박스는 자식이 늘면 같이 커지고, 부모를 옮기면 자식이 따라온다.
- **AC-5** 자동 배치 — 겹 구조(부모-자식)를 지키며 정렬한다. ERD 의 평면 배치와 달리 **중첩을 이해해야 한다.**
- **AC-6** PNG/SVG 내보내기(기존 `html-to-image` 자산 재사용).
  경계 계산은 **DB 서비스와 공유하지 않는다** — 저기는 평면(테이블이 다 형제)이고 여기는 중첩이라
  좌표가 부모 기준 상대값이다. 그대로 재면 자식이 원점 근처로 잡혀 캔버스에 빈 곳이 생긴다.
  `design/export.ts` 가 **절대 좌표로 펴서** 잰다.
- **AC-7** 검색 — 이름·종류로 노드를 찾고 화면 가운데로 옮긴다(DB 다이어그램의 포커싱과 같은 규칙: 확대 상한 유지).
  **팔레트의 '종류 검색'과 다른 칸이다** — 저건 *놓을 종류*를 고르는 거르개이고 이건 *놓인 노드*를 찾는다.
  한 칸으로 합치면 "찾았는데 안 보인다"가 된다. **이름이 맞은 것이 종류만 맞은 것보다 먼저** 나온다.
  확대 상한(1.2)을 두는 이유: 상한이 없으면 노드 하나가 화면을 채워 **무엇 옆에 있는지**가 사라지는데,
  인프라 그림에서는 이웃이 곧 정보다. 이미 축소해 놓았으면 그 배율은 건드리지 않는다.

### Section infra-architecture.design.data — 저장 모델
- **AC-1** `infra_designs(id, name, description, created_at, updated_at)` — 설계본은 여러 개일 수 있다
  (환경별·시스템별).
- **AC-2** `infra_nodes(id, design_id, type_id, name, parent_id, pos_x, pos_y, size_w, size_h, doc, meta, created_at, updated_at)`.
- **AC-3** `infra_edges(id, design_id, source_id, target_id, label, kind)`.
- **AC-4** `type_id` 가 가리키던 종류가 카탈로그에서 사라져도 **노드는 살아남는다** —
  '알 수 없는 종류(카탈로그 v3 에 있었음)'로 표시하고 지우지 않는다.
- **AC-5** 테이블 이름은 전부 `infra_` 접두어(서비스 네임스페이스 규칙). 다른 서비스와 겹치면 앱이 안 켜진다.

### Section infra-architecture.design.versions — 설계본 버전 (후속)
- **AC-1** 자리만 잡아 둔다. DB 서비스의 Versions(스냅샷 + 잠금)와 같은 패턴을 따를 것.
  M1~M3 에서는 만들지 않는다 — **여기에 미리 구현하지 않는다.** (M2 까지: 미구현)

## Surface: infra-architecture.node-doc (노드 문서 — 설계 의도)

> 이 서비스의 무기다. 그림만 있는 도구는 흔하고, 실물만 보는 콘솔도 흔하다.
> **"이게 왜 있고 죽으면 뭐가 되는지"** 를 들고 있는 도구가 드물다.

### Section infra-architecture.node-doc.fields — 문서 칸
- **AC-1** 정해진 칸 다섯 — **역할**(왜 있나) · **영향**(죽으면 무슨 일이 나나) · **담당**(사람/팀) ·
  **의존**(무엇을 부르고 무엇이 나를 부르나) · **손대기 전 알 것**(운영 메모).
- **AC-2** 정해진 칸 아래 **자유 서술(마크다운)** 이 붙는다. 자유 서술만 두면 아무도 안 쓰고,
  칸만 두면 의도가 안 담긴다 — 둘 다 둔다.
- **AC-3** 종류에 기본 문서 틀이 있으면 노드를 만들 때 **미리 채워진다**(빈 종이 앞에 앉히지 않는다).
- **AC-4** 관련 링크(런북 · 대시보드 · 티켓)를 여러 개 붙일 수 있다.
- **AC-5** **문서가 빈 노드는 다이어그램에서 표시로 구분된다**("설명 없음"). 채우게 만드는 압력이다.

### Section infra-architecture.node-doc.mcp — 에이전트에게 내보내기
- **AC-1** 설계본과 노드 문서를 MCP 로 **읽기 전용** 노출한다. 이것이 D1(구축은 밖에서)의 반대편 짝이다 —
  에이전트가 "이게 뭐고 왜 있고 죽으면 뭐가 되는지"를 알아야 구축·수정할 수 있다.
- **AC-2** 노출 도구 셋 — `infra_list_designs` · `infra_get_design` · `infra_get_node_doc`. 전부 읽기.
  쓰기·실행·자격증명 채널은 제외 등재(→ `infra-catalog.md` §mcp). `infra:runProbe` 는 **영구 제외**다.
- **AC-4** **대조 결과 노출은 아직 안 한다.** 대조 계산이 렌더러 도메인(`reconcile/`)에 있어 메인이 못 부른다 —
  열려면 그 순수 로직을 `src/shared/` 로 옮기는 별도 작업이 필요하다. 그때까지 `infra:latestSnapshot` 은 제외.
- **AC-3** 노출되는 노드 정보에는 **의존 관계와 영향**이 반드시 포함된다. 이름·종류만 주면
  에이전트도 "그래서 어쩌라고"가 된다.

## Surface: infra-architecture.live (실물 지도)

### Section infra-architecture.live.sync — 읽어 오기
- **AC-1** 공급자별 `새로고침` — 그 카탈로그의 탐침들을 돌려 실물 목록을 가져온다.
- **AC-2** 결과는 **스냅샷으로 로컬에 저장**되고, 화면은 **"○분 전 기준"** 을 항상 표시한다.
- **AC-3** 자동 주기 갱신은 **기본 꺼짐**. 켜도 주기는 사용자가 정한다(요금·호출 제한).
- **AC-4** 일부 탐침이 실패해도 **성공한 것은 반영하고 실패한 것은 실패로 표시**한다.
  전부 실패로 뭉개지 않고, 조용히 성공으로 넘기지도 않는다.
- **AC-5** 카탈로그에 없는 종류로 읽힌 실물은 **'미상' 노드**로 그린다(버리지 않는다).

### Section infra-architecture.live.data — 저장 모델
- **AC-1** `infra_snapshots(id, provider_id, taken_at, ok, error)` — 회차 단위.
- **AC-2** `infra_resources(id, snapshot_id, type_id, external_id, name, status, raw_status,
  parent_external_id, design_node_ref)`.
  `status` 는 사전을 거친 값, `raw_status` 는 원본 문자열(둘 다 남긴다 — AC 근거는 catalog probe.shape AC-5).
- **AC-3** 스냅샷은 공급자별로 최근 N 회만 남기고 오래된 것은 정리한다(로컬 DB 무한 증식 방지).
- **AC-4** `infra_snapshot_probes(snapshot_id, type_id, ok, count, error)` — **탐침 하나하나의 결과**.
  이 표가 없으면 **"0건이었다"와 "못 읽었다"를 구분할 수 없고**, 그러면 멀쩡한 인프라가 '미구축'으로
  보여 사용자가 지우러 간다. 아래 `reconcile.result` AC-4 의 '대조 안 함' 판정이 여기에 선다.

## Surface: infra-architecture.reconcile (대조)

### Section infra-architecture.reconcile.match — 짝짓기
- **AC-1** **1순위 = 태그/라벨.** 실물에 `rockury:node=<설계노드id>` 가 붙어 있으면 그것으로 짝짓는다
  (탐침의 `designNodeRef` 로 들어온 값).
- **AC-2** **2순위 = 이름 일치.** 1순위 짝이 있으면 2순위는 보지 않는다.
- **AC-3** 한 설계 노드에 실물이 여러 개 붙는 것은 **정상일 수 있다**(오토스케일) —
  **개수와 함께 보이고 하나로 접지 않는다.**
- **AC-4** 짝짓기 근거(1순위인지 2순위인지)를 화면에 보인다 — 이름으로 어쩌다 맞은 것과
  태그로 확실히 맞은 것은 신뢰도가 다르다.
- **AC-5** **같은 이름의 설계 노드가 둘 이상이면 이름 짝짓기를 포기한다.** 둘 중 아무 데나 붙이면
  대조가 조용히 틀린 답을 내고 사용자는 그걸 믿는다 — **틀린 답보다 "못 정했다"가 낫다.**
  그 이름들을 따로 보고해 "태그를 붙이세요"라고 안내할 근거로 쓴다.

### Section infra-architecture.reconcile.result — 결과 세 가지
- **AC-1** 결과는 셋으로 갈린다 — **미구축**(설계에만 있음) · **미등록**(실물에만 있음) ·
  **어긋남**(둘 다 있는데 다름).
- **AC-2** 어긋남 판정 대상은 카탈로그가 정한 비교 필드(상태 · 부모 · 종류).
  **무엇이 어떻게 다른지 필드 단위로** 보인다("다름" 한 단어로 뭉개지 않는다).
- **AC-3** 대조 결과를 설계 다이어그램 위에 겹쳐 볼 수 있다(설계 노드에 배지).
  **표와 그림이 같은 계산·같은 색을 본다** — 그림 쪽에서 판정을 다시 계산하면 두 화면이 서로 다른
  답을 말할 수 있고, 그러면 사용자는 어느 쪽을 믿을지 모른다. 색이 다르면 같은 것으로 못 읽는다.
  기본은 꺼짐이고, 켰는데 실물을 아직 안 읽었으면 **그 사실을 화면이 말한다**(전부 '대조 안 함'으로
  보이는 이유를 모르면 앱이 고장 난 것으로 읽힌다).
- **AC-4** 실물 스냅샷이 없는 공급자의 노드는 **"대조 안 함"** 으로 표시한다.
  실물을 안 읽었는데 "미구축"으로 보이면 안 된다.

### Section infra-architecture.reconcile.absorb — 설계본에 흡수
- **AC-1** **미등록** 실물을 설계 노드로 만들어 설계본에 넣는다(하나씩 또는 골라서 여러 개).
  부모 관계(`parentExternalId`)도 함께 옮겨 중첩이 유지된다.
- **AC-2** **어긋남**을 실물 값 기준으로 설계본을 고친다.
- **AC-3** **흡수는 설계본만 바꾼다 — 실물을 절대 건드리지 않는다.**
- **AC-4** 흡수는 되돌릴 수 있다(흡수 직전 설계본 상태를 보관).
- **AC-5** 흡수로 만들어진 노드는 문서가 비어 있으므로 **"설명 없음" 표시가 붙는다**
  (node-doc.fields AC-5 와 같은 규칙 — 흡수가 문서 빈 노드를 몰래 늘리는 통로가 되지 않게).
- **AC-6** **접을 수 있는 것은 구조(종류·부모)뿐이다. 상태 어긋남은 흡수 대상이 아니다.**
  컨테이너가 멈춘 것은 밖에서 고칠 일이지, 설계를 "멈춰 있어야 한다"로 바꿀 일이 아니다.
  이걸 흡수 대상에 넣으면 대조가 스스로 어긋남을 지워 버려 다음부터 아무것도 못 잡는다.
- **AC-7** 계획 객체에는 **설계본 변경분(추가·갱신) 외의 필드가 존재하지 않는다.** 구조로 못 박는다 —
  나중에 누가 실행 지시 필드를 더하면 `CASE-iarch-043` 이 깨진다.

### Section infra-architecture.reconcile.bootstrap — 처음 시작
- **AC-1** 설계본이 비어 있는 사용자는 실물을 읽어 **통째로 흡수해 설계 초안**을 만들 수 있다.
  이미 인프라가 있는 사람에게 이게 유일하게 현실적인 진입로다.
- **AC-2** 초안으로 만든 노드는 전부 "설명 없음" 이므로, 무엇부터 채우면 되는지 목록을 보인다.
  **순서를 우리가 정해 준다** — 배지만 수십 개 뿌려 놓으면 어디부터 손댈지 못 정한다:
  ① 담는 상자부터(큰 그림을 먼저 적어야 안쪽이 쉬워진다) → ② 자식을 많이 담은 것부터
  (죽었을 때 파급이 크다) → ③ 이름 순(순서가 흔들리면 "아까 그거"를 다시 못 찾는다).
  **흡수한 적이 있을 때만** 보인다 — 손으로 그리는 중인 사람에게 들이밀면 잔소리가 된다.

## Surface: infra-architecture.middleware (미들웨어 콘솔) — M5 🟡 Redis 만

> **미들웨어(= 앱과 앱 사이에서 메시지·캐시를 나르는 서버).** 아키텍처 그림의 노드이면서
> 동시에 **접속해서 안을 들여다보는 작은 콘솔**이다 — 성격이 DB 서비스의 Console 과 같다.

### Section infra-architecture.middleware.scope — 범위와 순서
- **AC-1** 순서는 **Redis → RabbitMQ → Kafka → MQTT.** 단순하고 흔한 것부터.
  **지금 붙는 것은 Redis 뿐이다.** 나머지 셋은 목록에 **남겨 두고 "아직 못 붙음"으로 표시**한다 —
  목록에서 빼면 "지원 안 하나?"를 사용자가 짐작해야 하고, 표시 없이 두면 눌러 보고 나서 안다.
  못 붙는 종류에는 **왜 못 붙는지**가 함께 뜬다.
- **AC-2** 접속 관리·콘솔 화면 구조는 DB 서비스의 Connections/Console 패턴을 빌린다(새로 발명하지 않는다).
- **AC-3** 클라이언트는 전부 순수 JS 로 고른다(네이티브 모듈 도입 금지 규칙). 터미널 없이 완결된다.
  **의존성도 0으로 갔다** — `node:net` 위에 규약을 직접 태운다. 라이브러리를 안 쓴 이유가 둘이다:
  ⑴ 의존성 추가는 `main` 브랜치에서 한 사람만 하기로 돼 있고, ⑵ 규약 해독기를 직접 들고 있으면
  **그 전체가 단위 테스트로 덮인다**(조각 걸침·조기 종료·인증 거절까지 결정적으로 재현).
- **AC-4** 각 미들웨어의 세부 인수조건은 **그 마일스톤에 들어갈 때** 이 문서에 채운다.

### Section infra-architecture.middleware.connection — 접속
- **AC-1** `infra_mw_connections(id, kind, name, host, port, username, secret_encrypted, options)`.
  **비밀은 암호문 컬럼에만 있고 꺼내는 창구가 없다** — 공급자 연결과 같은 규칙이다.
- **AC-2** 종류를 고르면 **기본 포트가 채워진다**(6379·5672·9092·1883). 모르는 종류는 0 — 지어내지 않는다.
- **AC-3** 접속을 고쳐 저장할 때 비밀을 비워 두면 **기존 값을 지우지 않고 그대로 둔다**
  (이름만 고치려는 사람에게 비밀 재입력을 강요하지 않는다).

### Section infra-architecture.middleware.console — 콘솔
- **AC-1** **접속을 들고 있지 않는다** — 한 번 붙어 명령을 돌리고 끊는다. 메인 프로세스에 소켓을
  눌러앉히면 앱이 사는 동안 남의 서버에 연결이 매달려 있고, 죽은 연결을 되살리는 상태 기계까지
  떠안아야 한다. 콘솔은 사람이 한 번에 몇 줄 치는 도구라 그 비용을 낼 이유가 없다.
- **AC-2** **"붙지 못했다"와 "서버가 거절했다"를 구분해 보인다.** 뭉개면 사용자가 "주소가 틀렸다"와
  "명령이 틀렸다"를 못 가른다. 시간 초과도 성공으로 넘어가지 않는다.
- **AC-3** 처음 붙은 사람을 위한 **빠른 명령**을 준다. **전부 읽기다** — 콘솔을 열자마자 데이터가
  바뀌면 안 된다.
- **AC-4** 명령 줄은 **인자 배열로 갈라** 규약에 실린다(길이가 앞에 붙는 벌크 문자열).
  값에 공백·줄바꿈이 있어도 명령이 쪼개지지 않는다 — CLI 쪽의 "셸을 거치지 않는다"와 같은 성질이다.
  따옴표로 묶은 덩어리는 한 인자다(공백 든 값을 넣을 길이 없으면 콘솔이 반쪽이 된다).
- **AC-5** **없음(nil)과 빈 문자열을 구분해 보인다** — 둘을 같게 보이면 "키가 없다"와 "값이 비었다"를
  못 가른다.
- **AC-6** 실행 이력에 남는다. **명령 이름만 남기고 값은 남기지 않는다** — 키 이름·비밀이 이력에
  눌러앉지 않게.
