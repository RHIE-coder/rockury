# Service: api-runner (운영부 — Environments · Runner)

> 실제 서버에 요청을 보내고 그 결과를 **관측 기록으로 쌓는** 곳. active Environment 가 중심이다.
> 여기서 쌓인 기록이 판정(`api-contract.md`)의 원재료이자, AI 가 다른 데서 못 얻는 조각이다.
> 서비스 정본·도메인 모델·불변식은 `api-service.md`.

공통 불변식
- **Environment 는 명시적으로 고를 때까지 비어 있다** — PROD 오조작 방지(DB 서비스와 같은 규율).
- **실행은 사람이 앱에서 한다.** MCP 에는 실행 도구가 없다(`api-service.md` §4-③).
- 실행 기록(Run)은 **불변**이다 — 지나간 관측을 고쳐 쓰지 않는다.

## Surface: api-environments (Environments 모듈)

### Section api-environments.list — 환경 카드
- **AC-1** 현재 Spec 에 속한 환경을 카드 목록으로 보인다. 카드에는 이름 · 서버 주소 ·
  마지막 실행 시각을 표시한다.
- **AC-2** 카드를 누르면 active Environment 가 된다. 컨텍스트 바 셀렉터와 항상 같은 값을 가리킨다.
- **AC-3** 환경 추가·이름변경·복제를 제공한다. **복제는 값을 함께 복사하지 않는다** —
  구조(변수 이름)만 복사하고 값은 비운다(STG 를 복제해 PROD 를 만들다 STG 키가 PROD 에 남는 사고 방지).
- **AC-4** 삭제는 확인 게이트를 거친다. 실행 기록이 붙은 환경은 삭제 대신 **보관**만 된다 —
  기록이 가리키는 환경이 사라지면 지나간 관측을 해석할 수 없다.

### Section api-environments.values — 환경 값
- **AC-1** 이름·값 목록으로 편집한다. 각 값에 **비밀 표식**을 켤 수 있다.
- **AC-2** 비밀 표식이 켜진 값은 화면에서 가려지고(`••••`), 누르면 잠깐 보인다.
- **AC-3** 환경 값은 호출 파라미터와 **한 목록에 섞이지 않는다**(`api-service.md` §2).
  화면에서 구획이 갈리고, 어느 쪽인지 라벨로 표시된다.
- **AC-4** 어느 요청도 참조하지 않는 값(고아)과, 참조되는데 값이 빈 것(구멍)을 각각 표시한다.
  · **둘 다 아닌 값은 목록에 안 나온다** — 정상인 것을 나열하면 목록이 시끄러워 아무도 안 읽는다.
  · 판정은 **저장된 값이 아니라 편집 중인 값** 기준이다. 값을 지우자마자 구멍이 뜨는 것이
    저장한 뒤에 뜨는 것보다 낫다.
  · 참조는 요청의 모든 템플릿 자리(경로·쿼리 값·헤더 값·본문·파라미터 기본값)에서 모은다.
- **AC-5 (불변식 ⑥)** 내보내기·복제·MCP 어디로도 값이 나가지 않는다. 이름만 나간다.

### Section api-environments.resolution — 값 해석 순서
> 같은 이름이 여러 곳에 있을 때 누가 이기는지가 안 보이면, Postman 이 겪는
> "STG 인 줄 알고 PROD 를 쳤다" 사고가 그대로 재현된다.

- **AC-1 (순서 고정)** `Request 기본값  <  Environment 값  <  호출 파라미터` — 오른쪽이 이긴다.
- **AC-2** 해석 결과에 **출처가 함께 실린다** — 이 값이 기본값에서 왔는지, 환경에서 왔는지,
  호출자가 넣었는지를 값마다 안다.
- **AC-3** 어디에도 값이 없는 참조는 **실행 전에 차단**하고 이름을 지목한다. 빈 문자열로
  조용히 치환하지 않는다.

### Section api-environments.guard — 오조작 방지
- **AC-1** Environment 는 앱 진입 시 **선택되지 않은 상태**로 시작한다. 고르기 전에는
  실행 버튼이 비활성이고 이유를 툴팁으로 알린다.
- **AC-2** 환경에 **운영 표식**을 켤 수 있다. 켜진 환경이 active 이면 상단에 상시 경고 띠가
  보인다 — 화면 어디에 있어도 지금 PROD 라는 사실이 보인다.
- **AC-3** 운영 표식 환경에서 실행하면 확인 게이트를 한 번 거친다. 요청 이름과 환경 이름을
  확인 문구에 넣는다("무엇을 어디로"가 문구에 보인다).
- **AC-4** 서비스를 전환했다 돌아오면 active Environment 는 초기화된다(선택 안 됨으로).

## Surface: api-runner.send (Send 뷰 — 단발 요청→응답)

### Section api-runner.send.compose — 파라미터 입력 · 최종 요청 미리보기
- **AC-1** 요청의 시그니처(`api-studio.md` § requests.signature)에서 입력칸이 자동으로 생긴다.
  타입에 맞는 입력 형태(숫자·불리언 토글·enum 드롭다운)를 쓴다.
- **AC-2** 치환이 끝난 **최종 요청 전문**(경로·헤더·본문)을 보내기 전에 보인다.
- **AC-3 (출처 표시)** 미리보기의 각 치환 값에 출처가 보인다 — 기본값 / 환경 / 호출 파라미터.
  비밀 표식 값은 미리보기에서도 가려진다.
- **AC-4** 필수 파라미터가 비었거나 해석 못 한 참조가 있으면 보내기가 막히고 이유를 지목한다.

### Section api-runner.send.execute — 실행
- **AC-1** 실행하면 응답 본문 · 상태 · 헤더 · 소요 시간 · 크기를 보인다.
- **AC-2** 본문은 형식에 맞게 보인다(JSON 접기/펼치기, 텍스트, 바이너리는 크기·형식만).
- **AC-3** 취소를 제공한다. 취소된 실행도 기록에 남는다(결과=취소).
  · 취소 손잡이는 **화면이 만든다** — 응답을 기다리기 전에 화면이 이미 알고 있어야 버튼을
    누를 수 있다(스트림 세션 식별자와 같은 이유).
  · 끊긴 뒤 화면을 먼저 "취소됨"으로 바꾸지 않는다. 실제 기록이 돌아와야 그 사실이 사실이다.
- **AC-4** 연결 실패·타임아웃·TLS 오류를 서로 구분해 알린다 — "실패"로 뭉뚱그리지 않는다.
- **AC-5** 응답을 curl / fetch 로 복사할 수 있다(비밀 표식 값은 변수 이름으로 남긴다).

### Section api-runner.send.observe — 관측 기록으로 저장
> 이 섹션이 이 서비스가 AI 에게 댈 수 있는 두 조각 중 하나를 만든다.
- **AC-1** 모든 실행은 Run 으로 저장된다 — 요청 · 파라미터 · 환경 · **기준 버전** · 요청 전문 ·
  응답 전문 · 시각 · 소요.
  · **파라미터는 따로 담는다.** 조립된 주소에서 되돌릴 수 없기 때문이다(치환은 한 방향이다) —
    이게 없으면 "같은 파라미터로 다시 실행"(history.list AC-3)이 성립하지 않는다.
- **AC-2** Run 은 불변이다. 나중에 명세가 바뀌어도 지나간 Run 은 안 바뀐다.
- **AC-3** 비밀 표식 값은 Run 에 **가려진 채로** 저장된다 — 기록을 열람하거나 MCP 로 읽을 때
  실값이 드러나지 않는다. 저장한 뒤 가리는 게 아니라 **가린 뒤 저장한다**(저장소에 실값이
  한 번도 안 들어간다).
- **AC-3b (응답 경로)** **응답 본문·응답 헤더·오류 문구에서도** 아는 비밀을 지운다.
  요청만 가리면 **서버가 되돌려준 값이 그대로 남는다** — 키를 에코하는 서버, 디버그
  엔드포인트, 인증 헤더가 실린 오류 메시지가 그렇다(e2e 로 실측해 잡은 자리다).
  · **되돌려주는 형태가 원문이 아닐 수 있다.** 쿼리에 실었으면 URL 인코딩된 형태로 오고,
    `{{base64(키)}}` 로 보냈으면 base64 로 에코된다 — 아는 비밀의 **되돌릴 수 있는 표기**들도
    함께 지운다(e2e 로 실측해 잡은 자리다).
  · **한계를 분명히 한다:** 지울 수 있는 것은 *우리가 값을 아는* 비밀뿐이다. 서버가 새로
    발급한 토큰(로그인 응답의 access token 등)은 모르므로 못 지운다. 해시·서명
    (`md5`·`sha256`·`hmac`)은 되돌릴 수 없어 표기를 만들 수조차 없다 — 그래서 MCP 에는
    본문을 아예 주지 않고 **모양까지만** 준다(`api-mcp.md` § tools.read AC-3).
  · **우리가 만든 문자열은 지우는 그물을 믿지 않는다** — 조립기가 `{{…}}` 조각 통째로 가린
    것을 쓴다. 그물은 글자 그대로 일치만 지우므로 가공된 값(인코딩·함수)을 못 잡는다.
  · 너무 짧은 값(4글자 미만)은 지우지 않는다 — 본문이 걸레가 되어 읽을 수 없게 된다.
- **AC-4** Run 저장 실패가 요청 실행을 막지 않는다(기록은 부가물이지 관문이 아니다).

## Surface: api-runner.history (History 뷰)

### Section api-runner.history.list — 기록 목록
- **AC-1** 최근 실행을 시간 역순으로 보인다. 요청 이름 · 환경 · 상태 · 소요를 한 줄에.
- **AC-2** 요청별 · 환경별 · 상태별(성공/실패) 필터와 기간 필터를 제공한다.
- **AC-3** 항목을 열면 요청/응답 전문을 본다. **다시 실행**을 제공한다(같은 파라미터로).
  · 기록의 파라미터는 **가려진 채로** 저장된다. 그래서 비밀 표식 값이 섞여 있으면 그 자리는
    **되살리지 않고 비운 뒤 이름을 지목한다** — `••••` 를 그대로 보내면 서버가 받는 것이
    거짓이 되고, 조용히 보내면 사람이 그 사실을 모른다.
  · 지나간 기록은 안 바뀐다(Run 은 불변) — 다시 실행은 **새 기록을 하나 더** 만든다.
  · 스트림 세션·웹훅 수신에는 다시 실행이 없다: 세션을 "다시 트는 것"은 같은 뜻이 아니고,
    웹훅은 우리가 보내는 것이 아니다.
- **AC-4** 두 Run 을 골라 응답을 비교할 수 있다(무엇이 달라졌나).
  · **순서가 뜻을 갖는다** — 먼저 고른 것이 기준이고, 뒤바꾸면 `새로 생김`과 `없어짐`이 뒤집힌다.
    화면이 어느 쪽이 기준인지 보인다.
  · 판정(`api-contract.md`)과 다른 자리다 — 판정은 **선언 대 실제**, 여기는 **실제 대 실제**다.
    그래서 선언이 없어도 되고 "어긋남"이라는 말도 쓰지 않는다.
  · **비교할 수 없었다는 사실을 "같다"로 바꾸지 않는다** — JSON 이 아니면 필드로 못 쪼갠다는
    사실을 결과에 담는다. 상태·기준 버전·환경처럼 본문 밖의 차이는 따로 센다.
- **AC-5** 보관 기간·최대 건수 상한을 설정할 수 있고, 상한으로 지워진 것이 있으면
  **몇 건이 지워졌는지 표시**한다(조용한 소실 금지).

## Surface: api-runner.stream (Stream 뷰 — 서버 스트리밍 · 양방향 세션)

### Section api-runner.stream.session — 세션
- **AC-1** 접속/끊기와 현재 상태(대기·연결됨·끊김·오류)를 보인다. 끊긴 이유를 표시한다.
- **AC-2** 주고받은 메시지를 **시간순 타임라인**으로 보인다. 보낸 것과 받은 것이 방향으로 구분된다.
- **AC-3 (양방향만)** 보내기 패널이 있다. 서버 스트리밍(SSE·gRPC server-streaming)에서는
  보내기 패널이 **없다**(비활성이 아니라 없음).
- **AC-4** 자동 재접속 여부를 켜고 끌 수 있다. 재접속 시도도 타임라인에 남는다.
- **AC-5** 타임라인 검색·필터, 메시지 하나 복사, 전체 내보내기를 제공한다.
- **AC-6** 세션 전체가 하나의 Run 으로 저장된다 — 메시지 목록이 그 Run 의 관측 내용이다.
- **AC-7 (전송 범위 · 강등 금지)** 1차 전송은 **WebSocket · SSE** 두 가지다. 그 밖의
  스트리밍(gRPC 스트리밍 4종 · GraphQL subscription)은 **있는 전송으로 흉내 내지 않고**
  화면에 사유를 띄운다 — 붙긴 했는데 아무것도 안 오는 상태는 미관측을 통과로 적는 것과 같다.
  · gRPC: HTTP/2 프레이밍이 필요해 전송 라이브러리 도입이 선행된다.
  · GraphQL subscription: WebSocket 위 `graphql-ws` 하위 프로토콜 손잡기가 필요하다.
- **AC-8 (비밀 · 세션 경로)** 보낼 메시지도 `{{변수}}` 치환을 지난다. 소켓에 나가는 글자만
  실값이고, **타임라인에 들어가기 전에 가려진다** — 화면·기록·내보내기 어디에도 실값이 없다.
  받은 메시지도 같은 관문을 지난다(서버가 키를 되돌려주는 경우 — send.observe AC-3b 와 같은 규율).
  · 보내기·접속 주소는 단발 전송과 같이 **두 벌**을 만든다(소켓용 실값 / 기록용 가림).
    한 벌만 만들고 지우는 그물로 때우면 가공된 비밀(`{{base64(키)}}`·URL 인코딩)이 샌다.
  · 못 보내는 이유·오류 문구도 **가린 쪽**을 쓴다 — 내장 함수 오류는 받은 인자를 그대로 인용한다.

- **AC-9 (붙는 데는 제한시간이 있다)** 접속 시도에는 제한시간을 걸고, 붙은 뒤에는 걸지 않는다
  (오래 조용한 것이 스트림의 정상 상태다). 제한시간을 안 걸면 TCP 만 받고 응답을 안 주는
  서버에서 어느 이벤트도 안 와 **영원히 '접속 중'** 이고 기록도 안 남는다.
- **AC-10 (자동 재접속에 총 상한)** 연속 실패 상한만으로는 안 막힌다 — 붙자마자 끊는 서버에서는
  매번 "붙었다"로 세어 연속 카운터가 0으로 돌아가 **영원히 재접속한다**(그러면 세션이 끝나지
  않아 관측 기록도 안 남는다). **줄어들지 않는 누적 상한**을 함께 둔다.
- **AC-11 (원격 입력에 크기 상한 · 조용한 소실 금지)** 한 줄·한 프레임·한 메시지·타임라인
  전체에 각각 상한을 둔다(단발 응답의 본문 상한과 같은 규율). 넘치면 **자른 사실을 데이터에
  적는다.** 상한이 없으면 서버가 메인 프로세스 메모리를 채울 수 있고, 메인이 죽으면 창이 전부
  사라져 **안내 한 줄도 못 띄운다.**
- **AC-12 (화면 상한 = 기록 상한)** 화면이 들고 있는 타임라인 상한은 저장되는 것과 **같아야 한다.**
  다르면 같은 세션을 두고 화면과 기록이 다른 수를 말한다.
- **AC-13 (주인 없는 세션을 남기지 않는다)** 화면이 새로 뜨면 앞선 화면이 열어 둔 세션은 주인이
  없다 — 끊을 창구가 없는 소켓이 남고 자동 재접속이 계속 돈다. 새 화면은 남은 세션을 정리한다
  (Inbox 가 앱을 켤 때 대기를 꺼짐으로 시작하는 것과 같은 규율).
- **AC-14 (세션 관측은 다시 볼 수 있다)** 저장만으로 AC-6 이 성립하지 않는다 — 기록 화면에서
  그 세션의 메시지를 방향·시각과 함께 다시 볼 수 있어야 한다. 목록은 본문을 안 싣고
  건수만 보이며(본문이 크면 앱이 멈춘다), 펼칠 때 하나만 읽는다.

> **세션은 화면보다 오래 산다.** 소켓은 메인 프로세스가 들고 있어서 다른 화면에 갔다 와도
> 안 끊긴다. 그래서 세션은 응답이 아니라 **이벤트**로 화면에 밀려오고, 끝맺음(사용자가 껐든
> 서버가 끊었든)은 **한 자리로 모여** Run 이 된다 — 경로를 둘로 두면 한쪽이 기록을 빠뜨린다.
>
> **세션 식별자는 화면이 만든다.** 메인이 만들어 응답으로 돌려주면, 붙자마자 동기로 실패하는
> 경우(주소 스킴 오타 등) 오류·종료 이벤트가 **응답보다 먼저** 도착해 화면이 자기 것으로 못
> 알아보고 버린다 — 그러면 '접속 중' 에 영구히 갇히고 끊기 버튼도 죽는다(실측해 잡은 자리다).

## Surface: api-runner.inbox (Inbox 뷰 — 웹훅 수신)

> 내가 안 보냈는데 들어온다. 4모양 중 유일하게 방향이 반대다.

### Section api-runner.inbox.listener — 수신 대기
- **AC-1** 로컬 수신 주소를 만들고 대기 상태를 보인다(주소 · 포트 · 켜짐/꺼짐).
- **AC-2** 주소를 복사할 수 있다. 포트 충돌 시 이유를 알리고 다른 포트를 제안한다.
- **AC-3 (1차 범위)** **로컬 전용**이다 — 외부에서 닿지 않는다. 화면에 그 사실을 명시한다
  ("이 주소는 이 컴퓨터 안에서만 닿습니다"). 외부 터널은 후속(`api-service.md` §7).
- **AC-4** 앱을 껐다 켜면 대기 상태는 꺼짐으로 시작한다(모르는 새 포트가 열려 있지 않게).

### Section api-runner.inbox.received — 받은 것
- **AC-1** 들어온 요청을 시간순 목록으로 보인다. 메서드 · 경로 · 크기 · 시각.
- **AC-2** 항목을 열면 헤더와 본문 전문을 본다.
- **AC-3** 선언한 기대 본문 스키마(`api-studio.md` § requests.shape AC-6)와 대조해
  맞는지/어긋나는지 표시한다. 스키마 선언이 없으면 "선언 없음"으로 둔다.
- **AC-4** 각 수신은 Run 으로 저장된다 — 웹훅도 관측 기록이다.
- **AC-5** 응답 코드를 지정할 수 있다(기본 `200`). 재전송을 유도하려면 실패 코드를 내보낼 수 있어야 한다.
  코드를 바꾸는 것이 **대기를 끊지 않는다** — 켜고 끄는 사이에 온 웹훅을 놓치게 되기 때문이다.
- **AC-6 (대조 결과 네 갈래)** `맞음` · `어긋남` · **`선언 없음`** · **`대조 불가`**(JSON 아님)로 갈린다.
  뒤 둘을 맞음으로 뭉치지 않는다 — 대조할 것이 없었다는 사실을 통과로 바꾸는 셈이다
  (판정의 `unparsable` 과 같은 규율). 선언이 깨져 있어도 **추측하지 않고** `선언 없음`으로 둔다.
  · 선언에 없는 필드가 더 와도 **어긋남이 아니다.** 발신자는 남이고 그쪽이 필드를 더하는 것은
    흔한 일이다 — 우리가 선언한 것이 오는지만 본다(판정의 `server-only` 와 다른 자리다).
  · 필수여부 `모름`은 대조에서 빠지고 **몇 개 뺐는지** 결과에 실린다.
- **AC-7 (받는 모양만)** 수신 대기는 `inbound` 모양 요청에만 걸 수 있다 — 모양이 곧 방향이다.
  보내는 요청에 걸려 하면 이유를 달아 거부한다.
- **AC-8 (비밀 · 수신 경로)** 받은 본문·헤더·경로에서도 아는 비밀을 지운다 — 웹훅은 서명 헤더에
  우리 비밀이 실려 오는 경우가 흔하다. **대조는 원문 기준**으로 하고 기록에는 가린 것을 남긴다
  (가린 본문으로 대조하면 비밀이 실린 필드의 타입까지 달라져 없는 어긋남이 생긴다).
- **AC-9 (상한 · 조용한 소실 금지)** 본문 크기와 목록 건수에 상한을 둔다(남이 보내는 것이라 크기를
  우리가 못 정한다). 넘치면 **잘랐다·버렸다고 적는다.** 화면 상한은 저장되는 것과 같아야 한다.
- **AC-10 (기록은 관문이 아니다)** 기록에 실패해도 **응답은 돌려준다** — 우리 사정으로 발신자를
  재전송에 밀어 넣지 않는다(send.observe AC-4 와 같은 규율).
