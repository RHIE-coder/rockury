# Shell: project-scope (프로젝트 범위 — 다섯 서비스를 함께 좁히는 자리)

> 어느 서비스에도 속하지 않는 **공용** 기능이다. 다섯 서비스(uiux·api·db·infra·ai)가 같은
> 프로젝트를 가리키므로 한 서비스가 소유할 수 없다.
> 코드: `store/migrations/shell.ts` · `store/projects.ts` · `store/scopedItems.ts` ·
> `ipc/projects.ts` · `renderer/shell/project*` · 테스트 정의 `docs/qa/shell-project-scope.md`.

## 1. 이 기능이 푸는 문제

서로 다른 일(쿠팡 만들기 · 사내 위키 만들기)의 설계·명세·접속이 **한 목록에 섞여** 있었다.
쿠팡 작업 중에도 위키 것이 계속 눈에 들어온다.

프로젝트를 고르면 다섯 서비스의 목록이 **함께** 좁혀진다.

## 2. 왜 레일의 여섯 번째 서비스가 아닌가

레일의 다섯 칸은 전부 *무엇을 하는 자리*다. 프로젝트는 하는 일이 아니라 **범위** — "지금 보는
모든 것이 무엇에 속하나" 다. 레일에 넣으면 *프로젝트를 관리하러 가는 화면*이 되는데, 정작
필요한 건 나머지 다섯 칸이 그 프로젝트로 좁혀지는 것이다. **그 화면을 떠나야 효력이 생기는
컨텍스트는 컨텍스트가 아니다.** 자리는 타이틀바의 셀렉터 하나다.

이름을 "워크스페이스"로 하지 않은 이유: 이 코드베이스에서 그 낱말은 이미 다른 뜻이다
(`nav/types.ts` 의 `WorkspaceComponent` = 모듈 본문 · `shell/WorkspacePanels.tsx` ·
`services/db/workspaces/`). 같은 낱말이 두 대상을 가리키면 코드·테스트 대조가 깨진다.

## 3. 도메인 모델

| 엔티티 | 정의 | 성격 |
|---|---|---|
| **Project (프로젝트)** | 이름·주소 조각(`key`)을 가진 범위. UI/UX 위계의 맨 위층이기도 하다 | 공용 · 소유자 없음 |
| **소속(project_id)** | 각 서비스의 "목록 맨 위에 이름으로 뜨는 것"이 갖는 칸. **비울 수 있다** | 서비스 소유 테이블의 칸 |

### 소속을 갖는 것 — 여섯

| 종류 | 테이블 | 무소속 규칙 |
|---|---|---|
| DB 설계 | `designs` | strict |
| API 명세 | `api_specs` | strict |
| 인프라 설계본 | `infra_designs` | strict |
| DB 접속 | `connections` | shared |
| 클라우드 계정 | `infra_providers` | shared |
| 미들웨어 접속 | `infra_mw_connections` | shared |

**안쪽에는 칸을 두지 않는다.** 명세가 쿠팡 것이면 그 안의 요청 200개도 쿠팡 것이다 — 부모를
보면 안다. 요청마다 적으면 ⑴ 명세를 옮길 때 200개를 같이 고쳐야 하고 ⑵ 하나라도 빠지면
*명세는 쿠팡인데 요청은 배민* 인, 있을 수 없는 상태가 생긴다.

## 4. 두 갈래 — 무소속에서만 갈린다

다른 프로젝트 것이 숨는 건 두 갈래가 같다. **비어 있는 것**에서만 다르다.

- **strict (설계류)** — 그 프로젝트의 **산출물**이다. 쿠팡을 보는데 정체 모를 무소속이 섞이면 안 된다.
- **shared (접속류)** — **쓰는 도구**다. 로컬 테스트 DB 는 쿠팡을 하든 위키를 하든 쓴다. 여기서
  숨기면 비워 두는 것 자체가 쓸모없어지고, 같은 접속을 프로젝트마다 다시 등록하게 된다.

정본은 `renderer/shell/projectScope.ts` 의 순수 함수 하나(`inScope`)다 — 화면마다 조건을
다시 쓰면 한 곳만 고쳐진다.

## 5. 무소속을 허용한다

사용자 결정(2026-08-04). 소속 칸은 `NOT NULL` 이 아니다.

- 이 기능을 도입하기 **전에** 만든 것이 전부 무소속으로 시작한다 — 소급해서 답할 것이 없다.
- 접속을 프로젝트에 강제로 매면 로컬 DB 하나를 프로젝트 수만큼 중복 등록해야 한다.

## 6. 여러 프로젝트에 동시 소속(N:M)은 하지 않는다

접속류에는 수요가 있지만("쿠팡과 위키에서만 보이게"), 그 대부분은 **비워 두기**가 이미 덮는다.
그리고 방향에 따라 비용이 다르다 — 칸 하나 → 여러 개는 기계가 옮기지만(기존 값이 연결 1개로
그대로 들어간다), 여러 개 → 칸 하나는 *셋 중 뭘 버리냐*를 사람이 답해야 한다.
**싼 쪽에서 시작한다.**

설계류는 아예 안 한다: 버전·마이그레이션이 붙어 있어 주인이 둘이면 "누구 기준으로 버전을
올리나"에 답이 없다. 공유하려면 복제한다.

## Surface: shell.project-scope.selector — 타이틀바 셀렉터

- **AC-1** 타이틀바에 프로젝트 셀렉터가 **하나** 있다. 값은 `전체` · 각 프로젝트 · `프로젝트 없음`.
- **AC-2** 기본값은 **전체**다. 기본이 특정 프로젝트면 앱을 켜자마자 목록이 비어 보인다(도입 전
  데이터는 전부 무소속).
- **AC-3** **좁혀 있을 때만 색이 켜진다**(`전체` 는 조용하고, 나머지 둘은 강조). "왜 내 설계가
  목록에 없지?" 의 답이 늘 화면 맨 위에 있어야 하는데, 같은 무게로 보이면 좁혀진 것을
  눈치채지 못한다.
- **AC-4** 프로젝트가 하나도 없으면 `프로젝트 없음` 항목을 숨긴다 — 전체와 결과가 같아 보일 이유가 없다.
- **AC-5** 고른 범위는 앱을 껐다 켜도 남는다. 그 사이 지워진 프로젝트를 가리키면 **전체로 되돌린다**
  (빈 화면을 보이지 않는다).
- **AC-6** 새로 만들면 **그 프로젝트로 범위가 옮겨간다** — 만들어 놓고 다시 골라야 하면 만든 뜻이 반만 남는다.

## Surface: shell.project-scope.filter — 목록 좁히기

- **AC-1** 프로젝트를 고르면 DB 설계·API 명세·인프라 설계본 목록에서 **남의 것과 무소속이 함께** 숨는다.
- **AC-2** 같은 상태에서 DB 접속·클라우드 계정·미들웨어 접속은 **남의 것만** 숨고 무소속은 남는다.
- **AC-3** `전체` 는 소속과 무관하게 전부 보인다. `프로젝트 없음` 은 무소속만 보인다.
- **AC-4** 새로 만들 때 **지금 보고 있는 범위가 그대로 소속**이 된다(폴더 안에서 파일을 만드는 것과 같다).
  `전체`·`프로젝트 없음` 을 보고 있으면 무소속으로 만들어진다. 만들기 폼에 소속 칸을 두지 않는다.

## Surface: shell.project-scope.organize — 소속 정리

> 이 자리가 없으면 기능이 반쪽이다: 만들 때 소속이 정해지므로, 도입 **전에** 만든 것은 영원히
> 무소속으로 남는다.

- **AC-1** 여섯 종류를 **한 창에서** 다룬다 — 서비스마다 목록 화면을 뜯지 않아 서비스 파일 소유권이 유지된다.
- **AC-2** 무소속의 표시가 종류마다 다르다: 접속류는 `공용`, 설계류는 `없음`. 같은 낱말로 뭉뚱그리면
  왜 하나는 안 숨는지 알 수 없다.
- **AC-3** 옮기면 **그 자리에서** 각 서비스 목록에 반영된다. (회귀 2026-08-04: 저장소만 바뀌고
  서비스 스토어가 든 사본이 옛 소속이라, 옮긴 설계가 셀렉터에 계속 안 나타났다.)
- **AC-4** 없는 프로젝트로는 옮길 수 없다 — 어느 범위에서도 안 보이는 유령이 된다.

## 불변식

- **INV-1** 프로젝트 `key` 는 전역 유일하다. 화면 안정 주소의 첫 조각이라(`coupang.buyer.auth.login`)
  겹치면 한 주소가 두 프로젝트를 가리킨다. UNIQUE 인덱스가 강제한다.
- **INV-2** **프로젝트를 지워도 설계·명세·접속은 지워지지 않고 소속만 풀린다.** 프로젝트는 범위를
  나누는 이름표이고 DB 설계는 그보다 무거운 산출물이다 — 이름표를 떼는 일에 딸려 사라지면
  되돌릴 방법이 없다.
  - **예외: UI/UX 위계.** 거기서는 프로젝트가 곧 트리의 뿌리라, 앱·화면이 부모를 잃으면 유령이
    된다(`uiux-ia.md` INV-4). 그쪽만 연쇄로 지운다.
- **INV-3** 소속 칸은 각 서비스에서 **한 층**에만 있다(§3).
- **INV-4** 범위를 고르는 상태는 **한 곳**(셸 스토어)에만 산다. 서비스가 복제하면 같은 앱 안에서
  화면끼리 다른 프로젝트를 보게 된다.
