# Service: api (API 서비스 — 정본 루트)

> Swagger·Postman 자리의 도구를 **AI 가 읽고 쓰는 것을 전제로** 다시 만든 것.
> 이 문서는 **Service 레벨** 정본이다 — 도메인 모델·IA·불변식·결정로그가 여기 산다.
> Surface 명세는 갈라진 문서에 있다: `api-studio.md`(설계부) · `api-runner.md`(운영부) ·
> `api-contract.md`(판정) · `api-mcp.md`(AI 노출면).
> 위계: Service > Surface > Section > Component. ID 는 코드·테스트와 기계 대조용 안정 키.

---

## 1. 이 서비스가 잡은 자리

**Rockury 는 API 의 정본(source of truth)을 주장하지 않는다.** 팀에서 정본은 늘 세 군데에
흩어져 있다 — 선언한 명세 · 코드 · 돌고 있는 서버. Rockury 가 대는 것은 **그 셋 중 어디에도
없는 두 조각**이다:

1. **선언된 의도** — 코드에 안 적히는 것(이 필드가 왜 nullable 인지, 이 엔드포인트를 언제
   쓰면 안 되는지, 무엇이 곧 없어지는지).
2. **사람이 쓰면서 쌓인 관측 기록** — 실제로 쏴 보고 받은 응답의 축적. 한 번 호출해 보는
   것과 다르다. PROD 관측은 특히 다른 데서 못 얻는다.

**코드가 명세대로인지 판정하는 것은 AI 의 몫이다** — AI 는 코드를 읽을 수 있고 Rockury 는
못 읽는다. Rockury 자체 판정은 **자기가 아는 것 안에서만** 한다(§4-①).

## 2. 도메인 모델

| 엔티티 | 정의 | 성격 |
|---|---|---|
| **Spec (명세)** | 이름을 가진 API 명세 묶음. **인터페이스 종류(REST/GraphQL/gRPC/…)는 생성 시 결정되는 고정 속성** — 화면·편집기가 그 종류의 네이티브 모양 그대로. | 설계부 |
| **Request (요청)** | Spec 안의 개별 요청 정의. **파라미터 시그니처를 갖는 함수**다 — 요청 모양 + 응답 모양 + 문서를 함께 든다. | 설계부 |
| **Version (버전)** | Spec 의 불변(immutable) 스냅샷. 깨지는 변경 판정의 기준선. | 전역 소유 · 단조 증가 |
| **Environment (환경)** | 서버 주소 + 그 환경의 변수 값 묶음. DEV/STG/PROD. Spec 에 소속(1:N). | 운영부 |
| **Run (실행 기록)** | 한 번 쏜 것 — 요청 + 파라미터 + 환경 → 실제 요청/응답/시각/소요. **판정의 원재료.** | 운영부 · 불변 |
| **Function (내장 함수)** | 값 가공용 고정 목록. 엔티티가 아니라 **언어의 일부** — 사용자가 만들거나 지우지 않는다. | 전역 · 고정 |

### 관계

- **Spec 1 : N Request** — 요청은 항상 한 명세에 소속된다.
- **Spec 1 : N Environment** — 환경은 항상 한 명세에 소속된다.
- **Spec 1 : N Version** — 버전은 명세 전체의 스냅샷이다(요청 단위 버전 아님).
- **Run → (Request, Environment, Version)** — 실행 기록은 셋을 모두 가리킨다. 그래야
  "어느 버전 기준으로 무엇을 관측했나"가 나중에 판정된다.

### 값의 두 종류 (섞지 않는다)

이 갈래가 이 서비스의 핵심 모델이다. Postman 이 "변수" 한 바구니에 다 넣어서 커지면
무엇이 무엇인지 모르게 되는 지점이다.

| | 언제 정해지나 | 어디 사나 | 예 |
|---|---|---|---|
| **환경 값** | 환경마다 다름 · **호출마다 같음** | Environment | base URL · API 키 · 테넌트 id |
| **호출 파라미터** | 환경과 무관 · **호출마다 다름** | Request 시그니처 | 조회할 userId · 페이지 번호 |

### 값 해석 순서 (못 박음)

```
Request 기본값  <  Environment 값  <  호출 파라미터      (오른쪽이 이긴다)
```

어떤 값이 어디서 왔는지는 **화면에서 항상 보인다**(`api-runner.md` § compose AC-3).

## 3. IA (확정본)

```
API (service)
│  컨텍스트 바:  [ Spec ▾ ]  [ Version ▾ ]  [ Environment ▾ ]
│                            └ 설계부에서만 활성    └ 운영부에서만 활성
│
│  ── 설계부 (design) ──  Env 무관, 버전 중심
├─ Studio      ┬ Requests · Docs · Mocking
├─ Versions    ┬ Timeline(컷/락) · Diff
│
│  ── 운영부 (ops) ──  active Env 중심
├─ Environments   환경 카드(주소 · 변수 값 · 자격증명)
├─ Runner      ┬ Send · History · Stream · Inbox
└─ Contract    ┬ Drift · Accept · Logs        선언 ↔ 실제 가교
```

- **depth = Service→Module→View 3단.** Spec/Version/Environment 는 nav 계층이 아니라
  상단 **컨텍스트 바**의 셀렉터다 — DB 서비스와 같은 규칙이라 depth 가 안 늘어난다.
- **Environment 는 명시적으로 고를 때까지 비어 있다** — PROD 오조작 방지. DB 서비스의
  같은 규칙을 그대로 가져온다.
- 모듈 탭은 area(설계/운영) 전환 지점에 칩으로 구획된다.

### 상호작용 4모양 → 화면 대응

화면을 가르는 것은 프로토콜 개수가 아니라 **상호작용 모양**이다. 이 4개만 만들면
프로토콜이 늘어도 화면이 안 는다.

| 모양 | 해당 인터페이스 | 화면 |
|---|---|---|
| **단발 요청→응답** | REST · GraphQL query/mutation · gRPC unary · JSON-RPC · SOAP | Runner › Send |
| **서버 스트리밍** | SSE · gRPC server-streaming · GraphQL subscription | Runner › Stream |
| **양방향 세션** | WebSocket · gRPC 양방향/클라이언트 스트리밍 | Runner › Stream (+보내기 패널) |
| **수신 대기** | 웹훅 | Runner › Inbox |

### 지원 범위

**1차 포함** — REST · GraphQL · gRPC · JSON-RPC · WebSocket · SSE · 웹훅 수신
**후순위** — SOAP(WSDL 이 있어 완전 판정은 되지만 수요가 낮다)
**범위 밖** — 메시지 브로커(MQTT · AMQP · Kafka). 사유는 §4-⑨.

## 4. 절대 불변식 (기계가 강제 — 어기면 테스트 실패)

**① 판정은 두 등급이고, 화면에서 갈라 보인다.**
서버가 자기 스키마를 표준으로 뱉는 것(gRPC reflection · GraphQL introspection · WSDL)은
**완전 판정** — 커버리지 100%. 나머지(REST · JSON-RPC · WebSocket · SSE)는 **관측 판정** —
쏴 본 것만 안다. **미관측을 통과로 표시하지 않는다**("12개 중 7개 관측, 5개 미관측").
e2e 스위트가 `--no-db` 로 건너뛴 것을 "미검증"으로 표시하는 것과 같은 규율이다.

**② Rockury 는 표준 준수를 판정하지 않는다.**
REST 는 경로·에러 모양·페이지네이션이 팀마다 다르다. 판정 기준은 언제나
**"이 프로젝트가 선언한 것" 하나뿐**이다. "이게 맞는 REST 다"라고 말하지 않는다.

**③ MCP 는 설계면만 연다.**
만들기·고치기 ✅ / **지우기 ❌ · 실행 ❌**. DB 서비스 MCP 도구 목록에 `delete_*` 도
실행 도구도 없는 것과 같은 선이다. 실행이 없으므로 **자격증명을 MCP 로 줄 이유 자체가
없다** — 값을 숨기는 장치가 아니라 값을 쓸 일이 없는 구조다.

**④ 환경 값과 호출 파라미터를 한 바구니에 담지 않는다.** (§2)

**⑤ 사용자 코드를 실행하지 않는다(1차).**
값 가공은 §5 내장 함수 목록으로만. Electron 에서 사용자 JS 를 돌리는 보안 표면을 만들지
않는다(`node:vm` 은 보안 경계가 아니다). 내장 함수는 순수 함수라 전부 `*.test.ts` 로 덮인다.

**⑥ 내보내기에는 환경 값이 실리지 않는다.**
변수 **이름만** 나가고 값 자리는 빈 껍데기다. 컬렉션 파일을 git 에 올려도 키가 안 박힌다.

**⑦ AI 의 쓰기는 Draft 까지.** 버전 컷은 사람이 한다.

**⑧ 깨지는 변경은 사람 승인 게이트.**
자동 반영 금지. 판정 규칙은 `api-studio.md` § versions.diff.

**⑨ 메시지 브로커는 범위 밖 — 사유 명시.**
이 앱의 판정은 "선언 vs 관측"인데 브로커는 **발행에 응답이 없어 인과가 끊긴다**. 구독으로
흘러온 메시지는 "누가 언젠가 보낸 것"이지 내가 보낸 것의 결과가 아니다. 발행
(fire-and-forget)은 §3 의 4모양 어디에도 안 들어간다. 브로커는 접속해 오래 붙어 있는
상태 있는 서버라 성격이 `infra` 서비스에 가깝다.
**재검토 조건:** 발행–응답 상관관계 판정에 답이 나왔을 때. 그때 API 가 가져갈 몫은
AsyncAPI(= 이벤트 기반 시스템용 명세 표준) 형식 지원뿐이다.

## 5. 내장 함수 목록 (고정 · 정본)

값 가공은 이 목록으로만 한다(§4-⑤). 사용자가 추가·삭제하지 않는다.

| 갈래 | 함수 |
|---|---|
| 시각 | `now()` · `now(포맷)` · `timestamp()` · `isoDate()` |
| 식별자·난수 | `uuid()` · `random(min, max)` |
| 인코딩 | `base64(값)` · `base64decode(값)` · `urlencode(값)` · `urldecode(값)` · `json(값)` |
| 해시·서명 | `md5(값)` · `sha1(값)` · `sha256(값)` · **`hmac(알고리즘, 키, 값)`** |
| 문자열 | `upper(값)` · `lower(값)` · `trim(값)` · `replace(값, 찾을것, 바꿀것)` |

- **`hmac()` 이 이 목록에 있는 이유**가 §4-⑤ 를 가능하게 한다. 사용자 코드가 필요한 거의
  유일한 사례(서명 계산)가 인자 3개짜리 함수로 덮인다.
- **비결정 함수(`now`·`timestamp`·`isoDate`·`uuid`·`random`)는 시각원·난수원을 주입
  가능하게 구현한다** — 안 그러면 테스트가 불가능하고 §4-⑤ 의 "전부 테스트로 덮인다"가
  거짓이 된다. 이건 선택이 아니라 구현 제약이다.
- 함수 목록에 화면을 주지 않는다 — 편집기 자동완성 + 도움말 팝오버가 노출 경로다.

## 6. 결정 로그

| # | 결정 | 근거 |
|---|---|---|
| A | 화면 축 = 프로토콜이 아니라 **상호작용 4모양** | h1/h2/h3 는 같은 인터페이스의 전송 버전이라 요청 모양이 같다. 화면을 가르는 건 응답이 1개냐, 계속 오냐, 내가 계속 보내냐, 안 보냈는데 오냐 |
| B | **정본을 주장하지 않는다** — 두 조각의 출처로 자리 잡음 | REST 에는 `information_schema` 같은 완전 창구가 없다. 정본을 주장하면 REST 에서 앱이 거짓말을 한다 |
| C | 판정 **2등급** | 서버가 스키마를 뱉느냐가 갈랐다. 스키마에서 서버를 만드는 방식(gRPC·GraphQL·SOAP)이면 도로 뱉을 수 있고, 손으로 라우트를 짜면 뱉을 게 없다 |
| D | **MCP 실행 도구 제외** (초안 뒤집음) | AI 는 터미널에서 더 잘 쏜다. 중간에 끼면 요청 id·환경 id 를 맞춰야 해서 **더 어려워진다.** 그리고 실행이 없으면 자격증명 문제 자체가 안 생긴다 |
| E | **비밀값 강한 격리 철회** (초안 뒤집음) | 로컬 개인 도구다. 프로젝트에 `.env` 가 이미 열려 있어 앱만 잠그면 문 하나 잠그고 창문 여는 꼴. 남는 실제 문제는 **내보내기**뿐이라 거기만 막는다(§4-⑥) |
| F | **코드 실행 1차 제외** (초안 뒤집음) | `hmac()` 내장으로 필요한 자리가 사라진다. 보안 표면 하나가 통째로 없어지고 전부 테스트로 덮인다. 내장으로 안 되는 실제 사례가 나오면 그때 연다 |
| G | 관측 기록의 근거 = **"사람이 쓰면서 쌓여서"** (근거 교체) | 원래 근거 "AI 가 못 쏘니까"는 성립하지 않는다 — AI 는 curl 로 쏜다. 남는 건 시간에 걸친 축적과 PROD 관측 |
| H | **Functions 는 서비스 아님** | 아무도 "함수 쓰러" 앱을 열지 않는다. 서비스로 두면 서비스 간 런타임 의존이 생겨 병렬 개발 전제가 깨지고, 범위가 안 정해져 스크립트 실행기로 자란다 |
| I | **Environment 가 서버 주소를 직접 든다** (Target 분리 안 함) | DB 는 설계 없이 접속만으로 조회가 되지만, API 는 **요청 정의 없이 서버만 갖고 할 일이 없다.** 분리는 모델만 늘린다. **재검토 조건:** 한 서버를 여러 Spec 이 공유하는 게 실제 문제가 됐을 때(DB 서비스가 정확히 그 순서로 Connection 을 승격했다) |
| J | 요청 = **파라미터 시그니처를 갖는 함수** | 값의 두 종류를 가르는 자리를 만든다. 부수 효과로 그 시그니처가 곧 AI 용 구현 문서가 된다 |
| K | 메시지 브로커 **제외 + 사유 명시** | §4-⑨. 조용히 빼면 나중에 "왜 없지"가 되고, 사유를 적으면 "이 조건이 풀리면 넣는다"가 된다 |

## 7. 열린 질문 / 뒤로 미룬 것

- **Overview · Reference 모듈** — 지금 IA 에 없다. DB 서비스는 뒀다. 필요해지면 추가.
- **웹훅 외부 터널** — 1차는 로컬 전용. 진짜 외부 콜백을 받으려면 터널이 필요하다.
- (전송은 2026-07-29 로 **네 가지가 다 섰다** — WebSocket · SSE · gRPC · GraphQL 구독.
  gRPC 는 `@grpc/grpc-js`·`@grpc/proto-loader` 를 사용자 합의 후 `main` 에서 더했고,
  GraphQL 구독은 `graphql-transport-ws` 를 손으로 구현해 새 의존성 없이 붙였다.)
- **이름 없는 스트림 메시지의 대조** — 이벤트 이름이 있으면 대조하지만(`api-contract.md`
  § drift.observed AC-6), WebSocket 프레임처럼 이름이 없으면 어느 선언과 맞출지 못 정한다.
  본문 안의 판별 필드를 쓰려면 "어느 필드가 판별자인가"를 선언에 더해야 한다 — 모델이 늘어서
  실제 필요가 나올 때 연다.
- **MCP 도구 승격 스위치** — 자주 쓰는 요청을 전용 도구로 올릴지. 1차는
  `api_get_spec` 한 덩어리로 충분한지 보고 정한다.
- **SOAP** — WSDL 덕에 완전 판정 대상이지만 수요가 낮아 후순위.

## 8. 다른 서비스와의 경계

- **`infra`** — 메시지 브로커를 띄우고 운영하는 것은 infra 몫(§4-⑨).
- **`db`** — 개념이 비슷해 보이나 **기능을 빌려오지 않는다.** 공유하는 것은 셸(nav 3단 +
  컨텍스트 바)과 "Env 는 명시적으로 고를 때까지 비어 있다" 같은 **화면 규율뿐**이다.
  기능은 API 논리로만 정한다.
- **`ai`** — MCP 게이트웨이는 ai 서비스 것이고, API 서비스는 `src/main/ai/coverage/api.ts`
  에 자기 채널을 등재한다(`api-mcp.md`).
