# Service: api-studio (설계부 — Studio · Versions)

> API 명세를 짜고, 문서를 붙이고, 버전을 컷하는 곳. **환경과 무관하고 버전이 중심**이다.
> 서비스 정본·도메인 모델·불변식은 `api-service.md`. 여기는 설계부 Surface 명세다.
> 위계: Service > Surface > Section > Component.

공통 불변식
- **요청은 함수다** — 파라미터 시그니처를 갖고, 그 시그니처가 곧 AI 용 구현 문서다.
- **인터페이스 종류는 Spec 생성 시 고정** — 편집기는 그 종류의 네이티브 모양 그대로 보인다.
  종류를 바꾸는 것은 편집이 아니라 새 Spec 생성이다.
- 값 가공은 `api-service.md` §5 내장 함수로만. 사용자 코드 실행 없음.

## Surface: api-studio.requests (Requests 뷰)

### Section api-studio.requests.tree — 요청 트리
- **AC-1** 폴더/요청 계층 트리로 보인다. 폴더 생성·이름변경·끌어 옮기기(자기 자손 드롭 방지).
- **AC-2** 이름·경로 부분일치 검색으로 걸러진다(대소문자 무시). 빈 질의는 전체를 원래 순서로.
- **AC-3** 각 요청 행에 인터페이스 배지(`REST`/`GQL`/`gRPC`/`RPC`/`WS`/`SSE`/`HOOK`)와
  상호작용 모양 표식을 **텍스트로** 표시한다(이모지 금지 — DB 서비스 표기 규율과 동일).
- **AC-4** 판정 결과가 있는 요청은 상태 표식을 함께 보인다(일치 / 어긋남 / **미관측**).
  미관측을 일치로 보이지 않는다.

### Section api-studio.requests.signature — 파라미터 시그니처
> 이 섹션이 "요청 = 함수"를 실물로 만든다. 값의 두 종류를 가르는 자리(`api-service.md` §2).
- **AC-1** 파라미터마다 **이름 · 타입 · 필수여부 · 기본값 · 설명**을 갖는다.
  타입은 `string` · `number` · `boolean` · `enum` · `object` · `array`.
- **AC-2** `enum` 타입은 허용 값 목록을 갖는다. 목록 밖 값은 실행 전에 거부된다.
- **AC-3** 필수 파라미터에 값이 없으면 **실행이 차단**되고, 어느 파라미터가 비었는지 이름으로 알린다.
- **AC-4** 시그니처는 환경 값과 **한 목록에 섞이지 않는다** — 화면에서 구획이 갈린다.
  (환경 값은 `api-runner.md` § environments.values)
- **AC-5** 시그니처가 그대로 MCP 응답에 실린다 — AI 가 읽고 자기 코드에 구현할 수 있는
  형태여야 한다(`api-mcp.md` § tools.read).

### Section api-studio.requests.shape — 요청 모양 (인터페이스별)
- **AC-1 (REST)** 메서드 · 경로 · 쿼리 · 헤더 · 본문. 경로 안 `{{이름}}` 은 파라미터/환경 값으로 치환된다.
- **AC-2 (GraphQL)** 질의문 + variables. 서버 introspection 결과가 있으면 필드 자동완성이 붙는다.
- **AC-3 (gRPC)** proto 에서 온 서비스/메서드 선택 + 메시지 본문. 스트리밍 종류
  (unary/server/client/양방향)가 메서드 정의에서 자동으로 정해진다 — 사람이 고르지 않는다.
- **AC-4 (JSON-RPC)** 메서드 이름 + params. id 는 자동 부여.
- **AC-5 (WebSocket/SSE)** 접속 주소 + 접속 헤더. 보낼 메시지는 실행 화면에서 다룬다.
- **AC-6 (웹훅)** 보내는 모양이 없다 — 받을 모양(기대하는 본문 스키마)만 선언한다.
- **AC-7** 인터페이스 종류가 지원하지 않는 칸은 **보이지 않는다**(비활성이 아니라 없음).

### Section api-studio.requests.response — 응답 모양 선언
- **AC-1** 상태(HTTP 상태코드 / gRPC 코드 / 스트림 이벤트 종류)별로 응답 스키마를 선언한다.
- **AC-2** 각 필드는 이름 · 타입 · **필수여부(nullable)** 를 갖는다. 필수여부는 깨지는 변경
  판정에 쓰이므로 비워 둘 수 없다 — 모르면 `모름`으로 명시하고, `모름`은 판정에서 제외된다.
- **AC-3** 관측 기록에서 응답 스키마를 **제안**받을 수 있다(자동 반영 아님 — 사람이 수락).
- **AC-4** 선언하지 않은 상태는 "선언 없음"으로 남는다. 빈 값을 "응답 없음"으로 해석하지 않는다.

### Section api-studio.requests.template — 값 채우기
- **AC-1** 본문·헤더·경로·쿼리 어디서나 `{{이름}}` 으로 파라미터/환경 값을 참조한다.
- **AC-2** `{{함수(...)}}` 로 내장 함수를 호출한다. 목록은 `api-service.md` §5 고정.
- **AC-3** 목록에 없는 이름을 부르면 **실행 전에** 거부하고 오타를 지목한다(조용히 빈 값 치환 금지).
- **AC-4** 함수는 중첩된다(`{{base64(hmac('sha256', apiKey, timestamp()))}}`).
- **AC-5** 문자열 안 리터럴 `{{` 는 이스케이프로 그대로 둘 수 있다.
- **AC-6** 치환 결과 미리보기를 보낼 때가 아니라 **편집 중에** 보인다.

### Section api-studio.requests.import — 가져오기
> 없으면 첫 화면이 빈 화면이다. 기존 API 가 있는 팀이 손으로 다시 칠 리 없다.
- **AC-1** OpenAPI 3.x(JSON/YAML) → REST Spec. 경로·메서드·파라미터·응답 스키마·설명을 옮긴다.
- **AC-2** `.proto` 파일 → gRPC Spec. 서비스·메서드·메시지 타입·스트리밍 종류를 옮긴다.
- **AC-3** GraphQL SDL 또는 introspection 결과 → GraphQL Spec.
- **AC-4** 가져오기는 **기존 Spec 을 덮지 않는다** — 새 Spec 을 만들거나, 기존에 합칠 때는
  무엇이 추가·변경·충돌인지 먼저 보이고 사람이 수락한다.
- **AC-5** 해석 못 한 항목은 **버리지 않고 목록으로 보고**한다(조용한 누락 금지).

### Section api-studio.requests.export — 내보내기
- **AC-1** Spec 을 OpenAPI 3.x / `.proto` / GraphQL SDL 로 내보낸다(인터페이스 종류에 맞게).
- **AC-2 (불변식 ⑥)** 내보낸 파일에 **환경 값이 실리지 않는다.** 자격증명·토큰·base URL
  실값이 파일에 박히면 안 된다. 구조적으로 그렇다 — 명세는 값을 담을 자리 자체가 없고
  `{{이름}}` 참조만 든다.
  · **헤더는 이름만 나간다.** `Authorization: Bearer {{apiKey}}` 에서 나가는 것은 헤더 **이름**
    뿐이다(OpenAPI 의 `in: header` 파라미터). 값 쪽(`Bearer {{apiKey}}`)은 환경이 채우는
    것이라 파일에 실리지 않는다. 그렇다고 헤더를 통째로 빼면 "이 엔드포인트가 이 헤더를
    받는다"는 계약이 조용히 사라지므로, 이름은 반드시 남긴다.
- **AC-3** 내보내기 직전에 "값은 빠지고 이름만 나갑니다"를 한 줄로 알린다.

## Surface: api-studio.docs (Docs 뷰)

> 함정은 **문서와 정의가 갈라지는 것**이다. 손으로 쓴 파라미터 표는 반드시 썩는다.

### Section api-studio.docs.generated — 자동 생성분
- **AC-1** 파라미터 표 · 응답 필드 표 · 상태 목록 · 예시 요청/응답을 **정의에서 생성**해 보인다.
- **AC-2 (핵심)** 이 부분은 **편집 불가**다. 정의를 고쳐야 바뀐다 — 그래야 안 썩는다.
- **AC-3** 예시는 관측 기록이 있으면 실제 응답에서, 없으면 스키마에서 만든다.
  어느 쪽인지 표시한다(실제 관측 / 스키마 생성).

### Section api-studio.docs.authored — 사람이 쓰는 문서
- **AC-1** Markdown 편집기. 이 API 가 왜 있는지 · 언제 쓰면 안 되는지 · 알려진 함정 · 폐기 예정 등
  **정의에서 나올 수 없는 것**만 담는다.
- **AC-2** 미리보기를 제공한다. 링크·코드블록·표를 지원한다.
- **AC-3** 자동 생성분과 **한 화면에서 구획이 갈려** 보인다 — 어디까지가 기계 것이고
  어디부터가 사람 것인지 읽는 사람이 안다.
- **AC-4** 이 내용이 MCP 로 그대로 나간다 — AI 가 구현할 때 참고하는 것이 주로 이 부분이다.

## Surface: api-versions (Versions 모듈)

### Section api-versions.timeline — 타임라인 (컷 · 락)
- **AC-1** Spec 의 버전 목록을 시간순으로 보인다. 각 버전은 **불변 스냅샷**이다.
- **AC-2** Draft 에서 버전을 컷하면 그 시점 명세 전체가 굳는다. 컷은 **사람만** 한다
  (`api-service.md` §4-⑦ — AI 는 Draft 까지).
- **AC-3** 이미 관측 기록이 붙은 버전은 잠긴다(lock) — 지나간 관측의 기준이 흔들리면 안 된다.
- **AC-4** 버전 번호는 전역 소유 · 단조 증가. 요청 단위 버전은 없다.

### Section api-versions.diff — 버전 간 diff · 깨지는 변경 판정
> **요청과 응답은 방향이 반대다.** 요청은 *더 요구하면* 깨지고, 응답은 *덜 주면* 깨진다.
> 이 비대칭이 판정의 핵심이고 가장 자주 틀리는 지점이다.

- **AC-1** 두 버전을 골라 추가/삭제/변경된 요청·파라미터·응답 필드를 보인다.
- **AC-2 (요청 쪽 깨지는 변경)** 아래는 **깨짐**으로 판정한다 — 기존 호출자가 못 부르게 된다:
  - 필수 파라미터 **추가**
  - 파라미터 타입 변경
  - `enum` 허용 값 **제거**
  - 요청 필수 필드 추가
- **AC-3 (응답 쪽 깨지는 변경)** 아래는 **깨짐**으로 판정한다 — 기존 호출자가 기대한 걸 못 받는다:
  - 응답 필드 **제거**
  - 응답 필드 타입 변경
  - 응답 필드 **필수 → nullable**(있다고 믿던 게 없어질 수 있음)
  - 선언된 상태(코드) 제거
- **AC-4 (안전한 변경)** 아래는 **깨지지 않음** — 경고도 아니다:
  - 선택 파라미터 추가 · 응답 필드 추가 · `enum` 값 추가(응답 쪽) · 설명 변경
- **AC-5** 필수여부가 `모름`인 필드는 판정에서 **제외**하고, 제외했다는 사실을 결과에 표시한다
  (`requests.response` AC-2). 모르는 것을 안전으로 치지 않는다.
- **AC-6 (불변식 ⑧)** 깨지는 변경이 하나라도 있으면 컷 시 **사람 승인 게이트**가 뜬다.
  자동 통과 없음. 무엇이 왜 깨지는지 항목별로 보인다.
