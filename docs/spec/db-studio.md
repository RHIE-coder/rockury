# Service: db-studio (DB 스튜디오 — 설계부)

> 버전 중심의 **설계 저작** 서비스. 활성 설계(Design)의 도면을 짓고 버전을 컷한다.
> **환경(Environment)·연결(Connection)과 무관** — 이 서비스의 어떤 화면도 실 DB 에 DDL·DML 을 실행하지 않는다.
> 위계: Service > Surface > Section > Component. ID 는 코드·테스트와 기계 대조용 안정 키.

## 이 문서의 범위 (정본 흡수 현황)

Studio 의 뷰는 `Definition → Diagram → Seed → Mocking → Documenting → Validation` 순이다.
이 문서는 **steward spec 단계를 거친 Surface 부터** 점진적으로 채운다(`docs/spec/README.md` 흡수 원칙).

| Surface | 상태 |
|---|---|
| `db-studio.definition` | 구현 완료, **정본 미흡수** — 근거는 `docs/before-steward-background/db-service-ia.md`, 동작은 코드(`services/db/workspaces/definition/`)와 `docs/qa/db-console.md` 의 Definition 케이스가 덮는다. |
| `db-studio.diagram` | 구현 완료, **정본 미흡수** — 위와 같음(`services/db/workspaces/diagram/`). |
| `db-studio.seed` | **이 문서에 명세됨**(아래). |
| `db-studio.mocking` · `db-studio.documenting` · `db-studio.validation` | 미구현(placeholder). |

## 공통 불변식 (Studio 전역)

- 키·표식은 **텍스트 배지만** 쓴다(`PK`·`FK`·`UK`·`IDX`·`CHECK`·`KEY`). 열쇠 이모지 등 애매한 기호 금지.
- 저장은 **설계 스코프 교체** — 설계 X 저장이 설계 Y 행을 건드리지 않는다(에이전트(MCP)·화면 동시 작업 안전).
- 활성 설계가 없으면 모든 Surface 는 설계 선택 안내를 보이고 빈 상태로 남는다.

## Surface: db-studio.seed (Seed 뷰 — 기준 데이터 저작)

> **시드**(= 테이블을 만들 때 처음부터 있어야 하는 기준 데이터: roles·permissions·코드표)를 설계에 저작한다.
> Console › Data 와 화면 형태(그리드)는 같지만 대상이 다르다 — Data 는 실 DB 에 지금 담긴 데이터,
> Seed 는 **설계가 정의하는 기준 데이터**다. 스키마 요소는 아니지만 서비스 정책·제약의 바탕이므로
> **버전 Diff 대상**이다.
>
> 관리 단위는 테이블 전체가 아니라 **시드 세트**(대상 테이블 · 자연키 · 무시 컬럼 · 관리 강도).
> 이 선언이 있으면 `{설계→운영}` 반영은 UPSERT 로, `{운영→설계}` 되먹임은 자연키 기준 행 단위
> 비교 + 선별 채택으로 성립한다. 두 방향 모두 **후속 범위**이며, 이 Surface 는 저작과 Diff 까지다.

### Section db-studio.seed.set-list — 시드 세트 목록
- **AC-1** 활성 설계의 시드 세트를 테이블 이름순으로 보이고, 각 행 우측에 행 수를 표시한다.
- **AC-2** `+` 로 **설계 테이블 중에서** 세트를 만든다. 이미 세트가 있는 테이블과 뷰(`isView`)는 고를 수 없다(뷰는 데이터를 담지 않으므로). 고르기 목록의 검색·테이블/뷰 가르기는 공용 순수 로직(`db/tableList`)을 재사용한다.
- **AC-3** 세트 삭제는 확인을 받는다. 세트를 지워도 설계 테이블 정의는 건드리지 않는다.
- **AC-4** 세트가 하나도 없으면 빈 상태 + "테이블에서 시드 세트 만들기" CTA 를 보인다.
- **AC-5** 자연키가 선언되지 않은 세트는 목록에서 `자연키 필요` 경고 표식을 단다(AC 는 declaration AC-2 로 이어짐).

### Section db-studio.seed.declaration — 세트 선언 (자연키·무시 컬럼·관리 강도)
- **AC-1** **자연키**(= 행의 정체성을 잡는 업무상 열쇠)를 컬럼 1개 이상으로 선언한다. 기본값은 그 테이블의 PK 컬럼들이되, **PK 가 자동증가**(`AUTO_INCREMENT`·`serial`·`identity`)면 기본값을 비우고 사람이 고르게 한다 — 환경마다 값이 달라 짝짓기 기준이 될 수 없기 때문.
- **AC-2** 자연키가 비면 행 저작은 되지만 **Diff 는 행 단위로 비교하지 않고 그 세트를 `비교 불가`로 표시**한다. 화면은 무엇이 없어 그런지 알린다.
- **AC-3** **무시 컬럼**(= 환경마다 달라도 차이로 보지 않을 컬럼: `id`·`created_at` 류)을 여러 개 고를 수 있다. 자연키 컬럼은 무시 컬럼으로 고를 수 없다(상호 배타).
- **AC-4** **관리 강도**는 `보장만`(기본, 설계에 적힌 행만 맞추고 나머지는 방치) / `전권`(설계에 없는 행은 삭제 후보) 중 하나. `전권` 을 고르면 삭제 후보가 생긴다는 경고를 함께 보인다. **실제 삭제는 이 화면에서 일어나지 않는다** — 후속 반영 단계의 트랜잭션 게이트 몫.
- **AC-5** 선언 변경은 즉시(자동) 저장된다.

### Section db-studio.seed.grid — 행 저작 그리드
- **AC-1** 그리드 컬럼은 그 테이블의 **설계 컬럼 순서**를 따른다. 컬럼 머리에서 자연키(`KEY`)·무시 컬럼(`무시`)을 **그 자리에서 지정**한다(텍스트 배지만 — 이모지 금지). 편집 가능할 때는 이 토글 자체가 상태 표시를 겸하고, 읽기 전용(커밋 버전 열람)에서는 같은 뜻의 배지로 보인다. 무시 컬럼은 흐리게 그린다.
- **AC-1b** 긴 타입 라벨(예: `ENUM('a','b',…)`)은 **잘라 그리고** 전체는 툴팁으로 본다 — 타입 하나가 컬럼 폭을 독차지해 값이 안 보이는 것을 막는다(표시와 폭 계산이 같은 상한을 쓴다).
- **AC-2** 행 추가·셀 편집·행 삭제를 지원하고, 편집 상태 표기는 Data 그리드 관례와 같다 — 신규행 `NEW` 배지, 삭제행 취소선, 변경 셀 하이라이트.
- **AC-3** 자연키 값이 비었거나 다른 행과 겹치면 그 행을 오류로 표시하고 이유를 알린다(중복 자연키 금지).
- **AC-4** NULL 토글을 제공하고 NULL 은 흐린 이탤릭으로 표기한다(Data 뷰와 같은 표기).
- **AC-5** 컬럼 폭은 Data 그리드의 자동 폭 로직(`console/data/colWidth`)을 재사용한다 — 같은 계산을 두 번 만들지 않는다.
- **AC-6** 이 화면은 **실 DB 를 건드리지 않는다** — 저장은 로컬 설계 저장소에만 일어나고 어떤 DDL·DML 도 실행하지 않는다.

### Section db-studio.seed.variables — 변수 자리표시자 (환경차 분리)
- **AC-1** 셀 값이 `{{이름}}` 꼴이면 **변수**로 알아보고 셀에 변수 표식을 보인다. 문법은 저장쿼리 파라미터화와 같다 — bare `{{x}}` 만 변수, `'{{x}}'`(따옴표 안)는 리터럴.
- **AC-2** 세트 머리에 그 세트가 요구하는 변수 목록을 중복 없이 이름순으로 보인다.
- **AC-3** 변수는 **이름으로 비교**된다 — 같은 변수 이름끼리는 Diff 에서 차이가 아니다(환경차가 diff 소음이 되지 않게).
- **AC-4** 이 화면에는 변수의 **값 입력칸이 없다**. 값은 환경 쪽에 두고(비밀값은 OS 키체인 암호화 경로) 반영 시점에 치환한다 — 후속 범위. 화면은 비밀값을 평문으로 넣지 말고 변수를 쓰라고 안내한다.

### Section db-studio.seed.persistence — 저장
- **AC-1** 시드 세트는 **설계 스코프**로 저장된다 — 설계 X 저장이 설계 Y 의 세트를 건드리지 않는다(`tables` 와 같은 방식).
- **AC-2** 앱을 다시 켜도 세트 선언과 행이 그대로 남는다.
- **AC-3** 새로 만든 IPC 채널은 MCP 커버리지 지도(`src/main/mcp/coverage.ts`)에 **노출 또는 제외 사유**로 등재된다(프로젝트 불변식 4).
- **AC-4** 설계를 지우면 그 설계의 시드도 함께 사라진다 — 시드는 설계 소유물이다. 남기면 같은 이름의 새 설계에 유령 시드가 붙는다.

### Section db-studio.seed.version-diff — 버전 스냅샷·Diff
- **AC-1** 버전 컷 시 스냅샷에 시드를 함께 담는다(`{ tables, seeds }`). 컷 모달과 Timeline 의 버전 행은 **담기는/담긴 시드 행 수**를 보인다(시드가 0이면 표시하지 않는다) — 무엇이 버전에 들어갔는지 컷 직전·직후에 확인할 수 있게.
- **AC-2** 시드가 없던 **옛 스냅샷과 비교해도 깨지지 않는다** — `seeds` 없음은 빈 목록으로 읽는다.
- **AC-3** Version Diff(Versions › Version Diff 화면)에 시드 섹션이 뜬다: 세트 추가/삭제 + 행 추가/삭제/값 변경. 행 짝짓기는 **자연키 기준**이고 **무시 컬럼은 비교에서 뺀다**.
- **AC-3b** 행을 짝지을 수 없는 세트(자연키 없음·양쪽 선언 불일치)는 행 delta 를 만들지 않되, 행 내용이 실제로 다르면 그 세트를 **변경 + `행 비교 불가`** 로 보인다 — "바뀐 걸 비교하지 못했다"는 사실을 침묵하지 않는다. 행 로컬 id 차이는 차이로 보지 않는다.
- **AC-4** 선언 자체의 변경(자연키·무시 컬럼·관리 강도)도 차이로 잡는다.
- **AC-5** 스키마는 그대로고 시드만 바뀐 두 버전을 비교하면 "변경 없음"으로 보이지 않는다.
